# 题目 B5：基于 Dijkstra 算法的校园导航最短路径系统

**适用学院**：人工智能学院（4 系）　**组容量**：本题目最多 3 组选择

## 一、系统/算法说明

**1）系统是做什么的**：本系统把校园里的若干地点（图书馆、主楼、食堂、宿舍等）抽象成图的节点，把连接它们的道路抽象成带权的边（权值为步行距离，单位 m），构建邻接矩阵，然后用 Dijkstra 算法求出从任意起点到任意终点的最短路径，输出完整路径（经过哪些地点）与总距离；系统还支持"临时封路"（把某条边的距离改为极大值后重新计算）和多目的地巡航（从起点出发依次贪心前往最近的未访问地点）。

**2）它解决了什么重要问题**：在带距离/时间权重的道路网中，如何找到从 A 到 B 的最省时最短走法，是导航系统的核心问题。简单地把所有路径枚举一遍在节点多时不可行，Dijkstra 算法通过"每一步都在未确定的节点中选距离最小的一个"来高效求解。若不掌握它，学生就无法理解地图导航、物流配送、网络路由中"最短路径"是怎么算出来的。

**3）它支撑哪些关键应用**：① 手机地图导航的最短路径计算；② 无人车/无人艇的航路规划；③ 物流配送路线优化；④ 通信网络的路由选择；⑤ 更复杂规划算法（A*、D*）的基础。Dijkstra 是这些系统的共同内核。

**4）与专业培养的关联**：对应人工智能学院"智能控制与机器人/智能规划"方向，路径规划是自主系统的基本能力。本系统让学生在大一用 C 语言实现图的存储与最短路径计算，建立"图 = 邻接矩阵 + 距离数组 + 前驱数组"的直觉，为后续人工智能导论、规划与决策课程打基础，全程只用到二维数组、循环与比较。

## 二、题目任务与专业关联

本题目要求小组用 C 语言多文件工程实现上述校园导航系统。程序需支持：地点与道路数据读入、邻接矩阵构建、地点列表显示、单源最短路主循环、前驱数组回溯、临时封路、多目的地巡航排序、交互查询、查询日志文件输出与主控菜单。全组需完成 10 个模块，总代码 900～1200 行，每人 2～3 个模块。题目综合训练"文件 + 二维数组 + 结构体 + 函数"，并把"图与最短路径"的计算思维带进人工智能专业学习。

## 三、数据来源与格式

### 3.1 数据文件格式

采用两个纯文本文件，首行以 `#` 开头的说明行在读入时跳过。

地点文件 `campus_nodes.txt`：

```
# 校园地点文件 v1：编号 名称（名称不含空格）
# 编号从 0 起连续编号
0 图书馆
1 主楼
2 启航活动中心
3 一食堂
4 六号宿舍楼
```

道路文件 `campus_roads.txt`：

```
# 校园道路文件 v1：起点编号 终点编号 距离(m)
# 道路为双向通行，距离为正整数
0 1 320
1 2 210
0 3 450
3 4 180
2 4 260
```

三列含义：道路两端的地点编号、道路长度（米）。用 `fscanf(fp, "%d %d %d", &u, &v, &w)` 逐行读入。

### 3.2 仿真数据生成规则

| 字段 | 单位 | 取值范围 | 生成规则 |
|---|---|---|---|
| 节点数 n | 个 | 6～30 | 任意整数 |
| 节点名称 | — | 2～12 个汉字或无空格字符串 | 从地点名表中随机取，不重复 |
| 边距离 w | m | 20～2000 | 均匀随机 `20 + rand()%1981`，按步行速度 1.3 m/s 约合 15～1540 s |
| 边数 e | 条 | n-1 ～ n(n-1)/2 | 先生成一棵连通随机树保证全连通，再随机补边 |
| 连通性 | — | — | 保证任两点可达（生成时先连通；封路测试时可能断开） |

**异常值注入**（用于检验 M1/M2 校验，注入 1～2 类）：

1. 距离为负数（如 `-50`），提示非法并跳过该边；
2. 端点编号越界（如 `99`，超过节点数），提示非法并跳过；
3. 重复边（同一对节点出现两次、距离不同），提示"重复边，取较小值"；
4. 孤立节点（某节点没有任何边），在"全连通性检查"中报告。

可参考开源地图路网数据作为真实拓扑来源（仅作了解，需自行转成上述边表）：OpenStreetMap https://www.openstreetmap.org/ 。

## 四、数据结构设计

```c
#define NODE_MAX  30
#define EDGE_MAX  450        /* n(n-1)/2 上限 */
#define INF       999999     /* 表示"不可达"的极大距离 */

struct Edge {                /* 一条道路 */
    int u, v;                /* 两端地点编号 0~n-1 */
    int w;                   /* 距离，单位 m，20~2000 */
};

struct Graph {
    int  n;                          /* 地点数 6~30 */
    char name[NODE_MAX][32];         /* 地点名称（UTF-8 字符串） */
    int  mat[NODE_MAX][NODE_MAX];    /* 邻接矩阵，INF 表示不通 */
    int  edgeCnt;                    /* 边数 */
    struct Edge edge[EDGE_MAX];      /* 边表，供封路/恢复使用 */
};

struct Graph g_graph;

int  g_dist[NODE_MAX];       /* 起点到各点的当前最短距离，m */
int  g_prev[NODE_MAX];       /* 最短路径上的前驱节点，-1 表示无 */
int  g_done[NODE_MAX];       /* 是否已确定最短距离 0/1 */
int  g_start;                /* 当前单源起点编号，-1 表示未设定 */
```

辅助：查询日志用结构体数组记录"查询序号、起点、终点、总距离、路径字符串"。

## 五、功能模块拆解（共 10 个模块）

### 第一部分：数据读入（3 个模块）

**M1 地点与道路数据读入模块**（源文件 `GraphIO.c`）
- 功能简介：分别读入地点文件与道路文件，检查编号是否连续、距离是否为正、端点是否越界；对非法边给出提示并跳过，统计有效地点数与边数。
- 输入：地点文件路径、道路文件路径。
- 输出：填充 `g_graph` 的 `name[]`、`n`、`edgeCnt`、`edge[]`。
- 接口示例：`int LoadGraph(const char *nodePath, const char *roadPath, struct Graph *g);`

**M2 邻接矩阵构建模块**（源文件 `GraphIO.c`）
- 功能简介：把边表填成 n×n 邻接矩阵：先全部置 `INF`、对角线置 0，再对每条有效边把 `mat[u][v]` 与 `mat[v][u]` 置为距离；同一条边重复出现时取较小值；构建后检查是否存在孤立节点并报告。
- 输入：`g_graph.edge[]`、`edgeCnt`、`n`。
- 输出：`g_graph.mat[NODE_MAX][NODE_MAX]`。
- 接口示例：`void BuildMatrix(struct Graph *g);`

**M3 地点列表显示模块**（源文件 `GraphIO.c`）
- 功能简介：按编号顺序打印"编号—名称"对照表，并计算每个地点的度数（连接的道路条数），列出孤立节点。
- 输入：`g_graph`。
- 输出：屏幕地点对照表。
- 接口示例：`void ShowNodes(const struct Graph *g);`

### 第二部分：算法实现（4 个模块）

**M4 单源最短路主循环模块**（源文件 `Dijkstra.c`）
- 功能简介：以指定地点为起点，初始化 `g_dist`（起点 0、其余 INF）与 `g_prev`（-1）；每轮在未确定的节点中选出 `g_dist` 最小者，标记为已确定，再用它松弛所有邻居（若经它到达更近则更新距离与前驱）；重复 n 次得到全部最短距离，用纯数组实现，不使用优先队列。
- 输入：起点编号、`g_graph.mat`、`n`。
- 输出：`g_dist[]`、`g_prev[]`、`g_done[]`。
- 接口示例：`void Dijkstra(const struct Graph *g, int start);`

**M5 前驱数组回溯模块**（源文件 `Dijkstra.c`）
- 功能简介：从终点出发沿 `g_prev` 一步步回退到起点，把经过的节点编号倒序整理成路径序列（起点在前、终点在后）并输出总距离；若终点不可达（距离为 INF）则报告无路径。
- 输入：终点编号、`g_prev`、`g_dist`。
- 输出：路径数组（节点编号序列）与路径长度；屏幕路径显示。
- 接口示例：`int BuildPath(int goal, int path[], int *len);`

**M6 临时封路模块**（源文件 `RoadCtrl.c`）
- 功能简介：把指定一条边的距离暂时改为 `INF`（或改为指定绕行距离）后重新调用 M4 计算，比较封路前后的总距离；支持恢复道路（从 `g_graph.edge[]` 重新构建矩阵）。
- 输入：被封闭边的两端编号、是否恢复的标志。
- 输出：更新 `g_graph.mat`；屏幕封路前后对比。
- 接口示例：`void CloseRoad(struct Graph *g, int u, int v);` / `void RestoreRoad(struct Graph *g, int u, int v);`

**M7 多目的地巡航排序模块**（源文件 `Cruise.c`）
- 功能简介：从一个起点出发，重复"在未访问地点中用 Dijkstra 找最近的、可达的一个，走过去并把它标记为已访问"，直到所有需要访问的地点走完；输出访问顺序与累计总路程（贪心策略，不保证全局最优，但结果稳定可复现）。
- 输入：起点编号、待访问地点清单、`g_graph`。
- 输出：访问顺序表与累计路程；屏幕巡航路线。
- 接口示例：`int CruiseRoute(struct Graph *g, int start, int targets[], int tc, int order[]);`

### 第三部分：数据输出（3 个模块）

**M8 交互查询模块**（源文件 `Query.c`）
- 功能简介：交互输入起点与终点编号（或名称），调用 M4、M5 输出路径（用"→"连接地点名称）、总距离（m）与按 1.3 m/s 步行的预计时间（min）；对无效输入给出提示。
- 输入：起点、终点编号/名称。
- 输出：屏幕查询结果（路径、距离、时间）。
- 接口示例：`void QueryPath(struct Graph *g);`

**M9 查询日志文件输出模块**（源文件 `Query.c`）
- 功能简介：把每一次查询（或封路实验、巡航路线）的序号、起点、终点、总距离、路径字符串追加到 `nav_log.csv`，首行写列名；同时支持把日志在屏幕汇总。
- 输入：查询日志结构体数组。
- 输出：`nav_log.csv`；屏幕日志汇总表。
- 接口示例：`int SaveNavLog(const char *path, const struct NavLog log[], int n);`

**M10 主控菜单模块**（源文件 `Stu_main.c`）
- 功能简介：文本主菜单（读数据 / 显示地点 / 最短路径查询 / 封路重算 / 恢复道路 / 巡航排序 / 查看日志 / 退出），`do-while + switch` 调度，未读数据前禁止查询。
- 输入：用户菜单选项。
- 输出：调度各模块。
- 接口示例：`int main(void);`

## 六、数据流与控制流

**控制流**：`main()` 菜单循环 → switch 分发到 M1～M9 → 回菜单直至退出。状态约束：M2～M9 前必须先执行 M1、M2；M8 查询前必须先设定起点并运行 M4；M6 封路后需重跑 M4 才能反映新距离；M5 必须在 M4 之后执行。

**数据流**：

```
campus_nodes.txt ─┐
                  ├─► M1 读入 ─► g_graph (name / edge[])
campus_roads.txt ─┘        │
                           ▼
                    M2 邻接矩阵构建 ─► g_graph.mat[][]
                           │
                           ▼
                    M3 地点列表显示
                           │
                           ▼
                    M4 单源最短路主循环 ─► g_dist[] / g_prev[] / g_done[]
                           │
              ┌────────────┼───────────────┬───────────────┐
              ▼            ▼               ▼               ▼
       M5 前驱回溯   M6 临时封路     M7 多目的地巡航   M8 交互查询
              └────────────┬───────────────┴───────────────┘
                           ▼
                    M9 查询日志文件输出
```

## 十、选做扩展

1. 增加"步行/骑行"两种交通方式：给每条边附加两种权值（时间），查询时可选择以"时间"而非"距离"为最短目标；
2. 增加"多点必经"路径：依次经过给定的若干地点，把每段用 Dijkstra 求解后拼接，输出分段路径表；
3. 输出"所有地点对之间的最短距离矩阵"（对每个节点各跑一次 Dijkstra，仍是课程内做法），并找出校园中距离最远的两个地点。
