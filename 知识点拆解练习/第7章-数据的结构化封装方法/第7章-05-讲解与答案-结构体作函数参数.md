## 二、预备知识：结构体作参数的值传递原理（零基础阅读）

### 1. 参数传递的本质是"复制"

第 4 章学过：C 语言函数的普通参数是**值传递**——调用时把实参的值**复制**一份交给形参，函数内操作的是副本。当参数是 `double` 时复制一个数；当参数是 `struct IceBlock` 时，复制的是**整个结构体的所有成员**：

```
main 中：b = {3, 2.0, 1.5, 0.6, 1650.60}
              │ 调用 iceBuoyancy(b) 时整块复制
              ▼
函数中：b' = {3, 2.0, 1.5, 0.6, 1650.60}   ← 另一份独立内存
```

五个成员一口气复制过去。于是在函数内读 `b.length、b.mass` 与在 main 里读完全一样——**传"一块冰"，函数就真的拿到了完整的一块冰**。对比不用结构体的写法：`iceBuoyancy(len, wid, thick)` 要把三个成员逐个罗列，漏传、错序的风险随成员数增长；结构体参数一个顶一串，函数的参数表干净且不易错。

### 2. 值传递意味着"函数改不动原件"

副本与原件是两块独立内存，函数内写 `b.mass = 0;` 只改了副本，返回后 main 里的冰块毫发无损。对本题来说这是**恰好合适**的：三个计算函数都是"只读"的——它们只需要冰块的信息，不需要修改冰块。经验法则：**函数只读数据时，用值传递的结构体参数最安全**；若确实要修改原数据，需要结构体指针（本章 7.4，练习 08 预告）。

### 3. 复制是有代价的

整块复制意味着成员越多、结构体越大，每次调用复制的字节数越多。本例约 40 字节可忽略不计；工程中上千字节的大结构体常改传指针以省去复制。当前阶段结构体小、题目规模小，**放心用值传递**，把注意力放在"参数表简洁、语义清晰"上。

### 4. 物理公式先行

重力 $G = mg$，浮力按阿基米德原理 $F = \rho_{sea}\, g\, V$，其中 $V$ 由三个尺寸算出。净浮力 $F - G > 0$ 时冰块有上浮趋势——这正是 C8 后续"平衡吃水"方程（冰块部分淹没时求吃水深度）的起点，本练习先把"完全淹没"这一情形算清楚。

## 三、解题思路

1. **定类型**：`struct IceBlock` 五个成员照题干框架；
2. **拆函数**：体积、重力、浮力各成一个小函数，形参都是 `struct IceBlock b`；
3. **嵌套调用**：浮力函数内部调用体积函数，体现模块复用；
4. **常量**：`RHO_SEA = 1025.0`、`G = 9.8` 定义为 `const double`（可作全局常量，三个函数共用）；
5. **main 读入 → 调用 → 单位换算输出**：函数内以 N 为单位，输出时除以 1000.0 化 kN。

## 四、参考代码

```c
#include <stdio.h>

struct IceBlock {              /* 一块冰的完整信息 */
    int    id;
    double length;
    double width;
    double thickness;
    double mass;
};

const double RHO_SEA = 1025.0; /* 海水密度 kg/m^3 */
const double G       = 9.8;    /* 重力加速度 m/s^2 */

double iceVolume(struct IceBlock b)      /* 值传递：收到整块副本 */
{
    return b.length * b.width * b.thickness;
}

double iceGravity(struct IceBlock b)     /* 重力 = mg */
{
    return b.mass * G;
}

double iceBuoyancy(struct IceBlock b)    /* 完全淹没浮力 = 海水密度 x g x 体积 */
{
    return RHO_SEA * G * iceVolume(b);   /* 嵌套调用体积函数 */
}

int main(void)
{
    struct IceBlock b;
    double fw, fb, net;

    scanf("%d%lf%lf%lf%lf", &b.id, &b.length, &b.width, &b.thickness, &b.mass);

    fw  = iceGravity(b);       /* 每次调用都复制一份 b */
    fb  = iceBuoyancy(b);
    net = fb - fw;

    printf("重力 = %.2f kN\n", fw / 1000.0);
    printf("浮力 = %.2f kN\n", fb / 1000.0);
    printf("净浮力 = %.2f kN\n", net / 1000.0);

    return 0;
}
```

## 五、运行验证

| 输入 | 手算过程 | 程序输出 |
|---|---|---|
| `3 2.0 1.5 0.6 1650.60` | $V = 1.80$；$G = 1650.60 \times 9.8 = 16175.88$ N；$F = 1025 \times 9.8 \times 1.80 = 18081.00$ N；$F-G = 1905.12$ N | `重力 = 16.18 kN`、`浮力 = 18.08 kN`、`净浮力 = 1.91 kN` ✓ |
| `7 1.2 0.8 0.5 440.16` | $V = 0.48$；$G = 440.16 \times 9.8 = 4313.57$ N；$F = 1025 \times 9.8 \times 0.48 = 4821.60$ N；$F-G = 508.03$ N | `重力 = 4.31 kN`、`浮力 = 4.82 kN`、`净浮力 = 0.51 kN` ✓ |

两组数据中浮力均大于重力（海冰密度 917 < 海水 1025），净浮力为正、冰块上浮，与物理常识一致。

## 六、常见错误与讲解

**错误 1：形参写成类型名，漏了变量名**

```c
double iceVolume(struct IceBlock);        /* 声明中可以只写类型 */
double iceVolume(struct IceBlock b) { ... }   /* 定义中必须有变量名 b */
```

定义函数时若不写 `b`，函数体里就没有名字可用，编译报错"未声明的标识符"。

**错误 2：把"传结构体"误解为"传引用"，期望函数修改原件**

```c
void halfMass(struct IceBlock b) { b.mass = b.mass / 2; }   /* 改的是副本 */
halfMass(myIce);          /* 调用后 myIce.mass 纹丝不动 */
```

值传递的副本机制决定了函数内赋值影响不到主调函数——这不是 bug，是 C 的规矩；想改原件要用指针（7.4）。

**错误 3：全局常量忘了 const 或在函数里重复定义**

```c
double G = 9.8;                       /* 能用，但作为物理常数应加 const */
const double G = 9.8;                 /* 对：全程序共用一份只读常量 */
```

若在每个函数内部各写一遍常量，一旦改数值要改多处，容易漏改造成各函数用的"g"不一致。

**错误 4：单位混乱——kN 与 N 混用**

```c
printf("重力 = %.2f kN\n", fw);        /* 错：fw 单位是 N，数值大了 1000 倍 */
printf("重力 = %.2f kN\n", fw / 1000.0);   /* 对：输出前换算 */
```

用样例 1 自查：重力必须是 16.18 kN 而不是 16175.88。

## 七、与综合实验的衔接

实验 C8 的浮力计算主流程正是"体积 → 重力 → 浮力 → 净浮力 → 判断上浮/下沉"的函数链，本练习完成了其中"完全淹没"的部分；C8 后续的平衡吃水问题（部分淹没，浮力正比于淹没体积）将把净浮力等于零时的吃水深度作为方程根来求解（第 3、4 章的二分法/迭代法会再次登场）。练习 06 将解决本练习遗留的一个不便：三个函数各算一个量、main 要调用三次——让函数**一次性返回一个统计结果结构体**，一个函数顶三个返回值。
