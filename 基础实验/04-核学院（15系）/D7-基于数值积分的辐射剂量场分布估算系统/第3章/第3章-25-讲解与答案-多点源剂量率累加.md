## 二、预备知识：叠加求和为什么用累加器

### 1. 问题是怎么来的

上一练习算的是**一个源**的贡献。但现实中测点往往受多个源共同照射：近处一个强源、远处两块工件、头顶一根管道……总剂量率是它们**各自贡献之和**。

数学上这是求和：

$$
\dot{D}_{\text{总}} = \sum_{j=1}^{k} \frac{S_j}{d_j^{2}}
$$

符号 $\sum$ 的意思是"把 $j$ 从 1 到 $k$ 的每一项都加起来"。计算机不会一次算完全部求和，而是**一项一项加**——这就需要一个"累加器"：一个专门用来攒和的变量。

### 2. 累加器是怎么工作的

累加器的核心就一句话：**先清零，再反复加**。

```
Dtotal ← 0
对于每个源 j：
    Dtotal ← Dtotal + (第 j 项的贡献)
输出 Dtotal
```

**为什么必须先清零？** 因为 C 语言的变量定义后不会自动归零，里面是"上次那片内存留下的垃圾值"。若不清零，第一次累加就变成"垃圾值 + 第一项"，最后结果完全错乱。这是累加类程序最经典的错误。

**为什么能一项项加出总和？** 因为加法满足结合律：$(a + b) + c = a + (b + c)$。所以无论按什么顺序累加，只要不漏、不重，结果都等于总和。计算机正是利用这一点，用循环把 $k$ 项依次收拢进一个变量。

### 3. 用本例走一遍

样例 2 有三个源：$(S, d) = (120, 2)$、$(60, 5)$、$(40, 10)$，逐项算贡献：

| j | S | d | 贡献 S/d² |
|---|---|---|---|
| 1 | 120 | 2 | 120/4 = 30.00 |
| 2 | 60 | 5 | 60/25 = 2.40 |
| 3 | 40 | 10 | 40/100 = 0.40 |

累加过程：

- 初始 `Dtotal = 0`；
- 加第 1 项：`Dtotal = 0 + 30.00 = 30.00`；
- 加第 2 项：`Dtotal = 30.00 + 2.40 = 32.40`；
- 加第 3 项：`Dtotal = 32.40 + 0.40 = 32.80`。

结果 32.80 μSv/h。注意第 1 项占了总量的 91%——**近距离强源的贡献压倒性地大**，这是平方反比律的直接后果，也是辐射防护中"离源远一点"极其有效的原因。

### 4. 编程时怎么用它

循环三要素：**起点**（$j=0$，用计数器 `i`）、**终点**（`i < k`）、**步长**（`i++`）。循环体里就是"读一对数、算一项、加进去"。累加变量 `Dtotal` 必须在循环**之前**定义并清零。

> **这个思想在综合实验中反复出现**：D7 剂量场（每个测点叠加所有源）、D8 能谱寻峰（累加相邻道求净面积）、D3 截面插值（累加拉格朗日各项），全部是"清零 + 循环累加"。这是数值计算里最高频的两种模式之一（另一种是打擂台找最值）。

## 三、解题思路

1. **确定变量**：源个数 `k`（int）、循环变量 `i`（int）、当前源的 `S` 与 `d`（double）、累加器 `Dtotal`（double，初值 0.0）；
2. **读入 k**：`scanf("%d", &k);`；
3. **累加循环**：
   ```c
   for (i = 0; i < k; i++) {
       scanf("%lf %lf", &S, &d);
       Dtotal += S / (d * d);
   }
   ```
4. **输出**：`printf("Dtotal = %.4f\n", Dtotal);`，保留 4 位小数。

## 四、参考代码

```c
#include <stdio.h>

int main(void)
{
    int k, i;                  /* 点源个数、循环计数器 */
    double S, d;               /* 当前源的强度、距离 */
    double Dtotal = 0.0;       /* 总剂量率，累加前必须先清零 */

    scanf("%d", &k);           /* 读入点源个数 */

    for (i = 0; i < k; i++) {
        scanf("%lf %lf", &S, &d);      /* 读入第 i 个源的强度与距离 */
        Dtotal += S / (d * d);         /* 加上该源的平方反比贡献 */
    }

    printf("Dtotal = %.4f\n", Dtotal); /* 输出叠加后的总剂量率 */
    return 0;
}
```

## 五、运行验证

| 输入 | 手算过程 | 程序输出 |
|---|---|---|
| k=2: (120,2) (60,5) | 30.00 + 2.40 = 32.4000 | `Dtotal = 32.4000` ✓ |
| k=3: 再加 (40,10) | 32.40 + 0.40 = 32.8000 | `Dtotal = 32.8000` ✓ |
| k=1: (120,2) | 只有一项 30.0000（退化为单源） | `Dtotal = 30.0000` ✓ |
| k=4: 再加 (30,3) | 32.80 + 30/9 = 32.80 + 3.3333 = 36.1333 | `Dtotal = 36.1333` ✓ |

从 k=1 到 k=4，每次增添新源，总量只增不减，符合叠加的物理意义。

## 六、常见错误与讲解

**错误 1：累加器忘记清零**

```c
double Dtotal;                 /* 错：未初始化，初值是内存里的垃圾值 */
for (i = 0; i < k; i++) Dtotal += S / (d * d);
```

`Dtotal += ...` 展开是 `Dtotal = Dtotal + ...`，右边用了 `Dtotal` 自己的初值。若初值是垃圾值，结果全错。**规则：累加器定义时就要写 `= 0.0`。**

**错误 2：把累加写成赋值**

```c
Dtotal = S / (d * d);         /* 错：每次都覆盖，只留下最后一个源的贡献 */
Dtotal += S / (d * d);        /* 对：累加而不是覆盖 */
```

`=` 和 `+=` 差一个号，语义天壤之别：前者只保留最后一项，后者才是"总和"。**判据：要求"总和/累计"时一律用 `+=`。**

**错误 3：分母漏括号**

```c
Dtotal += S / d * d;          /* 错：算成 (S/d)*d = S，与距离无关 */
Dtotal += S / (d * d);        /* 对：先平方再除 */
```

与练习 26 同一个坑：乘除从左到右，`d * d` 必须加括号。

**错误 4：循环次数与读入不匹配**

```c
for (i = 0; i <= k; i++) { ... }    /* 错：多循环一次，多读一组数据（内存里没有，读到脏值） */
for (i = 0; i < k; i++)  { ... }    /* 对：正好 k 次，读 k 组数据 */
```

`k` 个源只能读 `k` 组数据，用 `<` 而非 `<=`，避免多读一组不存在的输入。
