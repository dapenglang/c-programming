## 二、预备知识：数组名交给函数时，到底发生了什么（零基础阅读）

### 1. 数组名在大多数场合"退化为首元素地址"

数组 `double a[50]` 在内存里是一排连续的抽屉。数组名 `a` 单独出现时，它代表的不是整排抽屉，而是**第一个抽屉的地址** `&a[0]`。所以：

```c
offset_all(a, n, bias);          /* 传进去的是首元素地址 */
offset_all(&a[0], n, bias);      /* 与上一行完全等价 */
```

函数定义里写 `double *a` 或 `double a[]`，对编译器来说是**同一件事**——接收一个"数组首地址"。这也是 C 语言里数组作参数"不拷贝整个数组、只传一个地址"的原因，效率很高。

### 2. 形参是地址的副本，但它指向的内存是调用者的

```
   main 的数组 a（连续内存）              offset_all 的形参
   ┌──────┬──────┬──────┬──────┐          ┌─────────────┐
   │ a[0] │ a[1] │ a[2] │ a[3] │  <───────│ a = 首地址  │
   │ 100  │ 105  │ 110  │ 115  │   指向   └─────────────┘
   └──────┴──────┴──────┴──────┘
        ▲  函数里执行 *(a+1) += (-2)：
        │  = 找到"首地址后第 1 个抽屉"，把里面改写为 103
        └─ 改的是 main 的 a[1]，不是副本
```

形参 `a` 本身确实是"地址的一份拷贝"，但这份拷贝里的地址指向哪儿，函数就在哪儿动手——动手的对象正是 `main` 的那排抽屉。所以 `offset_all` 执行完，`main` 里的 `a` 已经变了。这跟第 12 题"传变量地址"是同一个道理，只是这里传的是**一整片内存的起始地址**。

### 3. 一个必须牢记的陷阱：函数里 `sizeof(a)` 不再是数组长度

- 在 `main` 里，`sizeof(a) / sizeof(a[0])` = `50 * 8 / 8` = 50，能得到元素个数；
- 在 `offset_all` 里，`a` 已经退化成一个**指针变量**，`sizeof(a) = 8`（一个地址的大小），`sizeof(a) / sizeof(a[0]) = 8 / 8 = 1`，只有 1！（`sizeof(a[0])` 仍是 `double` 的 8 字节。）

所以函数**无法自己知道数组有多长**，必须由调用者把长度当参数传进来。这就是本练习接口 `(double *a, int n, double bias)` 里那个 `int n` 的由来——**"首地址 + 长度"是 C 语言处理数组的黄金搭档**。

### 4. 编程翻译

- 遍历：`for (i = 0; i < n; i++) *(a + i) += bias;`
- 想省一次加法也可写 `a[i] += bias;`，二者等价，选你觉得清楚的。

## 三、解题思路

1. **定接口**：`void offset_all(double *a, int n, double bias);`，无返回值，全部通过指针形参在原数组上生效；
2. **主流程**：读 `n` → 读 `n` 个数 → 读偏置 `bias` → 调用 → 输出；
3. **循环遍历**：函数内用下标或指针遍历 `0 ~ n-1`，逐元素 `+bias`；
4. **输出控制**：用 `i == n - 1 ? '\n' : ' '` 控制分隔符，保证行末换行、中间空格；
5. **格式**：每个值 `%.2f`。

## 四、参考代码

```c
#include <stdio.h>

/* 对数组 a 的每个元素加偏置 bias，直接作用在原数组上 */
void offset_all(double *a, int n, double bias)
{
    int i;
    for (i = 0; i < n; i++)
        *(a + i) += bias;    /* 等价于 a[i] += bias; */
}

int main(void)
{
    double a[50];            /* 测点压力序列，kPa */
    int n, i;
    double bias;             /* 零点修正偏置，kPa */

    scanf("%d", &n);
    for (i = 0; i < n; i++)
        scanf("%lf", &a[i]);
    scanf("%lf", &bias);

    offset_all(a, n, bias);  /* 数组名 a 就是首元素地址 */

    for (i = 0; i < n; i++)
        printf("%.2f%c", a[i], i == n - 1 ? '\n' : ' ');

    return 0;
}
```

## 五、运行验证

| 输入 | 手算过程 | 程序输出 |
|---|---|---|
| n=4，100 105 110 115，bias=−2 | 每个减 2：98、103、108、113 | `98.00 103.00 108.00 113.00` ✓ |
| n=3，20 40 60，bias=1.5 | 每个加 1.5：21.5、41.5、61.5 | `21.50 41.50 61.50` ✓ |

> 关键验证点：`main` 里打印的是 `a[i]`，而 `a` 从没在 `main` 里被赋值过第二次——能打印出修正值，正说明函数通过指针**改到了 `main` 的数组本体**。

## 六、常见错误与讲解

**错误 1：在函数里想用 `sizeof` 求长度**

```c
void f(double *a) {
    int n = sizeof(a) / sizeof(a[0]);   /* 错：a 是指针，n 恒为 1 */
    for (i = 0; i < n; i++) ...
}
```
只处理了一个元素，其余全被漏掉。**长度必须当参数传进来。**

**错误 2：形参漏写 `*`**

```c
void offset_all(double a, int n, double bias)   /* 错：a 变成一个 double，不是地址 */
```
此时 `a[i]` 无法编写，编译报错；即便改写成别的写法也完全达不到"改原数组"的效果。数组参数一定要写成指针或 `[]`。

**错误 3：把数组拷进局部数组再改**

```c
void offset_all(double *a, int n, double bias) {
    double b[50]; int i;
    for (i = 0; i < n; i++) b[i] = a[i];       /* 拷了一份 */
    for (i = 0; i < n; i++) b[i] += bias;      /* 改的是副本 */
}   /* 错：函数结束 b 销毁，main 的 a 毫无变化 */
```
要么直接在 `a` 上改，要么把副本的地址回传——本题要求"原地修改"，直接改 `a` 最简洁。

**错误 4：输出分隔符处理不当**

```c
for (i = 0; i < n; i++) printf("%.2f ", a[i]);   /* 行末多一个空格，且没有换行 */
```
虽多数判题系统容忍行末空格，但养成"中间空格、末尾换行"的习惯更规范，如参考代码所示。

## 七、与综合实验的衔接

- 在实验 **C9（冰压力场分析）**中，所有"预处理"函数（零点修正、单位换算、归一化）都采用本练习的接口风格：**首地址 + 长度**，直接在原数组上操作；
- 到了第 7 章，当数据不再是单个数字而是一条"测点记录"时，数组会升级成结构体数组，但"传首地址 + 长度、函数内遍历"的骨架原样保留。可以说，**掌握本题的接口，就掌握了后面所有批量处理函数的通用写法**。
