本题的"新知识"是把"两个文件"扩展到"多个文件"：指针多几个、纪律多几分，方法本身没有变。

## 二、预备知识：多文件数据流的组织原理（零基础阅读）

### 1. 为什么这样组织数据流

三个时刻的文件是**同构**的：同样的测点、同样的行数、同样的排列。要合成总表，最自然的想法是"对齐行合并"——第 1 行拼第 1 行，第 2 行拼第 2 行。用程序表达，就是让三个文件的读入进度**始终同步**：

```
p_t1.txt --fscanf--> (id, p1) ┐
p_t2.txt --fscanf--> (id, p2) ├─ fprintf --> p_all.txt: id p1 p2 p3
p_t3.txt --fscanf--> (id, p3) ┘
```

同步的办法是设一个**节拍器**：以第一个文件的 fscanf 返回值控制循环。第一个文件每成功读出一条记录，就"打一拍"，这一拍里再从第二个、第三个文件各读一条——三者的读入位置永远并排前进。循环结束时三个文件同时读完，总表恰好写完。

### 2. 各环节的职责

- **打开环节**：四个 fopen 依次执行，每一个都要检查。关键细节是**失败清理**：如果打开到第三个文件才失败，前两个已经打开的指针必须先 fclose 再退出，否则这些文件会被程序"占着不放"；
- **读入环节**：主循环的 while 条件只看 f1 的 fscanf 是否返回 2；f2、f3 的 fscanf 处于循环节拍之内。题目保证三个文件行数相同、编号一致，所以不必逐一判断——但工程上更稳妥的做法是把三个 fscanf 的返回值都纳入条件；
- **写出环节**：每拍用一条 fprintf 拼出四列。表头不属于数据，循环开始前单独写一次。

### 3. 文件指针的生命周期

本题四条生命周期并列：f1、f2、f3 从各自 fopen 起到循环结束关闭，fout 从 fopen 起到总表写完关闭。要记住两条铁律：其一，**失败的 fopen 返回 NULL，对 NULL 调 fclose、fscanf 都是未定义行为**，所以检查必须紧跟每个 fopen；其二，**提前退出路径上要关闭所有已打开的文件**，打开得越多，退出路径越要梳理清楚。

## 三、解题思路

1. **依次打开四个文件**并逐一检查；把"失败时关闭已打开文件再返回"处理成一条路径；
2. **写表头**：循环前 `fprintf(fo, "Point t1 t2 t3\n")`；
3. **同步循环**：以 f1 为节拍，每轮从三个文件各读一条，检查编号一致后拼行写出；
4. **收尾**：关闭四个文件，屏幕输出测点数。

## 四、参考代码

```c
#include <stdio.h>

int main(void)
{
    FILE *f1, *f2, *f3, *fo;   /* 三个源文件、一个总表文件 */
    int id, id2, id3;          /* 三个文件各自读到的测点编号 */
    double p1, p2, p3;         /* 三个时刻的压力值，kPa */
    int n = 0;                 /* 测点计数 */

    f1 = fopen("p_t1.txt", "r");
    f2 = fopen("p_t2.txt", "r");
    f3 = fopen("p_t3.txt", "r");
    fo = fopen("p_all.txt", "w");
    if (f1 == NULL || f2 == NULL || f3 == NULL || fo == NULL) {
        printf("错误：有文件无法打开\n");
        if (f1 != NULL) fclose(f1);      /* 失败清理：关掉已成功的 */
        if (f2 != NULL) fclose(f2);
        if (f3 != NULL) fclose(f3);
        if (fo != NULL) fclose(fo);
        return 1;
    }

    fprintf(fo, "Point t1 t2 t3\n");     /* 表头只写一次 */

    /* 以第一个文件为节拍器，三个文件同步前进 */
    while (fscanf(f1, "%d %lf", &id, &p1) == 2) {
        fscanf(f2, "%d %lf", &id2, &p2);
        fscanf(f3, "%d %lf", &id3, &p3);
        if (id2 != id || id3 != id) {    /* 对齐校验 */
            printf("错误：第 %d 号测点在三个文件中不对齐\n", id);
            fclose(f1); fclose(f2); fclose(f3); fclose(fo);
            return 1;
        }
        fprintf(fo, "%d %.1f %.1f %.1f\n", id, p1, p2, p3);
        n++;
    }

    fclose(f1);
    fclose(f2);
    fclose(f3);
    fclose(fo);
    printf("合并完成：共 %d 个测点\n", n);

    return 0;
}
```

## 五、运行验证

**文件内容前后变化**：三个源文件保持不变；`p_all.txt` 从无到有，内容如题干样例所示。逐行核对：测点 1 的三个压力 21.5、22.1、22.9 分别来自 t1、t2、t3 文件的第 1 行；测点 4 的 22.4、23.0、23.8 来自三个文件的第 4 行——列的顺序与文件的顺序一一对应，没有串位。

**屏幕输出**：

```
合并完成：共 4 个测点
```

附加验证：故意把 `p_t3.txt` 的第 2 行编号改成 9，再运行程序，应看到：

```
错误：第 2 号测点在三个文件中不对齐
```

说明对齐校验起了作用（验证后把文件改回原样）。

## 六、常见错误与讲解

**错误 1：只检查第一个 fopen**

```c
f1 = fopen("p_t1.txt", "r");
if (f1 == NULL) { printf("错误\n"); return 1; }
f2 = fopen("p_t2.txt", "r");       /* 错：f2、f3、fo 没检查，若 p_t2.txt 不存在，
                                      后面对 f2 的 fscanf 就是未定义行为 */
```

多文件程序中每个 fopen 后都要检查；也可以像参考代码那样集中判断一次，但要配合"失败清理"。

**错误 2：把 fo 也放进循环条件里**

```c
while (fscanf(f1, ...) == 2 && fscanf(fo, ...) == 2)   /* 错：fo 是写文件，不能 fscanf */
```

读写方向要分清：三个 "r" 的指针只能读，"w" 的指针只能写。

**错误 3：表头写进了循环里**

```c
while (...) {
    fprintf(fo, "Point t1 t2 t3\n");   /* 错：每行数据前面都多一个表头 */
    ...
}
```

表头是"一次性的"，应写在循环之前。

**错误 4：认为读不到数据时 fscanf 会返回 0 或崩溃**

读到文件末尾，fscanf 返回常量 EOF（-1）。用 `== 2` 作判据天然把 EOF 和"残缺行"都挡在循环外，这是最稳的写法；不要写成 `!= EOF`，那样遇到残缺行（返回 1）会死循环。

## 七、与综合实验的衔接

- 实验 **C9（压力场监测与热点分析）**的完整流程是"多时刻采集 → 合并总表 → 网格统计 → 热点定位"。本练习就是合并环节：真实系统中时刻文件可能有几十个、测点成百上千，还会先按时间排序再合并，但"同构文件对齐合并"的核心写法与本题完全一致。当源文件多到十几个时，可以把三个源指针换成**文件指针数组** `FILE *fin[3]`，配合循环处理——这是第 6 章指针数组的直接应用；
- 合并后的总表 `p_all.txt` 正是后续统计程序的标准输入。练习 20 的完整流水线里也有"多源汇聚"这一站，届时你会发现本题的节拍器思想原封不动地搬了过去。
