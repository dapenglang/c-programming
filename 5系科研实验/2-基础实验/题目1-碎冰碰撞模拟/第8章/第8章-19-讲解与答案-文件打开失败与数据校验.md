## 二、预备知识：文件容错三道关的基本原理（零基础阅读）

### 1. 为什么这样组织数据流

一个"从文件取数据"的程序，数据在抵达计算环节之前要过**三道关**，任何一道不过都要安全退出：

```
第 1 关：文件能打开吗？      —— fopen 返回 NULL？
第 2 关：数据读得进来吗？    —— fscanf 返回值够 3 项吗？
第 3 关：数据本身合理吗？    —— 质量为正？速度在范围内？
```

三道关对应三类故障：**环境故障**（文件不存在、无权限、路径错）、**格式故障**（文件残缺、行不完整）、**内容故障**（格式对但数值离谱）。真实工程中三类故障都常见，程序必须逐一把关。

### 2. 各关的技术要点

**第 1 关**：fopen 找不到文件时返回空指针 NULL。此刻**必须立即停止**：对 NULL 指针调用 fscanf、fclose 都是未定义行为，程序可能崩溃、可能输出垃圾。检查语句紧跟 fopen，两行之内完成；失败退出时用非零返回值（return 1）向操作系统报告"出了错"。

**第 2 关**：fscanf 返回成功赋值的项数。残缺行（例如只有编号没有数值）返回 1 或 2，不足 3 就不能当作完整记录处理。`while (fscanf(...) == 3)` 把"读到不完整数据"与"读到文件尾"统一挡在循环外。

**第 3 关**：格式正确不代表内容正确。质量录成 −3.0、速度录成 6.2，语法上毫无问题，物理上毫无意义。校验规则来自**领域知识**（冰块质量必为正、速度有物理上限），这就是工程师在程序里留下的"常识"。

### 3. 文件指针生命周期

fin 从 fopen（过第 1 关才算拿到）到读完 fclose；fout 只在需要写合法记录时打开，若打开 ice_params.txt 就失败，fout 根本不应创建。生命周期管理的关键新意在于**退出路径变多了**：正常结束、第 1 关失败、第 2/3 关中途正常读完——每条路径都要保证"已打开的文件全部关闭"。

## 三、解题思路

1. **第 1 关**：fopen 检查 NULL，失败输出错误、return 1；
2. **打开输出文件**：fout 以 "w" 打开 ice_valid.txt 并检查（失败时先关 fin）；
3. **循环读入（第 2 关）**：`while (fscanf(fin, "%s %lf %lf", ...) == 3)`，每轮总条数加一；
4. **校验（第 3 关）**：if-else 串联——质量 ≤ 0 报"质量必须为正"；否则速度不在 [0,5] 报"速度超出范围"；否则写入 ice_valid.txt 并合法数加一；
5. **收尾**：fclose 两个文件，输出三合一统计行。

## 四、参考代码

```c
#include <stdio.h>

int main(void)
{
    FILE *fin, *fout;
    char id[8];               /* 冰块编号 */
    double m, v;              /* 质量 t、速度 m/s */
    int total = 0, ok = 0, bad = 0;

    /* 第 1 关：文件能打开吗 */
    fin = fopen("ice_params.txt", "r");
    if (fin == NULL) {
        printf("错误：无法打开 ice_params.txt\n");
        return 1;
    }

    fout = fopen("ice_valid.txt", "w");
    if (fout == NULL) {
        printf("错误：无法创建 ice_valid.txt\n");
        fclose(fin);
        return 1;
    }

    /* 第 2 关 + 第 3 关：逐条读入并校验 */
    while (fscanf(fin, "%s %lf %lf", id, &m, &v) == 3) {
        total++;
        if (m <= 0) {
            printf("%s 非法（质量必须为正）\n", id);
            bad++;
        } else if (v < 0 || v > 5) {
            printf("%s 非法（速度超出范围）\n", id);
            bad++;
        } else {
            fprintf(fout, "%s %.1f %.1f\n", id, m, v);   /* 合法记录存档 */
            ok++;
        }
    }

    fclose(fin);
    fclose(fout);

    printf("共 %d 条，合法 %d 条，非法 %d 条\n", total, ok, bad);
    return 0;
}
```

## 五、运行验证

**逐条核对校验逻辑**：

| 记录 | 质量校验 | 速度校验 | 结论 |
|---|---|---|---|
| B01 12.5 0.8 | 12.5 > 0 通过 | 0.8 在 [0,5] 内 | 合法，写入 |
| B02 -3.0 1.1 | −3.0 ≤ 0 | （不再检查） | 非法（质量必须为正） |
| B03 9.6 0.5 | 9.6 > 0 通过 | 0.5 在 [0,5] 内 | 合法，写入 |
| B04 15.0 6.2 | 15.0 > 0 通过 | 6.2 > 5 | 非法（速度超出范围） |

**文件内容前后变化**：`ice_params.txt` 保持不变；`ice_valid.txt` 新建，只含 B01、B03 两行，内容与题干样例一致。

**屏幕输出**：

```
B02 非法（质量必须为正）
B04 非法（速度超出范围）
共 4 条，合法 2 条，非法 2 条
```

**附加测试**：把 ice_params.txt 临时改名（或移走）再运行，屏幕输出：

```

```

程序立即退出、返回值 1，没有崩溃——第 1 关生效（测完把文件名改回来）。

## 六、常见错误与讲解

**错误 1：不检查 fopen 就直接使用**

```c
fin = fopen("ice_params.txt", "r");
while (fscanf(fin, "%s %lf %lf", ...) == 3)   /* 错：文件不存在时 fin 为 NULL，程序崩溃 */
```

这是本题要根除的头号坏习惯。判定标准很简单：**写了 fopen 的下一行，必须是 if 检查**。

**错误 2：两个 fopen 的失败路径处理不对称**

```c
fout = fopen("ice_valid.txt", "w");
if (fout == NULL) return 1;    /* 错：fin 已经打开，泄漏了 */
if (fout == NULL) { fclose(fin); return 1; }   /* 对：先关 fin 再退出 */
```

退出路径越多越要清点：**退出的那一刻，谁还开着？**

**错误 3：校验顺序不当导致重复报错**

```c
if (m <= 0) printf("%s 非法（质量必须为正）\n", id);
if (v < 0 || v > 5) printf("%s 非法（速度超出范围）\n", id);   /* 错：两个独立 if，
    质量与速度都不合法的记录会连报两行，且该记录既没写入也没正确计数 */
```

用 if-else 串联保证一条记录恰好落入一个分支；若确实希望一条记录报出全部问题，则要重构计数逻辑——本题约定报第一个原因即可。

**错误 4：边界值判断写错**

```c
if (v <= 0 || v > 5)    /* 错：把合法的静止冰块 v = 0 判成非法 */
if (v < 0 || v > 5)     /* 对：0 是合法速度（静止冰块），5 是闭区间上界 */
```

边界值 0、5 必须单独代入测试——样例中 B03 的 0.5 距边界较远，建议自测时补一条 `B05 8.0 0` 验证 0 的合法性（应写入 ice_valid.txt）。
