# 题目 B9：基于贪心策略的机房任务调度模拟系统

**适用学院**：人工智能学院（4 系）　**组容量**：本题目最多 3 组选择

## 一、系统/算法说明

**系统做什么**：本系统是一套命令行机房任务调度模拟器：读入一批"上机任务"（提交时刻、预计运行时长、优先级），把它们按不同的贪心策略分配到 m 台机器上运行，逐任务记录开始时间与完成时间，统计平均等待时间、平均周转时间、最长等待等指标，以甘特图字符画直观展示各机器的任务安排，并把三种策略的指标放在一起对比，回答"哪种策略让任务排队更划算"。

**解决什么重要问题**：机房、服务器集群、云计算平台都面临同一个问题：大量任务到达，机器数量有限，先做谁后做谁？排错顺序的代价是实打实的——同样一批任务，好策略能让平均等待时间缩短一半，差策略会让短任务被长任务"堵死"（护航效应）。调度问题本身是经典的 NP 难问题，工程上通行做法是贪心：每一步只按一条明确规则选"当下最合适"的任务。本系统让学生用模拟实验亲手验证三种经典贪心规则的优劣，理解"贪心不一定最优、但必须有数据支撑"。

**支撑哪些关键应用**：① 操作系统的进程/作业调度（FCFS、SJF、优先级调度正是教材标准内容）；② 云计算与数据中心集群的任务编排；③ 智能制造生产线的排产排程；④ 打印队列、客服派单等日常排队系统。

**与专业培养的关联**：智能优化与调度是人工智能专业"智能控制与机器人""数据挖掘"方向的常见课题，而贪心是所有优化方法中最基础的构造式方法。本系统用课程内的排序、数组、结构体和过程模拟，让学生完整体验"建模—模拟—量化评估—对比决策"的实验闭环，为后续学习操作系统与智能优化课程建立直觉。

## 二、题目任务与专业关联

本题目要求实现一个含 10 个模块的任务调度模拟系统：(1) 从任务清单文件读入任务列表并校验清洗；(2) 交互录入机器台数等机房参数；(3) 实现三种贪心调度模拟：先来先服务（按提交时刻排序）、最短作业优先（按时长升序排序）、优先级调度（按优先级升序、同级按提交时刻），统一的分配规则为"任务依次分给当前空闲时刻最早的机器"；(4) 统计每任务等待时间、周转时间及各项平均指标；(5) 输出三策略对比表、甘特图字符画、调度记录文件与主控菜单。

专业关联：三种策略与操作系统课程中的作业调度算法同名同义；"用指标对比方案"则是数据挖掘与智能优化实验的标准流程。学生完成本题即完成了一次完整的"调度算法离线评估实验"。

## 三、数据来源与格式

### 3.1 数据文件格式

任务清单文件 `tasks.txt`：首行为 `#` 说明行，其后每行一个任务，字段以空格分隔。

```
# 任务编号 提交时刻(min) 预计运行时长(min) 优先级(1=最高, 5=最低)
T01  0.0  12.5  3
T02  1.5   4.0  1
T03  3.0  20.0  5
T04  4.5   2.5  2
T05  7.0  15.0  4
```

### 3.2 仿真数据生成规则

学生按下述规则生成 3 套规模不同的任务清单（20、30、40 个任务）：

| 字段 | 说明 | 单位/取值规则 |
|---|---|---|
| 提交时刻 | 单位：分钟 | 从 0.0 起递增，相邻间隔取 0～8 分钟的均匀随机数，模拟任务陆续到达 |
| 运行时长 | 单位：分钟 | 混合分布：30% 为短任务（1～5 分钟）、50% 为中等任务（5～15 分钟）、20% 为长任务（15～30 分钟），保留 1 位小数 |
| 优先级 | 整数 1～5 | 1～5 均匀随机，1 最高 |
| 异常注入·坏行 | 考察读入健壮性 | 每份清单混入 2～3 行坏数据：时长 ≤ 0 或 > 120 分钟、提交时刻为负；M1 读入时须丢弃、计数并在屏幕报告 |
| 异常注入·乱序 | 考察预处理 | 生成的清单故意不按提交时刻排序（约 10% 的行位置打乱），M1 读入后须按提交时刻重新排序 |
| 优先级越界 | 截断处理 | 混入 1～2 行优先级为 0 或 9 的记录，读入时截断到 [1,5] |

机器台数由交互录入（1～6 台，建议实验 2、3、4 台三组）。

### 3.3 真实数据集

无公开数据集。任务参数为自拟仿真数据；规则 3.2 参照操作系统教材中作业调度的典型算例设计，选做时可仿照教材例题数值构造"已知最优答案"的小算例用于验证。

## 四、数据结构设计

```c
#define MAX_TASK 60         /* 任务上限 */
#define MAX_MACH 6          /* 机器上限 */

/* 任务条目：输入字段 + 模拟结果字段一体存储 */
struct Task {
    char   id[8];            /* 任务编号，如 T01 */
    double arrive;           /* 提交时刻（min） */
    double dur;              /* 预计运行时长（min） */
    int    prio;             /* 优先级 1~5，1 最高 */
    /* ---- 模拟结果字段（各策略分别计算） ---- */
    double start;            /* 开始运行时刻（min） */
    double finish;           /* 完成时刻（min） */
    double wait;             /* 等待时间 = start - arrive（min） */
    int    machine;          /* 分配到的机器编号 1~m */
};

struct Task g_task[MAX_TASK];      /* 原始任务表（读入后即固定） */
struct Task g_run[MAX_TASK];       /* 参与当前策略模拟的工作副本 */
int    g_taskCount;                /* 有效任务数 */
int    g_machNum;                  /* 机器台数 1~6 */
double g_freeTime[MAX_MACH];       /* 各机器当前空闲时刻（min） */

/* 各策略的指标汇总，供对比表使用 */
struct Metrics {
    char name[20];                 /* 策略名，如 "SJF" */
    double avgWait;                /* 平均等待时间（min） */
    double avgTurn;                /* 平均周转时间（min） */
    double maxWait;                /* 最长等待时间（min） */
    double makespan;               /* 全部完成时刻（min） */
    double util;                   /* 机器平均利用率（0~1） */
};
struct Metrics g_metric[3];        /* 依次存放 FCFS / SJF / 优先级 */
```

## 五、功能模块拆解（共 10 个模块）

### 第一部分：数据读入（2 个模块）

**M1 任务清单文件读入模块**（源文件 `TaskIO.c`）

- 功能简介：打开 `tasks.txt` 逐行读入任务；坏行（时长或提交时刻非法）丢弃并计数，优先级越界截断到 [1,5]；读入完成后按提交时刻对任务表排序（冒泡排序），屏幕报告有效任务数、丢弃行数与时间跨度。
- 输入：文件路径（默认 `tasks.txt`）。
- 输出：`g_task` 与 `g_taskCount`；屏幕读入报告。

**M2 机房参数录入模块**（源文件 `Param.c`）

- 功能简介：交互录入机器台数（校验 1～6，超界重输）、策略选择或"三策略全跑"选项；录入后显示"m 台机器 × N 个任务"的实验配置摘要，并把配置写入日志备 M9 使用。
- 输入：用户键盘输入。
- 输出：`g_machNum`、策略选择标志；屏幕配置摘要。

### 第二部分：算法实现（4 个模块）

**M3 先来先服务调度模拟模块**（源文件 `FCFS.c`）

- 功能简介：把 `g_task` 复制到 `g_run`，按提交时刻顺序逐个任务决策：选当前空闲时刻最早的机器（并列取编号小者），任务的开始时刻 = max(任务提交时刻, 机器空闲时刻)，据此填 finish、wait、machine 并更新机器空闲时刻；提供统一入口函数供主控调用。
- 输入：`g_task`、机器台数。
- 输出：填充 `g_run` 的结果字段；返回状态。

**M4 最短作业优先调度模拟模块**（源文件 `SJF.c`）

- 功能简介：把任务按运行时长升序排序（时长相同按提交时刻），然后复用与 M3 完全相同的"选最早空闲机器"分配流程模拟；模拟前把 `g_run` 恢复为原始副本，保证三种策略互不污染。
- 输入：`g_task`、机器台数。
- 输出：填充 `g_run` 结果字段。

**M5 优先级调度模拟模块**（源文件 `Prio.c`）

- 功能简介：把任务按"优先级升序、同级按提交时刻"排序后复用同一分配流程模拟；排序用统一的选择排序函数（比较关键字作参数传入，体现"一个排序函数服务三种策略"的函数复用思想）。
- 输入：`g_task`、机器台数。
- 输出：填充 `g_run` 结果字段。

**M6 指标统计模块**（源文件 `Metrics.c`）

- 功能简介：基于 `g_run` 统计当前策略的四项核心指标：平均等待时间、平均周转时间（finish − arrive）、最长等待时间、全部完成时刻 makespan；再按"总运行时长 ÷ (机器台数 × makespan)"估算机器平均利用率；结果写入 `g_metric` 对应槽位并屏幕打印。
- 输入：`g_run`、策略名。
- 输出：`g_metric` 相应槽位；屏幕指标。

### 第三部分：数据输出（4 个模块）

**M7 三策略对比表模块**（源文件 `Compare.c`）

- 功能简介：读取 `g_metric` 三个槽位，输出对齐对比表（策略 × 指标），每列最优值加 `*` 标注，并在表尾自动给出一句结论（如"本数据集下 SJF 平均等待时间最短，比 FCFS 缩短 41%"）。
- 输入：`g_metric`。
- 输出：屏幕对比表与结论。

**M8 甘特图字符画模块**（源文件 `Gantt.c`）

- 功能简介：对选定策略绘制甘特图：每台机器一行，时间轴按 1 字符 = 2 分钟缩放，任务块用其编号后两位数字填充（如 `05`），空闲用 `.` 填充；行尾给出该机器的任务数与利用率；超长行自动截断。
- 输入：`g_run`、机器台数、makespan。
- 输出：屏幕甘特图。

**M9 调度记录文件输出模块**（源文件 `Record.c`）

- 功能简介：把当前策略（或三策略全部）的逐任务调度明细写入 `schedule_fcfs.csv` 等文件：任务编号、提交时刻、时长、优先级、开始、完成、等待、机器号；文件名自动携带策略名，互不覆盖。
- 输入：`g_run`、`g_metric`。
- 输出：CSV 文件；屏幕确认信息。

**M10 主控菜单模块**（源文件 `main.c`）

- 功能简介：文本主菜单（读入任务 / 机房参数 / FCFS 模拟 / SJF 模拟 / 优先级模拟 / 指标统计 / 对比表 / 甘特图 / 写记录 / 退出），`do-while + switch` 调度；状态约束"必须先读入任务并录入机器台数才能模拟"。
- 输入：用户菜单选项。
- 输出：调度各模块。

## 六、数据流与控制流

**控制流**：`main()` 菜单循环 → switch 分发 M1～M9 → 直至退出。状态约束：M3/M4/M5 均依赖 M1 与 M2；每次模拟后应立即执行 M6 统计；M7/M8/M9 作用于"最近一次模拟"的结果。

**数据流**：

```
tasks.txt ──► M1 读入校验+排序 ──► g_task[]（原始任务表，只读）
                                        │
用户录入 ─────► M2 机房参数 ────► g_machNum
                                        │
              ┌────────────────────────┼────────────────────────┐
              ▼                        ▼                        ▼
       M3 FCFS 模拟             M4 SJF 模拟             M5 优先级模拟
       （g_run 工作副本，三策略共用同一"选最早空闲机器"分配流程）
              └──────────── 每次模拟后 ────► M6 指标统计 ──► g_metric[3]
                                                                        │
                        ┌───────────────────────────────────────────────┤
                        ▼                       ▼                       ▼
                 M7 三策略对比表          M8 甘特图字符画         M9 调度记录 CSV
```

所有模块之间只通过 `g_task`、`g_run`、`g_freeTime`、`g_metric` 与参数传递交换数据，接口（函数头部）编码前书面约定。

## 十、选做扩展

1. 任务到达过程动画：逐任务打印"决策时刻—选中任务—落到的机器"的滚动明细，模拟排队过程（纯循环输出，无新理论）；
2. 加权优先级混合策略：新策略 = 优先级 × 权重 + 时长排序加权，权重由用户输入 0～1 的系数控制，纳入对比表（仍是排序贪心）；
