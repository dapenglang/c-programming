## 二、预备知识：一个函数的"输入指针"与"输出指针"（零基础阅读）

### 1. 函数与外界通信的三条途径

一个筛选函数要往外"交代"两件事：**筛出了哪些数据**、**一共筛出几个**。C 语言的函数往外传信息只有三条途径：

1. **`return` 交回一个值**——适合"个数"这种单个数字；
2. **指针参数写回**——适合"一批数据"这种不定长结果；
3. 全局变量——本题不用（不利于模块化）。

于是很自然地分工：`return` 负责个数，指针参数负责数据。

### 2. 为什么不让函数直接"返回一个数组"

C 语言规定函数**不能返回数组**。想返回数组只能返回指针，但如果指针指向函数内部的局部数组，函数一返回它就销毁了（第 11 题的"错误 1"）。稳妥的做法是反过来：**由调用者准备好一块存放区，把它的地址传给函数，让函数往里写。**

```
   main 提供两块内存：
     ┌── a[0..n-1] ──┐           ┌── sel[0..49] ──┐
     │ 原始样本(只读) │           │ 结果存放区(可写)│
     └───────────────┘           └────────────────┘
                │                          ▲
      const double *a                double *out
                └────────  filter_ge  ──────┘
                          返回 k = 写入的个数

   执行后：sel[0]=30.0  sel[1]=45.2  sel[2]=20.0  sel[3]=30.0
           返回值 k = 4，main 就知道"第二行打印前 4 个"
```

### 3. 这种接口模式的通用性

```
   int  f(const T *in, int n, ..., T *out);
   ─┬─      ─┬───             ──┬──
    │        │                  └── 可写指针：函数往外送数据
    │        └── 只读指针：原始输入，承诺不改
    └── 返回值：结果个数
```

只要结果个数事先不知道，就用这条模式。它把"读哪、写哪、写几个"三件事分得清清楚楚：**`const` 管住输入不被误改，`out` 管住结果有地方落，`return` 管住个数**。

### 4. 责任划分（务必记住）

- 保证 `out` 指向的空间**足够大**，是**调用者**的责任（本题 `sel[50]`，最多 50 个样本，够用）；
- 保证**不越界**、**不修改只读输入**，是**函数**的责任。

## 三、解题思路

1. **定接口**：`int filter_ge(const double *a, int n, double thr, double *out);`
2. **定遍历**：`for (i = 0; i < n; i++)`，逐个看 `a[i] >= thr` 是否成立；
3. **定写入**：成立就 `out[k] = a[i]; k++;`（也可写成 `out[k++] = a[i];`）；
4. **定返回**：`return k;`
5. **定输出**：主函数先打印个数，再循环打印前 `cnt` 个；若 `cnt == 0` 补一个空行。

## 四、参考代码

```c
#include <stdio.h>

/* 把 a 中 >= thr 的元素按原顺序写入 out，返回写入个数 */
int filter_ge(const double *a, int n, double thr, double *out)
{
    int i, k = 0;

    for (i = 0; i < n; i++)
        if (a[i] >= thr)        /* 只读原数据 */
            out[k++] = a[i];    /* 写入目标数组，k 自增 */

    return k;                   /* 报告筛选出几个 */
}

int main(void)
{
    double a[50], sel[50];      /* 原样本 + 结果存放区 */
    int n, i, cnt;
    double thr;                 /* 阈值，kN */

    scanf("%d", &n);
    for (i = 0; i < n; i++)
        scanf("%lf", &a[i]);
    scanf("%lf", &thr);

    cnt = filter_ge(a, n, thr, sel);   /* 只读 a，写 sel，返回个数 */

    printf("count = %d\n", cnt);
    for (i = 0; i < cnt; i++)
        printf("%.2f%c", sel[i], i == cnt - 1 ? '\n' : ' ');
    if (cnt == 0)
        printf("\n");           /* 无合格样本时输出空行 */

    return 0;
}
```

## 五、运行验证

| 输入 | 手算过程 | 程序输出 |
|---|---|---|
| 6 / 12.5 30.0 8.4 45.2 20.0 30.0，thr=20 | ≥20 的有 30.0、45.2、20.0、30.0，共 4 个 | `count = 4`；`30.00 45.20 20.00 30.00` ✓ |
| 5 / 5 15 25 35 45，thr=25 | ≥25 的有 25、35、45，共 3 个 | `count = 3`；`25.00 35.00 45.00` ✓ |

> 边界说明：`20.0 >= 20.0` 成立，所以样例 1 中的 20.0 被保留——可见用 `>=` 而非 `>`，一个等号的差别会直接影响筛选个数。

## 六、常见错误与讲解

**错误 1：阈值边界判断写错**

```c
if (a[i] > thr)      /* 错：漏掉"等于阈值"的样本 */
if (a[i] >= thr)     /* 对：题目要求"大于等于" */
```
样例 1 里 20.0 恰好等于阈值，用 `>` 会少筛一个，`count` 由 4 变 3。

**错误 2：计数与写入不同步**

```c
for (i = 0; i < n; i++)
    if (a[i] >= thr) out[i] = a[i];   /* 错：用 i 当下标，会在 out 中留下"空洞" */
```
若第 0 个样本不合格、第 1 个合格，`out[0]` 未被赋值却仍是脏数据。正确做法是用独立计数器 `k`，只在写入时前进。

**错误 3：企图修改只读输入**

```c
int filter_ge(const double *a, ...) {
    a[0] = 0;    /* 错：编译报错 assignment of read-only location */
}
```
这说明原数据是"只读契约"保护的：函数只许看，不许动。

**错误 4：接收区太小导致越界**

```c
double sel[3];
filter_ge(a, 50, thr, sel);   /* 若合格样本超过 3 个，就会越界写，破坏其他内存 */
```
调用者必须保证 `out` 容量不小于"最多可能的合格个数"。本题原样本最多 50 个，故 `sel[50]` 安全。
