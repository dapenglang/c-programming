## 二、预备知识：结构体数组上排序的基本原理（零基础阅读）

### 1. 内存布局决定了"交换必须整块换"

结构体数组在内存中是连续的"大块套小格"：

```
a[0]                a[1]                a[2]
+----+-------+-------+----+-------+-------+
| no | mass  | force | no | mass  | force |
+----+-------+-------+----+-------+-------+
|<--- 一次撞击事件 --->|<--- 一次撞击事件 --->|
```

排序的目标是让**整个格子**按 `force` 从大到小重新排队。若只交换 `a[j].force` 与 `a[j+1].force` 两个数，`no` 与 `mass` 仍留在原位——结果 3 号格子里写着"15.20 kN"，编号却是 1 号冰，报表彻底失真。正确做法是把结构体**当作一个整体值**来交换：C 语言允许同类结构体之间整体赋值（`a[j] = a[j+1];` 会把全部成员一口气复制过去），借助一个同类型的临时变量即可完成三步交换。

### 2. 冒泡排序的框架原封不动

第 5 章的冒泡排序是"相邻比较、逆序交换"，比较的对象从 `a[j]` 变成 `a[j].force`，交换的对象从 `a[j]` 变成整个结构体，框架完全不变：

```
for (i = 0; i < n-1; i++)
    for (j = 0; j < n-1-i; j++)
        if (a[j].force < a[j+1].force)   /* 降序：前面小就交换 */
            交换 a[j] 与 a[j+1] 这两个整块
```

降序用 `<`：前一个比后一个小，说明"轻的挡在重的前面"，交换让大的前移。

### 3. 为什么交换整个结构体是"安全"的

三个成员一起搬家，编号、质量、阻力的对应关系在交换前后始终绑定在同一个结构体里——**数据的一致性由语法保证**，不需要程序员额外操心。这正是第 7 章"结构化封装"的价值：封装之后，"一条记录"成了不可拆分的整体，任何搬运都是整块搬运。

### 4. 相等元素怎么办

比较条件用严格小于 `<`（而不是 `<=`），阻力相等的两个样本不交换，保持输入时的相对次序（样例 1 中 2 号在 4 号前，输出仍是 2 号在前），这与第 5 章冒泡排序的行为一致。

## 三、解题思路

1. **定类型定数组**：`struct Sample a[10];`，临时变量 `struct Sample temp;`；
2. **读入**：循环读 $n$ 条记录，直接存入 `a[i]` 的三个成员；
3. **冒泡排序**：双重循环，比较 `a[j].force` 与 `a[j+1].force`，降序则整体交换；
4. **输出**：单循环按 `编号 质量 阻力` 格式输出。

## 四、参考代码

```c
#include <stdio.h>

struct Sample {                /* 一次撞击事件的完整记录 */
    int    no;                 /* 冰块编号 */
    double mass;               /* 冰块质量 kg */
    double force;              /* 撞击阻力峰值 kN */
};

int main(void)
{
    struct Sample a[10], temp; /* temp 用于整体交换 */
    int n, i, j;

    scanf("%d", &n);
    for (i = 0; i < n; i++)
        scanf("%d%lf%lf", &a[i].no, &a[i].mass, &a[i].force);

    /* 冒泡排序：按阻力 force 降序，交换时整块交换 */
    for (i = 0; i < n - 1; i++)
        for (j = 0; j < n - 1 - i; j++)
            if (a[j].force < a[j + 1].force) {
                temp   = a[j];       /* 三步交换：整个结构体 */
                a[j]   = a[j + 1];
                a[j+1] = temp;
            }

    /* 输出排序后的样本表 */
    for (i = 0; i < n; i++)
        printf("%d %.2f %.2f\n", a[i].no, a[i].mass, a[i].force);

    return 0;
}
```

## 五、运行验证

以样例 1 走一遍排序（只列编号，括号内为阻力）：

初始：1(12.5)　2(8.3)　3(15.2)　4(8.3)　5(10.6)

- 第 1 轮（j = 0~3）：12.5 与 8.3 不换；8.3 与 15.2 交换；8.3 与 8.3 不换；8.3 与 10.6 交换 → `1(12.5) 3(15.2) 2(8.3) 5(10.6) 4(8.3)`；
- 第 2 轮（j = 0~2）：12.5 与 15.2 交换；12.5 与 8.3 不换；8.3 与 10.6 交换 → `3(15.2) 1(12.5) 5(10.6) 2(8.3) 4(8.3)`；
- 第 3、4 轮：相邻均为"前大后小"，无交换，序列不再变化。

每轮结束时序列如下（降序冒泡每轮把当前最小值"沉"到末尾）：

| 轮次结束后序列（编号） | 说明 |
|---|---|
| 初始 | 1 2 3 4 5 |
| 第 1 轮 | 1 3 2 5 4 |
| 第 2 轮 | 3 1 5 2 4 |
| 第 3 轮 | 3 1 5 2 4（已有序，无交换） |
| 第 4 轮 | 3 1 5 2 4 |

相等的 8.3(2) 与 8.3(4) 始终保持 2 在前的输入次序。程序输出：

```
3 1834.00 15.20
1 1650.60 12.50
5 1210.00 10.60
2 440.16 8.30
4 890.50 8.30
```

与题干样例 1 一致 ✓。样例 2 输出 `7 720.50 11.20`、`6 500.00 9.90`、`8 300.00 9.90`，相等的 9.9 保持 6 在 8 前的输入次序 ✓。

## 六、常见错误与讲解

**错误 1：只交换关键字，不交换整个结构体**

```c
double tf = a[j].force;              /* 错：只换了阻力，编号、质量没动 */
a[j].force = a[j+1].force;
a[j+1].force = tf;
```

排序结果"编号与阻力对不上号"，这是本节最隐蔽的错误——程序能跑、数字有序，但报表是错的。**记住：比较用成员，交换用整体。**

**错误 2：临时变量类型不对**

```c
int temp;                 /* 错：temp 要装下整个结构体 */
struct Sample temp;       /* 对：与数组元素同类型的结构体变量 */
```

**错误 3：降序条件写反**

```c
if (a[j].force > a[j+1].force)   /* 这是升序的条件，会输出从小到大 */
if (a[j].force < a[j+1].force)   /* 降序用 <：小的往后挪 */
```

用样例 1 自查：输出第一行必须是阻力最大的 3 号。

**错误 4：内层循环边界写错**

```c
for (j = 0; j < n - i; j++)          /* 错：j+1 会越界到 a[n] */
for (j = 0; j < n - 1 - i; j++)      /* 对：最后一轮只剩 1 个未排元素 */
```

越界读写 `a[n]` 不一定立刻报错，却可能破坏相邻内存，是排序类题目最难查的隐患。

## 七、与综合实验的衔接

实验 C7 的"载荷排行榜"模块与本练习几乎同构：把排序关键字从阻力换成质量（任务要点中的"按质量排序"），只需把比较式改为 `a[j].mass < a[j+1].mass`，其余代码一行不改；实验 C9 的"压力热点排序"同样如此。练习 04 将在结构体数组上做**查找**——按编号定位某块冰的完整记录，进一步体会"整条记录"作为基本操作单位的好处。
