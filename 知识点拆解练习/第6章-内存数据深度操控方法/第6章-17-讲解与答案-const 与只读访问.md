## 二、预备知识：`const` 修饰指针的三种写法（零基础阅读）

### 1. `const` 的本义：只读

`const` 是"constant（常量）"的缩写，加在变量前表示"这个量不能被修改"。它最大的价值不是"省内存"，而是**让编译器替你把关**：一旦有人试图改动它，编译阶段就会报错，把错误消灭在运行之前。

### 2. 修饰指针时，`const` 的位置决定了"锁住谁"

指针有两个可改的东西：**指针自己**（指向谁）和**它指向的内容**（`*p` 里的值）。`const` 放在 `*` 的左边还是右边，决定锁住哪一个：

```
   (1) const double *p;        /* 指向常量的指针：*p 只读，p 本身可改（可改指向别处） */
       double const *p;        /* 与上一行完全等价 */

   (2) double * const p = &x;  /* 常量指针：p 本身只读（一旦初始化不能指向别处），*p 可改 */

   (3) const double * const p = &x;  /* 两者都只读：*p 和 p 都不许改 */
```

记忆口诀：**`const` 紧挨着 `*` 的右边（`* const`），锁的是指针自己；`const` 在 `*` 左边（`const double *`），锁的是所指内容。** 从右往左读也行：`* const p` 读作"p 是常量指针"。

### 3. 本题用的是第 (1) 种

形参 `const double *a` 的意思是：**"我不改动你传给我的数据，只借来看看。"** 这是一种接口契约。函数体里只要出现

```c
a[i] = 0.0;      /* 或 *(a + i) = 0.0; */
```

编译器立刻报错：`assignment of read-only location`（对只读位置的赋值）。**错误在编译期被拦下，而不是在运行时破坏数据**——这正是 `const` 最实战的价值。

### 4. 传参的方向性：加锁安全，解锁危险

```
   double *a  ──传给──▶  const double *参数     允许（加锁，只读更安全）
   const double *b ──传给──▶  double *参数      不允许（要去掉锁，企图改动只读数据）
```

把普通指针传给 `const` 形参是"升级为更严格的约束"，安全；反过来要"丢弃 const 限定符"，编译器会给出警告或错误。这也解释了为什么**只读函数一律把形参写成 `const`**：它对调用者零要求，谁来都能传。

### 5. 一个必须澄清的边界

`const` 只约束"**通过这个指针**"不得修改，并不会把数据本身锁死。如果还有另一个非 `const` 指针指向同一块内存，通过它照样能改。所以 `const` 是"纪律"而非"保险箱"——但它足以防止绝大多数的无心之失。

## 三、解题思路

1. **定接口**：`double sum_readonly(const double *a, int n);`——返回求和值，形参加 `const` 表明只读；
2. **定算法**：循环 `sum += a[i];`，全程不写数组；
3. **定调用**：`sum = sum_readonly(a, n);`（`double *` 传给 `const double *` 合法）；
4. **定验证**：调用后重新打印数组，肉眼确认与输入一致；
5. **定格式**：`sum` 保留 4 位，数组元素保留 2 位。

## 四、参考代码

```c
#include <stdio.h>

/* 只读求和：const 承诺"绝不通过 a 修改元素" */
double sum_readonly(const double *a, int n)
{
    double sum = 0.0;
    int i;

    for (i = 0; i < n; i++)
        sum += a[i];        /* 只读 */

    /* a[i] = 0.0;  若写这一行，编译会直接报错：
       assignment of read-only location —— 这正是 const 在起作用 */

    return sum;
}

int main(void)
{
    double a[50];           /* 测点压力，kPa */
    int n, i;
    double sum;

    scanf("%d", &n);
    for (i = 0; i < n; i++)
        scanf("%lf", &a[i]);

    sum = sum_readonly(a, n);   /* double * 可安全传给 const double * */

    printf("sum = %.4f\n", sum);

    /* 重新打印原数组，验证数据未被函数改动 */
    for (i = 0; i < n; i++)
        printf("%.2f%c", a[i], i == n - 1 ? '\n' : ' ');

    return 0;
}
```

## 五、运行验证

| 输入 | 手算过程 | 程序输出 |
|---|---|---|
| 3 / 101.5 102.3 99.8 | 和 = 101.5+102.3+99.8 = 303.6 | `sum = 303.6000`；`101.50 102.30 99.80` ✓ |
| 4 / 1 2 3 4 | 和 = 10 | `sum = 10.0000`；`1.00 2.00 3.00 4.00` ✓ |

> 验证要点：第二行打印的数组与输入完全相同，证明 `sum_readonly` 只做了读取，没有改动任何元素。

## 六、常见错误与讲解

**错误 1：在 `const` 指针上写数据**

```c
double sum_readonly(const double *a, int n) {
    for (i = 0; i < n; i++) { sum += a[i]; a[i] = 0; }   /* 错：编译报错 */
}
```
这不是"陷阱"而是"保护"：编译器替你发现了越权修改。如果确实要改数组，就别给形参加 `const`。

**错误 2：混淆 `const double *p` 与 `double * const p`**

```c
const double *p;        /* *p 只读；p 可改（可指向别处） */
double * const p = &x;  /* p 只读（不能再指向别处）；*p 可改 */
```
写错位置，锁的对象就完全不同。判断方法：看 `const` 相对 `*` 的位置。

**错误 3：把 `const` 指针传给非 `const` 形参**

```c
void f(double *a);          /* 形参要能改 */
const double *b = ...;
f(b);                       /* 错：丢弃 const 限定符，编译器报错/警告 */
```
若 `f` 确实不需要改，就把 `f` 的形参也写成 `const double *`，让约束自洽。

**错误 4：误以为 `const` 能把数据彻底锁死**

```c
const double *p = a;   /* 锁住的是"通过 p"的写操作 */
a[0] = 99;             /* 通过原来的名字 a 依然能改 */
```
`const` 是给某个访问路径加锁，不是给整块内存上封印。
