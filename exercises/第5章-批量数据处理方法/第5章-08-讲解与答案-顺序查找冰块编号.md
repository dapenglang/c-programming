## 二、预备知识：顺序查找的基本原理（零基础阅读）

### 1. 问题是怎么来的

给定一个数组和一个目标值 `key`，问：**`key` 在不在数组里？在第几位？** 这是数据处理中最频繁的操作之一——查记录、查编号、查配置项，背后都是查找。查找算法的代价以**比较次数**计算：比较一次，花一份时间。

### 2. 顺序查找：最朴素也最通用的方案

数据没有任何排列规律时，唯一的办法就是**从第 1 个开始，一个一个比过去**：

- 第 1 个是 `key` 吗？不是，看第 2 个；
- 第 2 个是吗？不是，看第 3 个；
- ……要么某一步命中（找到），要么全部比完都不命中（未找到）。

这就是顺序查找（线性查找）。它的优点是**不讲条件**：数组乱序、无序、什么分布都行；缺点是**慢**：$n$ 个数据平均要比 $n/2$ 次，最坏要比 $n$ 次。100 个数据尚可接受，100 万个就难以忍受——慢的根治方案要等数组有序后用二分查找（练习 09）。

### 3. 两种出口怎么处理

顺序查找有两种结局：**命中**与**扫完未命中**。把输出语句直接写进循环会在"未命中"时无处说话，所以标准写法是**标志变量 + 循环外分支**：

```c
int found = 0;              /* 0 表示还没找到 */
for (i = 0; i < n; i++)
    if (a[i] == key) { found = 1; break; }
if (found) ... 找到的输出 ...
else       ... 未找到的输出 ...
```

标志变量把"查找"与"汇报"两个阶段分开：循环只负责找，`if` 只负责说。命中时的 `break` 让比较在最短路径上停止——找到位置就不再白比。

### 4. 位置如何计算

命中发生在下标 `i` 处，工程报表按"第几个"报，输出 `i + 1`。例如样例 1 中 2090 存放在 `a[4]`，输出"第 5 个"。

### 5. 比较次数清单（样例 1）

`key = 2090`，数组 `2101 2085 2103 2077 2090 …`：

| 比较次序 | a[i] | 是否命中 |
|---|---|---|
| 1 | 2101 | 否 |
| 2 | 2085 | 否 |
| 3 | 2103 | 否 |
| 4 | 2077 | 否 |
| 5 | 2090 | **是，break** |

共比较 5 次。若 `key = 2100`（样例 2），要比满 8 次才宣布未找到——**最坏情况总是发生在未命中或命中末尾**。

## 三、解题思路

1. 读入 $n$、数组、`key`；
2. 初始化标志变量 `found = 0` 与位置变量 `pos = -1`；
3. 顺序扫描：命中则置 `found = 1`、`pos = i` 并 `break`；
4. 循环外按 `found` 分支输出：找到报 `pos + 1`，否则报未找到。

## 四、参考代码

```c
#include <stdio.h>

int main(void)
{
    int id[100];      /* 冰块编号数组 */
    int n, key;       /* n 为冰块数，key 为待查编号 */
    int i, pos, found;

    scanf("%d", &n);
    for (i = 0; i < n; i++)
        scanf("%d", &id[i]);
    scanf("%d", &key);

    /* 顺序查找：从下标 0 逐个比对，命中即停 */
    found = 0;        /* 标志：0 = 未找到，1 = 已找到 */
    pos = -1;
    for (i = 0; i < n; i++)
        if (id[i] == key) {
            found = 1;
            pos = i;
            break;
        }

    /* 循环外统一汇报两种结局 */
    if (found)
        printf("编号 %d 是第 %d 个冰块\n", key, pos + 1);
    else
        printf("编号 %d 未找到\n", key);

    return 0;
}
```

## 五、运行验证

**样例 1**（key = 2090）：

| i | id[i] | id[i] == 2090? | 动作 |
|---|---|---|---|
| 0 | 2101 | 否 | 继续 |
| 1 | 2085 | 否 | 继续 |
| 2 | 2103 | 否 | 继续 |
| 3 | 2077 | 否 | 继续 |
| 4 | 2090 | 是 | found=1, pos=4, break |

输出 `编号 2090 是第 5 个冰块`，与样例一致。

**样例 2**（key = 2100）：8 次比较全部不命中，`found` 保持 0，输出 `编号 2100 未找到`，与样例一致。

**边界检查**：`key` 为第 1 个（2101）时比较 1 次即输出"第 1 个"；`key` 为最后一个（2088）时比较 8 次输出"第 8 个"；程序对首、尾两个极端位置均正确。

## 六、常见错误与讲解

**错误 1：把 `==` 写成 `=`**

```c
if (id[i] = key)   /* 错：赋值表达式值恒真，第一个元素就被判"找到" */
if (id[i] == key)  /* 对：相等比较 */
```

这是 C 语言最古老的陷阱之一：赋值表达式的值就是所赋的值，非零即真，编译器往往只给一个警告。

**错误 2：输出写在循环里，未找到无从处理**

```c
for (i = 0; i < n; i++)
    if (id[i] == key) printf("...第 %d 个...", i + 1);
printf("未找到\n");   /* 错：找到时也会跟一行"未找到" */
```

必须用标志变量把两种结局统一到循环外处理。

**错误 3：位置忘记 +1**

```c
printf("...第 %d 个...", pos);      /* 错：报的是下标 4 */
printf("...第 %d 个...", pos + 1);  /* 对：报的是第 5 个 */
```

**错误 4：break 后误以为循环变量还能用（概念性）**

```c
/* 有人用 for 结束后的 i 判断是否找到：i == n 表示未找到。
   能用但易错：忘写 break 时 i 恒为 n，"找到"也误报"未找到"。
   显式标志变量 found 更清晰、更不易错。 */
```
