## 二、预备知识：贪心枚举的基本原理（零基础阅读）

### 1. 问题是怎么来的

一根 `L = 29` 米的板材，切成 A 料（每段 7 米）和 B 料（每段 4 米），希望**总段数最多**。切法有很多种——A 料切几段？B 料切几段？切完必须**正好用完**（本题不考虑余料，余料必须为 0）。

把每种"A 料段数"都试一遍当然可以，但有一个更聪明的顺序：**优先多用 A 料**。因为 A 料长，每段"吃掉"更多板材，看起来浪费；直觉上"尽量多用长的"未必最优，但**从最多往下试、第一个恰好切完的方案**，就是枚举顺序下段数最多的方案——这就是"贪心枚举"：按从优到劣的顺序试，找到第一个可行解就停。综合实验 A9 的矩形板材下料正是把这一思想用在二维"矩形选规格"上。

### 2. 公式推导

设 A 料切 $x$ 段，则余料 $r = L - x \cdot a$。方案可行的条件是余料恰为 B 料长度的整数倍：

$$r \bmod b = 0, \qquad y = r / b \ (\text{B 料段数})$$

$x$ 的取值范围：$0 \le x \le \lfloor L/a \rfloor$（A 料段数不能超过"全长除以段长"的整数部分）。

**贪心序**：按 $x = \lfloor L/a \rfloor, \lfloor L/a \rfloor - 1, \ldots, 0$ 的顺序检查，第一个满足 $r \bmod b = 0$ 的 $x$ 即为所求。总段数

$$z = x + y = x + \frac{L - x a}{b}$$

把 $x$ 换成 $x-1$ 时，$z$ 的变化量为 $-1 + a/b$；即便 $a/b$ 是整数（如 $a=8, b=4$，$-1+2=+1$），从小 $x$ 侧补救也至多持平——因此**从大到小枚举取到的首个可行解，段数不会劣于任何更小的 $x$**，贪心成立。

### 3. 代入本例

样例 1（L=29, a=7, b=4），枚举过程：

| x（A 料段数） | r = 29 − 7x | r % 4 | 结论 |
|---|---|---|---|
| 4 | 29 − 28 = 1 | 1 % 4 = 1 ≠ 0 | ✗ |
| 3 | 29 − 21 = 8 | 8 % 4 = 0 | ✓ 停！y = 8/4 = 2 |

方案：A 料 3 段 + B 料 2 段 = **5 段**，余料 8 − 8 = 0 ✓。验证总用料：3×7 + 2×4 = 21 + 8 = 29 ✓。

样例 3（L=7, a=5, b=3）：

| x | r | r % 3 | 结论 |
|---|---|---|---|
| 1 | 2 | 2 ≠ 0 | ✗ |
| 0 | 7 | 7 % 3 = 1 ≠ 0 | ✗ |

枚举完毕仍无可行解 → 输出"无可行下料方案"。

样例 2（L=13, a=5, b=3）：x=2 → r=3, 3%3=0 → A 料 2 段 + B 料 1 段 = 3 段 ✓（先试 x=2 是因为 13/5 = 2）。

### 4. 编程翻译

| 数学/算法动作 | C 语言翻译 |
|---|---|
| $x$ 从 $\lfloor L/a \rfloor$ 递减到 0 | `for (x = L / a; x >= 0; x--)` |
| $r = L - xa$ | `r = L - x * a;` |
| $r \bmod b = 0$？ | `if (r % b == 0)` |
| 找到即停 | `break;` |
| 是否找到 | 标记变量 `found` |

> **贪心枚举 = 循环 + 整除判定 + break**：不需要数组存方案，也不需要函数——三个样例的全部计算都在几个整型变量里完成。这正是第 3 章"控制流"的威力：只靠顺序、分支、循环三种结构就能表达搜索算法。

## 三、解题思路

1. **读入** `L a b`；
2. **递减枚举** `x` 从 `L / a` 到 0，每个 `x` 算 `r = L - x*a`；
3. `r % b == 0` 则记下 `y = r / b`，`found = 1`，`break`；
4. 循环后按 `found` 输出方案或"无可行下料方案"。

## 四、参考代码

```c
#include <stdio.h>

int main(void)
{
    int L, a, b;            /* 板材长、A 料段长、B 料段长 */
    int x, y, r;            /* A 料段数、B 料段数、余料 */
    int found = 0;          /* 标记：是否找到可行方案 */

    scanf("%d %d %d", &L, &a, &b);

    for (x = L / a; x >= 0; x--) {      /* 贪心：A 料段数从多到少枚举 */
        r = L - x * a;                  /* 切完 A 料后的余料 */
        if (r % b == 0) {               /* 余料恰为 B 料长度整数倍 → 可行 */
            y = r / b;
            found = 1;
            break;                      /* 第一个可行解即最优解 */
        }
    }

    if (found) {
        printf("最优方案：A 料 %d 段 + B 料 %d 段 = 共 %d 段，余料 0 m\n",
               x, y, x + y);
    } else {
        printf("无可行下料方案\n");
    }
    return 0;
}
```

（说明：`break` 跳出后 `x`、`y` 保留的正是可行方案的值，可直接输出。）

## 五、运行验证

**第一次运行**（样例 1）：

输入：
```
29 7 4
```
输出：
```
最优方案：A 料 3 段 + B 料 2 段 = 共 5 段，余料 0 m
```
核对：3×7+2×4 = 29 = L，总段数 5，与手工枚举表一致。✓

**第二次运行**（样例 2）：

输入：
```
13 5 3
```
输出：
```
最优方案：A 料 2 段 + B 料 1 段 = 共 3 段，余料 0 m
```
核对：2×5+1×3 = 13 ✓。✓

**第三次运行**（样例 3，无解）：

输入：
```
7 5 3
```
输出：
```
无可行下料方案
```
✓ x=1、x=0 均不可行，`found` 保持 0。

**反例验证**：若把枚举方向改成从小到大（`x = 0` 起），样例 1 会先碰到 x=0 → r=29，29%4=1 不行；x=1 → r=22，22%4=2 不行；x=2 → r=15，15%4=3 不行；x=3 → r=8 可行——本例侥幸仍得 x=3，但构造 L=24, a=8, b=4 时从小到大得 x=0（B 料 6 段共 6 段），从大到小得 x=2（A 料 2 段 + B 料 2 段共 4 段）——**方向错了答案就不同**，说明枚举顺序本身就是算法的一部分。

## 六、常见错误与讲解

**错误 1：枚举起点算错**

```c
for (x = L / a - 1; x >= 0; x--)   /* 错：漏掉了"正好切 L/a 段"的情形 */
for (x = L / a; x >= 0; x--)       /* 对：从最多可能的段数开始 */
```

**错误 2：忘写 `x >= 0` 的下界（x 还要试 0 段 A 料的情形）**

```c
for (x = L / a; x > 0; x--)   /* 错：x = 0（全切 B 料）的方案被漏掉，样例 3 类型的问题会误判 */
```

**错误 3：整除方向颠倒**

```c
if (x % b == 0)      /* 错：判的是 A 料段数能否被 b 整除 */
if (r % b == 0)      /* 对：判余料是否为 B 料长度的整数倍 */
```

**错误 4：找到后不 `break`，输出最后一次枚举的结果**

```c
if (r % b == 0) { y = r / b; found = 1; }   /* 错：少了 break，循环继续跑，
                                               最后 x=0 的方案覆盖了最优方案 */
```

没有 `break` 时 `x`、`y` 会被后续枚举覆盖成最小 `x` 的方案（若它可行），贪心失效。

**错误 5：无解时输出垃圾值**

```c
printf("最优方案：A 料 %d 段 ...", x, y);   /* 错：未判 found，无解时 y 未初始化 */
```

必须用 `found` 标记分流两种输出。

## 七、与综合实验的衔接

- 实验 **A9（基于贪心枚举的矩形板材下料优化系统）**中，"下料方案枚举"是本题的二维扩展：矩形板材上枚举 A 规格矩形的**行列数**，检查剩余区域能否放下 B 规格，贪心序同样是"从大规格、多数量往小试"；本题的一维模型去掉了行列嵌套，只保留"枚举 + 整除判定 + break"的核心骨架；
- 与第 3 章其他内容衔接：穷举"鸡兔同笼""百钱百鸡"用的是**全枚举 + 条件筛选**（所有解都列出来），本题的贪心枚举则多了"**按优先级排序 + 找到即停**"两个要素——它比全枚举快，但前提是你能说清楚"为什么第一个可行解就是最优"。这个"说清楚"的能力，正是实验 A9 报告里"算法设计说明"要考查的。
