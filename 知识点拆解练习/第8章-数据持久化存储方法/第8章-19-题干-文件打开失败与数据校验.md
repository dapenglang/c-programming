# 第 8 章 练习 19　文件打开失败与数据校验

**对应章节**：8 数据持久化存储方法（8.2 文件型指针、8.3 文件的打开与关闭、8.4 文件的读写）

**场景来源**：综合实验 C6《冰区船舶与冰块碰撞模拟系统》（水声学院）——本练习是该实验中"冰块参数文件加载与容错检查"环节的实现。

**建议用时**：30～40 分钟

## 一、应用场景

实验 C6 的模拟程序每次启动都要从 `ice_params.txt` 加载冰块参数。现场运行时意外时有发生：文件被误删、路径不对、U 盘没插好——如果程序拿到一个失败的 fopen 还继续往下跑，轻则输出乱码，重则崩溃；另外，数据文件本身也可能被录错：质量录成负数、速度录得离谱，拿去模拟会得到荒谬结果。工程上把这两道防线合称**容错**：先检查文件能不能打开，再检查每条数据合不合理。本练习编写一个带完整容错的参数加载器。

## 二、任务要求

编写完整程序 `loadcheck.c`：

1. 以 `"r"` 方式打开 `ice_params.txt`，**检查 fopen 返回值**：若为 NULL，输出 `错误：无法打开 ice_params.txt` 并返回 1；
2. **数据文件格式约定**：每行三列、空格分隔——冰块编号（3 字符）、质量 $m$（吨，实数）、速度 $v$（m/s，实数）。样例数据行：`B01 12.5 0.8`；
3. 用循环 `fscanf(fin, "%s %lf %lf", ...)`（返回值等于 3 为条件）逐条读入，**每条记录立即校验**：质量必须大于 0（吨），速度必须在 $[0, 5]$（m/s）内。合法记录写入 `ice_valid.txt`（格式与输入相同），非法记录不写入，并在屏幕上指出该编号及原因（质量必须为正 / 速度超出范围）；
4. 统计并输出：总记录数、合法条数、非法条数；
5. 关闭文件。注意：合法记录若一条都没有，也要在屏幕上明确说明。

## 三、输入输出格式

**输入文件**：`ice_params.txt`（空格分隔，若干行）。

**输出文件**：`ice_valid.txt`（只含合法记录，格式与输入相同）。

**屏幕输出**：每条非法记录一行，格式为 `编号 X 非法（原因）`，其中原因为 `质量必须为正` 或 `速度超出范围`；最后输出一行统计 `共 M 条，合法 N 条，非法 K 条`。

## 四、样例

**输入文件 ice_params.txt 的内容**：

```
B01 12.5 0.8
B02 -3.0 1.1
B03 9.6 0.5
B04 15.0 6.2
```

**程序运行后 ice_valid.txt 的内容**：

```
B01 12.5 0.8
B03 9.6 0.5
```

**屏幕输出**：

```
B02 非法（质量必须为正）
B04 非法（速度超出范围）
共 4 条，合法 2 条，非法 2 条
```

**附加测试**：把 ice_params.txt 改名后再运行程序，屏幕输出：

```
错误：无法打开 ice_params.txt
```

## 五、提示

- fopen 失败返回 NULL，检查语句要紧跟 fopen：`if (fin == NULL) { ...; return 1; }`——对 NULL 指针调用 fscanf 是未定义行为；
- 一条记录可能同时不满足两个条件（如质量为负且速度越界），校验时按"先查质量、再查速度"的顺序用 if-else 串联，保证一条记录只报一个原因；
- 合法性判断是**区间判断**：速度条件写成 `v >= 0 && v <= 5`，注意边界值 0 和 5 都算合法；
- 统计三个量：总条数每轮加一，合法/非法在各自分支里加一。

**完成本练习后你将具备的能力**：树立"打开必检查、数据必校验"的防御性编程习惯，掌握 fopen 失败、EOF、数据越界三类异常的统一处理套路——实验 C6 及后续所有实验的文件加载模块都必须有这道保险。
