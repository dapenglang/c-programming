# 题目 D1：基于指数衰减模型的放射性核素活度计算系统

**适用学院**：核学院（15 系）　**组容量**：本题目最多 2 组选择

## 一、系统/算法说明

本系统是一套命令行放射性核素活度计算工具，围绕"放射性核素活度随时间按指数规律衰减"这一核物理基本规律展开。系统读入若干核素的名称、半衰期与初始活度，能够计算任意时刻的剩余活度、给出等间隔时间序列活度表、计算多种核素混合源的总活度，并能反解"活度衰减到某安全阈值所需等待的储存时间"。

放射性核素活度随时间的变化是核工程最基础的计算。如果不解决它，放射性废物暂存库的设计将失去依据——无法判断一批废物需要封存多久才能降到可转运、可回收或可解控的水平；辐射防护中的分区管理也无从谈起，因为场区剂量率的源头活度会随着时间下降，作业窗口的开放时间必须据此推算。核电站换料检修时，一回路水中的活化腐蚀产物活度决定了大修窗口的等待时长；医用同位素（如钴-60、碘-131）的生产与临床使用，必须精确知道出厂到注射这段时间内活度衰减了多少，才能保证给患者的实际剂量准确；辐射防护设计中的"安全距离"与"屏蔽厚度"估算同样以源活度为起点。

本系统支撑的关键场景包括：① 核电站换料检修计划的等待时间评估；② 医用同位素生产与配送的活度标定；③ 放射性废物暂存与解控时间评估；④ 辐射防护分区与作业窗口设计；⑤ 核设施退役拆除阶段的源项衰变估算。系统让学生在大一阶段就能用 C 语言把"指数衰减"这类专业公式变成可运行、可查表的工具，为后续《核物理》《辐射防护》《反应堆物理》等课程建立直观基础。本题目与核工程与核技术专业"核物理基础"方向直接相关，训练学生把物理规律转化为"数据读入—算法实现—数据输出"完整程序工程的能力。

## 二、题目任务与专业关联

本题目要求学生实现一个完整的放射性核素活度计算系统：从文本文件读入核素参数表与储存阈值配置，实现指数衰减活度计算函数，按用户给定时刻或等间隔时间序列批量计算活度，对多种核素做混合源总活度累加，并用二分法反解达到储存安全阈值所需的时间，最后生成活度衰减曲线字符画、结果数据文件与储存建议报表。

专业关联上，本题目复现了核电站大修源项评估、医用同位素活度标定、放射性废物暂存管理三类真实业务的核心计算。学生在此过程中将掌握课程中的函数、数组、结构体、文件读写、循环与选择结构，并第一次把专业公式写成可复用函数，理解"一个物理模型如何变成一套程序"。

## 三、数据来源与格式

- **数据文件格式**：核素参数表采用纯文本格式，首行为标题说明，其后每行一条核素记录，字段以空格分隔。字段依次为：核素名（无空格字符串）、半衰期 T（单位：天，正实数）、初始活度 A0（单位：贝可 Bq，正实数）。配置文件 `decay_config.txt` 另给出储存安全阈值（Bq）与时间序列步长（天）。

```
# nuclide_name   half_life_day   activity0_Bq
Co-60            1925.0          3.70e12
Cs-137           11000.0         1.20e13
I-131            8.02            5.00e11
Mo-99            2.75            8.00e11
Am-241           157800.0        4.00e10
```

```
# storage_safe_Bq  time_step_day  time_span_day
1.0e8               30.0           3000.0
```

- **仿真数据生成规则**：
  - 核素名：取 3～5 个字母或"元素符号-质量数"字符串，长度 ≤ 15，无空格，如 `Co-60`、`Sr-90`。
  - 半衰期 T：单位天，取值范围 1.0～200000.0，按对数均匀分布生成（保证长寿命与短寿命核素都有），即先均匀抽取 lgT∈[0, 5.3] 再取 10 的幂。
  - 初始活度 A0：单位 Bq，取值范围 1.0e9～1.0e14，按对数均匀分布生成，lgA0∈[9, 14]。
  - 储存安全阈值：单位 Bq，取值范围 1.0e6～1.0e9，由配置给定，全表共用。
  - 时间序列步长：单位天，取值范围 1.0～90.0，时间跨度 ≤ 200 步，保证表格可读。
  - **异常值注入方式**：由教师提供的生成程序人为注入三类错误。其一，半衰期字段填 0 或负数（如 `-5.0`），需在校验模块中识别并剔除；其二，活度字段填入非数字串（如 `abc` 或 `1.2e999` 溢出值），读入时应能捕获；其三，核素名重复或含空格导致 `fscanf` 错位。校验模块需输出"行号—异常类型—处理动作"清单。

- **真实数据集（如有）**：真实核素半衰期可参考国际原子能机构 IAEA 的《Table of Isotopes》与 ENSDF 评价核结构数据库（https://www.nndc.bnl.gov/ensdf/），以及日本原子力研究开发机构提供的 Nuclide Chart。学生**无需下载**真实数据文件，课程提供与上述字段含义对应的简化仿真数据表；表中"半衰期"对应评价数据库中的 half-life 字段，"初始活度"对应工程任务给定的源项活度。

## 四、数据结构设计

```c
/* ===== 常量定义 ===== */
#define MAX_NUCLIDE      30      /* 最多核素数量 */
#define MAX_NAME_LEN     16      /* 核素名最大长度（含结束符） */
#define MAX_STEP        200      /* 时间序列最大步数 */

/* ===== 核素参数结构体 ===== */
struct Nuclide {
    char  name[MAX_NAME_LEN];    /* 核素名，如 "Co-60" */
    double halfLife;             /* 半衰期 T，单位：天，> 0 */
    double act0;                 /* 初始活度 A0，单位：Bq，> 0 */
    double lambda;               /* 衰变常数 λ = ln2 / T，1/天（由 T 换算） */
    int    valid;                /* 有效标志：1 有效，0 已判为异常剔除 */
};

/* ===== 时间序列采样点 ===== */
struct TimeSample {
    double t;                    /* 时刻，单位：天 */
    double act;                  /* 该时刻总活度，单位：Bq */
};

/* ===== 全局数据区 ===== */
struct Nuclide   g_nuclide[MAX_NUCLIDE];   /* 核素表 */
int              g_nuclideCount;           /* 有效核素条数 */
double           g_safeTh;                 /* 储存安全阈值，单位：Bq */
double           g_step;                   /* 时间序列步长，单位：天 */
double           g_span;                   /* 时间序列总跨度，单位：天 */
struct TimeSample g_series[MAX_STEP];      /* 混合源时间序列 */
int              g_stepCount;              /* 序列实际点数 */

/* ===== 处理日志（供报表模块使用） ===== */
struct LogItem {
    char  op[24];                /* 操作名，如 "DUMP_TIME_SERIES" */
    char  detail[64];            /* 参数与关键结果摘要 */
};
struct LogItem g_log[MAX_NUCLIDE * 4];
int            g_logCount;     /* 已记录日志条数 */
```

辅助说明：核素表用结构体数组组织（课程 7.1/7.2），时间序列用一维结构体数组缓冲（课程 5.1），混合源累加逐点求和（课程 3.3）。衰变常数 λ 在核素校验通过后由 `λ = 0.693147 / T` 一次性换算并存回结构体，避免重复计算。

## 五、功能模块拆解（共 11 个模块）

### 第一部分：数据读入（3 个模块）

**M1 核素参数表读入模块**（源文件 `NuclideIO.c`）

- 功能简介：打开核素参数文本文件，跳过首行标题，用循环 + `fscanf` 逐行读入核素名、半衰期与初始活度，填充全局核素表，记录读入条数；文件不存在时给出明确提示。
- 输入：文件路径（菜单输入，默认 `nuclides.txt`）。
- 输出：填充后的 `g_nuclide[]` 与 `g_nuclideCount`；返回成功/失败标志。

**M2 核素参数校验与衰变常数换算模块**（源文件 `NuclideCheck.c`）

- 功能简介：逐条检查半衰期是否为正、活度是否为正且在 [1.0e6, 1.0e15] 内、核素名是否重复；对异常记录置 `valid=0` 并生成"行号—异常类型—处理动作"清单；对有效记录换算衰变常数 λ 并调用 `logUint` 排序检查。
- 输入：`g_nuclide[]`、`g_nuclideCount`。
- 输出：屏幕校验报告；修正后的 `g_nuclide[]`、有效条数。

**M3 阈值与时间序列配置读入模块**（源文件 `NuclideIO.c`）

- 功能简介：读入配置文件中的储存安全阈值、时间序列步长与总跨度；做范围检查（阈值 > 0、步长 > 0、跨度 ≤ 200 步），越界时给出提示并取默认值。
- 输入：配置文件路径（默认 `decay_config.txt`）。
- 输出：`g_safeTh`、`g_step`、`g_span`；屏幕确认信息。

### 第二部分：算法实现（4 个模块）

**M4 活度计算函数模块**（源文件 `Decay.c`）

- 功能简介：实现活度衰减函数 `A(t) = A0 · exp(-λ·t)`，其中 `λ = ln2 / T`；提供底层函数 `double decayAct(double a0, double lambda, double t)` 与按核素下标调用的封装 `double nuclideAct(int idx, double t)`。同时提供对数底 2 的写法作对照。
- 输入：核素下标或 `(A0, λ, t)` 参数、时刻 t（天）。
- 输出：返回该时刻活度值（Bq）；非法输入（t < 0 或无效核素）返回 -1.0 并提示。

**M5 多核素混合累加模块**（源文件 `Decay.c`）

- 功能简介：遍历全部有效核素，在同一时刻 t 下逐条累加活度，得到混合源总活度；对活度已低于 1.0e-6 Bq 的核素跳过并在结果中标注"已可忽略"。
- 输入：`g_nuclide[]`、时刻 t。
- 输出：返回混合源总活度（Bq）；屏幕打印各核素分量与总量。

**M6 时间序列批量计算模块**（源文件 `Decay.c`）

- 功能简介：从 t=0 起按步长 `g_step` 推进至 `g_span`，对每个时刻调用 M5 求混合源总活度，填入全局序列 `g_series[]`；点数超过 `MAX_STEP` 时自动截断并提示。
- 输入：`g_step`、`g_span`、`g_nuclide[]`。
- 输出：`g_series[]` 与 `g_stepCount`；屏幕进度摘要。

**M7 达标储存时间反解模块**（源文件 `Decay.c`）

- 功能简介：用二分法对混合源总活度函数在区间 [0, Tmax] 上求"总活度 = 安全阈值"的根，得到达标储存时间。初始上限取最长半衰期的 20 倍并逐步翻倍直到总活度低于阈值；迭代到区间宽度小于 1e-3 天。
- 输入：`g_safeTh`、`g_nuclide[]`。
- 输出：达标时间（天）及对应时刻的总活度；屏幕打印每次二分的区间与中点值。

### 第三部分：数据输出（4 个模块）

**M8 活度衰减曲线字符画模块**（源文件 `DecayPlot.c`）

- 功能简介：取 `g_series[]` 中部分点（每隔若干点抽样），以字符柱状图按对数刻度绘制总活度随时间的衰减曲线，横轴标注时刻、纵轴标注数量级，让衰减趋势"看得见"。
- 输入：`g_series[]`、`g_stepCount`。
- 输出：屏幕字符曲线图。

**M9 参数实验模块**（源文件 `Decay.c`）

- 功能简介：对同一组核素分别按给定倍率（如 0.5/1.0/2.0）整体缩放半衰期，或逐个只保留单一核素，重跑 M6 时间序列与 M7 二分反解，输出"半衰期倍率—达标时间"对照表，观察半衰期对储存年限的影响。
- 输入：核素表、半衰期倍率列表。
- 输出：屏幕参数实验对照表。

**M10 结果文件输出模块**（源文件 `DecayIO.c`）

- 功能简介：把时间序列结果按"时刻—各核素分量—总活度"列写出到 `decay_result.csv`，首行写列名；同时把核素参数表（含换算后的 λ）写出到 `nuclides_out.txt` 便于核对。
- 输入：`g_nuclide[]`、`g_series[]`、`g_stepCount`。
- 输出：`decay_result.csv`、`nuclides_out.txt`；屏幕确认信息。

**M11 储存建议报表与主控菜单模块**（源文件 `Stu_main.c`）

- 功能简介：汇总各核素的达标等待时间与储存建议（按达标时间长短分"短期待处理/中期暂存/长期封存"三档），写入 `storage_advice.txt` 并在屏幕显示；主菜单用 `do-while + switch` 调度 M1～M10，用状态标记约束"必须先读入并校验参数才能计算"。
- 输入：用户菜单选项。
- 输出：`storage_advice.txt`；屏幕建议报表；调度各模块。

## 六、数据流与控制流

**控制流**：`main()` 进入菜单循环，先用状态标记 `g_loaded` 约束流程——未读入核素表时只允许执行 M1/M3；读入后依次可调用 M2 校验、M4～M7 计算、M8 曲线、M9 参数实验、M10～M11 输出。任何计算模块要求核素表中至少有一条 `valid=1` 的记录，否则提示先执行 M2。

**数据流**：

```
nuclides.txt ─► M1 读入 ─► g_nuclide[] ─► M2 校验/换算λ ─► 有效核素表
                                   │
decay_config.txt ─► M3 配置 ─► g_safeTh/g_step/g_span
                                   │
        ┌──────────────────────────┼───────────────────────────┐
        ▼                          ▼                           ▼
  M4 活度计算函数          M6 时间序列批量 ──► g_series[]  M7 二分反解达标时间
        │                          │                           │
        ▼                          ▼                           ▼
  M5 多核素混合累加 ────► M8 曲线字符画             M9 参数实验（半衰期对比）
                                                     │
                                   ┌─────────────────┴───────────────┐
                                   ▼                                 ▼
                            M10 结果文件输出              M11 储存建议报表与主控
```

所有模块之间只通过全局核素表、全局序列数组与函数参数交换数据，函数头部（接口）在编码前由全组书面约定。

## 十、选做扩展
