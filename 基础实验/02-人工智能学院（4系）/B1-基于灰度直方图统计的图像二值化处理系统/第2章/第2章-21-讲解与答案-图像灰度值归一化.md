## 二、预备知识：灰度值与归一化的基本原理（零基础阅读）

### 1. 问题是怎么来的

数字图像是由像素点排成的大网格。灰度图像中，每个像素只记录一个亮度数字，取值范围是 $0$ 到 $255$，共 $256$ 个等级：

- $0$ 表示纯黑，$255$ 表示纯白；
- 中间的数字表示逐渐变亮的灰色，例如 $128$ 大约是中性灰。

为什么偏偏是 $255$？因为计算机用 8 个二进制位（一个字节）存一个像素，8 位能表示 $2^8 = 256$ 个不同的值，编号正好是 $0$ 到 $255$。这属于"存储设备的自然选择"，我们记住结论即可。

### 2. 公式是怎么来的

后续处理时，我们希望把"绝对亮度"变成一个**比例**："这个像素处在从黑到白的百分之几位置？"。用当前灰度除以灰度满值即可：

$$
g_{norm} = \frac{g}{g_{max}} = \frac{g}{255}
$$

$g = 0$ 时得 $0.0$（纯黑），$g = 255$ 时得 $1.0$（纯白），$g = 128$ 时得约 $0.502$（略过一半）——这个比例与具体是多少个灰度等级无关，所以叫**归一化**（把量统一到 $0\sim1$）。

### 3. 用本例走一遍

取 $g = 128$：

$$
g_{norm} = \frac{128}{255} \approx 0.50196 \approx 0.5020
$$

再取 $g = 51$：

$$
g_{norm} = \frac{51}{255} = 0.2 = 0.2000
$$

两个结果都在 $0\sim1$ 之间，符合归一化的预期。

### 4. 编程时怎么用它

直接写一行赋值：

```c
double gn = g / 255.0;
```

**这里最容易错的是把 255 写成整数**。C 语言中，两个 `int` 相除执行的是**整数除法**：小数部分被直接丢掉。若写 `g / 255`，则 `128 / 255` 得 `0`，`51 / 255` 也得 `0`，全部结果为 $0$，程序"看起来能跑但结果全错"。只要把分母写成 `255.0`（或写成 `(double)g / 255`），编译器就会按实数除法计算。

> **这个思想在综合实验中反复出现**：B1 灰度归一化（$0\sim255 \to 0\sim1$）、B2 传感器信号归一化、B10 相似度百分比（$0\sim1 \to 0\sim100$），都是"用一个基准值把量变成比例"同一个套路。

## 三、解题思路

1. **确定常量**：灰度满值 $255$ 是图像的固定属性，定义为 `const double GMAX = 255.0`；
2. **确定变量**：读入的灰度 `g` 是整数用 `int`，归一化结果 `gn` 是实数用 `double`；
3. **套用公式**：`gn = g / GMAX;`（分母是 double，除法自动按实数进行）；
4. **输出**：题目要求保留 4 位小数，用 `%.4f`。

## 四、参考代码

```c
#include <stdio.h>

int main(void)
{
    const double GMAX = 255.0;   /* 8 位灰度图像的满值（纯白） */

    int g;        /* 输入：像素灰度值，0~255 的整数 */
    double gn;    /* 输出：归一化灰度，0~1 的实数 */

    /* 读入灰度值 */
    scanf("%d", &g);

    /* 归一化：分母写作 255.0，保证按实数除法计算 */
    gn = g / GMAX;

    /* 输出，保留 4 位小数 */
    printf("gray_norm = %.4f\n", gn);

    return 0;
}
```

## 五、运行验证

| 输入 | 手算过程 | 程序输出 |
|---|---|---|
| 128 | 128 / 255 = 0.50196… ≈ 0.5020 | `gray_norm = 0.5020` ✓ |
| 51 | 51 / 255 = 0.2 = 0.2000 | `gray_norm = 0.2000` ✓ |
| 0 | 0 / 255 = 0.0000（纯黑） | `gray_norm = 0.0000` ✓ |
| 255 | 255 / 255 = 1.0000（纯白） | `gray_norm = 1.0000` ✓ |

端点 $0$ 与 $255$ 得到 $0$ 和 $1$，说明公式使用正确。

## 六、常见错误与讲解

**错误 1：整数除法（最典型）**

```c
gn = g / 255;          /* 错：g 与 255 都是 int，128/255 = 0 */
gn = g / 255.0;        /* 对：分母是 double，按实数除 */
gn = (double)g / 255;  /* 对：先把 g 转成 double */
```

**错误 2：把归一化结果存成 int**

```c
int gn = g / 255.0;    /* 错：0.502 被截断成 0 */
double gn = g / 255.0; /* 对：结果必须是 double */
```

即便除法算对了，若用一个 `int` 去接结果，小数部分照样丢失。

**错误 3：scanf 忘记取地址符**

```c
scanf("%d", g);      /* 错：程序崩溃或读不进数据 */
scanf("%d", &g);     /* 对：scanf 需要变量的地址 */
```

当前阶段记住规则：**scanf 的每个参数前面都要加 `&`**。

**错误 4：格式符与类型不匹配**

```c
scanf("%lf", &g);         /* 错：g 是 int，应该用 %d */
printf("gray_norm = %d\n", gn);  /* 错：gn 是 double，应该用 %.4f */
```

`int` 对应 `%d`，`double` 对应 `%lf`（输入）与 `%f`（输出）。
