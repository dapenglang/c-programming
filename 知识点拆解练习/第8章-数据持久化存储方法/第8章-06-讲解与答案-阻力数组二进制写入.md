## 二、预备知识：文件读写的基本原理（零基础阅读）

### 1. 为什么需要文件

程序在内存里的数组"一停就没"，要长期保存就得写进文件。本题要存的是一个整数组，而且数据量大——这时就不能照搬前几题的"按文本一行一个数"。先弄清楚两种文件的区别，再决定用什么武器。

### 2. 文本文件与二进制文件的区别

- **文本文件**：文件里存的是"人看得懂的字符"。数 $12.5$ 存进去，实际写入的是字符 `'1' '2' '.' '5'` 共 4 个字节。好处是能直接打开看、方便交换；坏处是占空间、转换有开销（读写时要和字符串互转，还有精度误差）。
- **二进制文件**：文件里存的是"内存中数据的原始字节"。数 $12.5$ 存进去，写入的是这个 `double` 在内存里的 8 个字节，与内存中一模一样。好处是**紧凑、快、精度无损**；坏处是不能用记事本看懂。

对比一下就明白：5 个 `double` 用文本存大约要几十个字节，用二进制存恰好 $5 \times 8 = 40$ 字节。数据一多，差距就拉开了。所以工程上"大批量数值"几乎都用二进制保存。

### 3. 文件操作的标准四步曲

1. **声明文件指针**：`FILE *fp;`；
2. **打开文件**：`fp = fopen("文件名", "模式");`；
3. **读或写**：本题用 `fwrite` 写；
4. **关闭文件**：`fclose(fp);`。

**`fopen` 返回的 `FILE *` 是什么？** 它是这次文件访问的"编号牌"，指向系统建立的记录（文件在哪、当前进行到哪、是读还是写）；记录里的**文件位置指针**标明"现在写到第几个字节"，每写一段字节就自动后推。

**打开失败会怎样？** 磁盘写保护、目录不可写时 `fopen` 返回 `NULL`，不判空就用会崩溃，因此写完打开后**必须**判空：

```c
if (fp == NULL) { printf("无法创建 loads.bin\n"); return 1; }
```

### 4. 常用读写函数怎么选

| 函数 | 读/写单位 | 典型写法 | 适合场景 |
|---|---|---|---|
| `fwrite` | 写字节块 | `fwrite(a, sizeof(double), n, fp);` | 二进制文件、批量存数组 |
| `fread` | 读字节块 | `fread(a, sizeof(double), n, fp);` | 二进制文件、批量读回 |
| `fprintf` | 按格式写 | `fprintf(fp, "%.2f\n", v);` | 文本、人可读 |
| `fscanf` | 按格式读 | `fscanf(fp, "%lf", &v);` | 文本、按格式解析 |
| `fgets` | 读一整行 | `fgets(buf, sizeof(buf), fp);` | 文本、整行处理 |

`fwrite` 的四个参数含义：**① 数据从哪开始（地址）；② 一个元素占多少字节（`sizeof`）；③ 一共几个元素；④ 文件指针。** 写数组 `a` 的 $n$ 个元素，就是 `fwrite(a, sizeof(double), n, fp)`；返回成功写入的元素个数。

### 5. 用本题的数据走一遍文件指针

样例 1 输入 `n = 5`，数组为 `{12.5, 18.3, 9.75, 21.0, 15.5}`。`fopen("loads.bin", "wb")` 后位置指针在 0 字节处。`fwrite(&n, sizeof(int), 1, fp)` 把整数 5 的 4 个字节写进去，指针移到第 4 字节；`fwrite(a, sizeof(double), 5, fp)` 把 5 个 `double` 共 40 字节一次写进去，指针移到第 44 字节。此时 `ftell(fp)` 返回 44，正好是文件总大小。`fclose` 后文件定格为 44 字节。**`ftell` 返回的是"当前位置距离文件开头的字节数"，刚写完时它就等于文件总字节数。**

## 三、解题思路

1. **读入**：`scanf("%d", &n)`，再循环读入 $n$ 个 `double` 到数组 `a`；
2. **打开二进制文件**：`fp = fopen("loads.bin", "wb")`，判空；
3. **写整数**：`fwrite(&n, sizeof(int), 1, fp);`
4. **写数组**：`fwrite(a, sizeof(double), n, fp);`
5. **取大小并关闭**：`size = ftell(fp);` 再 `fclose(fp);`，最后输出提示。

## 四、参考代码

```c
#include <stdio.h>

int main(void)
{
    FILE *fp;                 /* 二进制文件指针 */
    int    n, i;              /* n 为数据个数 */
    double a[100];            /* 阻力数组，最多 100 个 */
    long   size;              /* 文件字节数 */

    scanf("%d", &n);          /* 读入个数 */
    for (i = 0; i < n; i++)
        scanf("%lf", &a[i]);  /* 读入 n 个阻力值 */

    /* 以"二进制写"模式打开文件 */
    fp = fopen("loads.bin", "wb");
    if (fp == NULL) {
        printf("无法创建文件 loads.bin\n");
        return 1;
    }

    fwrite(&n, sizeof(int), 1, fp);        /* 先写记录个数 n（4 字节） */
    fwrite(a, sizeof(double), n, fp);      /* 再一次性写入整个数组（n*8 字节） */

    size = ftell(fp);                      /* 当前位置即文件总字节数 */
    fclose(fp);                            /* 关闭文件，数据落盘 */

    printf("已写入 %d 个阻力值，文件共 %ld 字节\n", n, size);

    return 0;
}
```

## 五、运行验证

**样例 1：运行前** `loads.bin` 不存在（或内容无关，`"wb"` 会重建它）。

屏幕输入：
```
5
12.5 18.3 9.75 21.0 15.5
```
屏幕输出：
```
已写入 5 个阻力值，文件共 44 字节
```
**运行后** `loads.bin` 的逻辑内容：4 字节整数 `5`，随后依次是 `12.5`、`18.3`、`9.75`、`21.0`、`15.5` 各 8 字节，共 $4 + 5 \times 8 = 44$ 字节，与输出一致。

**样例 2：运行前** `loads.bin` 有上次的 44 字节内容（`"wb"` 会先清空）。

屏幕输入：
```
3
10.0 20.0 30.0
```
屏幕输出：
```
已写入 3 个阻力值，文件共 28 字节
```
**运行后** `loads.bin` 逻辑内容：4 字节整数 `3`，随后是 `10.0`、`20.0`、`30.0` 各 8 字节，共 $4 + 3 \times 8 = 28$ 字节。旧的 44 字节已被覆盖。

## 六、常见错误与讲解

**错误 1：用文本模式 `"w"` 打开却做二进制写**

```c
fp = fopen("loads.bin", "w");              /* 错：未声明二进制模式 */
fp = fopen("loads.bin", "wb");             /* 对：模式串带 b */
```
在部分平台上，文本模式会自动改写换行等字节，导致文件内容与内存不一致，练习 07 回读时就会错乱。**二进制文件一律用带 `b` 的模式。**

**错误 2：`fwrite` 的字节数和个数写错**

```c
fwrite(a, sizeof(double), n, fp);   /* 对：n 个元素，每个 sizeof(double) 字节 */
fwrite(a, n, sizeof(double), fp);   /* 错：把个数与字节数写反了 */
fwrite(a, n, 1, fp);                /* 错：只写了 n 个字节，数据被截断 */
```
记住参数顺序：**（地址，单元素字节数，元素个数，文件指针）**。

**错误 3：写数组时用 `&a` 或漏写数组名**

```c
fwrite(a, sizeof(double), n, fp);    /* 对：数组名即首元素地址 */
fwrite(&a, sizeof(double), n, fp);   /* 虽可编译，但语义不清；应写 a */
```
数组名本身就代表首元素地址，写 `a` 即可，这与第 5、6 章"数组名作参数"的用法一致。

**错误 4：忘记判空或忘记 `fclose`**

```c
fp = fopen("loads.bin", "wb");
fwrite(&n, sizeof(int), 1, fp);      /* 错：fp 可能为 NULL */
```
以及写完不 `fclose`，缓冲区的数据可能没有真正落盘，文件大小与预期不符。打开判空、写完关闭，是文件操作的两条铁律。

## 七、与综合实验的衔接

实验 C7 的载荷采集模块在内存里攒够一批阻力值后，就用本练习的方式整批二进制存盘；C9 的压力网格、B2 的监测信号序列也同样如此。二进制存盘是"大批量数值持久化"的标准做法，一个字：快。练习 07 会把这份 `loads.bin` 读回来并做统计，体验"写—读"闭环。若将来数据规模进一步增大、还需要按条件检索与共享，第 8 章 8.7 节的数据库技术会在文件之上提供更系统的持久化管理。
