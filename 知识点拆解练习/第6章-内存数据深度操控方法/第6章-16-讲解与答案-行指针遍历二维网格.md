## 二、预备知识：二维数组与行指针的关系（零基础阅读）

### 1. 二维数组在内存里其实是"一行接一行"的连续空间

`double g[6][4]` 看起来是 6 行 4 列，但在内存里它是**连续的一长条**：先放第 0 行的 4 个数，紧接着放第 1 行的 4 个数……第 i 行的首地址就是 `g[i]`。所以"行"是理解二维数组的关键单位。

```
   内存（连续排布，每格一个 double）：
   ┌────────────────┬────────────────┬────────────────┐
   │ g00 g01 g02 g03│ g10 g11 g12 g13│ g20 g21 g22 g23│  ...
   │   = 第 0 行     │   = 第 1 行     │   = 第 2 行     │
   └────────────────┴────────────────┴────────────────┘
     ▲                ▲                ▲
     │ p 指向第0行     │ p+1 指向第1行   │ p+2 指向第2行
     └ p+i 每次前进"一整行"（4 个 double = 32 字节）
```

### 2. 关键概念：`g` 的元素类型是"一整行"，不是"一个数"

对一维数组 `double a[4]`，`a` 退化成"指向一个 double 的指针"（`double *`）。但对二维数组 `double g[6][4]`，`g` 退化后指向的**不是**一个 `double`，而是**一整行**（4 个 `double` 的数组）。所以描述它的指针类型是：

```
   double (*p)[4];
            └── p 是一个指针，指向"含 4 个 double 的数组"（一整行）
```

括号不能省！`double (*p)[4]` 是"指向数组的指针（行指针）"，而 `double *p[4]` 是"含有 4 个指针的数组"，两者天差地别（详见常见错误 2）。

### 3. 两层解引用：从行到列

```
   p          类型 double (*)[4]   指向第 0 行（一整行）
   p + i      仍是指向第 i 行的指针，地址前进 i * 4 * sizeof(double) 字节
   *(p + i)   类型 double *         第 i 行的首地址（退化成指向第 i 行首元素）
   *(p + i) + j                     第 i 行第 j 列元素的地址
   *(*(p + i) + j)                  第 i 行第 j 列元素的值
   p[i][j]                          与上一行完全等价（推荐这种写法）
```

一句话记法：**`p` 走一层到"行"，再走一层到"列"，两次解引用落到一个数**。

### 4. 为什么形参只给列数 4，不给行数

函数里要算 `p + i` 该前进多少字节，必须知道"一行有多宽"。这个宽度由**列数**决定（4 个 `double`）。行数只影响循环次数，与指针步进无关，所以作为普通参数 `int rows` 传入即可。因此 C 语言规定：**二维数组作函数参数时，列数必须写在形参里，行数可以省略（因为本来就要另传）。**

### 5. 编程翻译

- 形参：`double (*p)[4]`；
- 遍历：外层 `p + i` 走行，内层 `p[i][j]` 取列；
- 求和、再在主函数用总和除以 `rows * 4` 得均值。

## 三、解题思路

1. **定数据**：`double g[6][4]` 存网格；
2. **定接口**：`double grid_total(double (*p)[4], int rows);` 返回总和；
3. **定遍历**：双重循环，`sum += p[i][j];`
4. **定均值**：主函数算 `total / (rows * 4)`，避免在函数里重复传列数信息；
5. **定格式**：总和 `%.2f`、均值 `%.4f`。

## 四、参考代码

```c
#include <stdio.h>

/* 用行指针 p 逐行扫描网格，返回所有元素之和 */
double grid_total(double (*p)[4], int rows)
{
    double sum = 0.0;
    int i, j;

    for (i = 0; i < rows; i++)      /* p + i 指向第 i 行 */
        for (j = 0; j < 4; j++)     /* 行内逐列 */
            sum += p[i][j];         /* 等价于 *(*(p + i) + j) */

    return sum;
}

int main(void)
{
    double g[6][4];                 /* 压力网格，最多 6 行 4 列，kPa */
    int rows, i, j;
    double total;

    scanf("%d", &rows);
    for (i = 0; i < rows; i++)
        for (j = 0; j < 4; j++)
            scanf("%lf", &g[i][j]);

    total = grid_total(g, rows);    /* 二维数组名 g 退化为行指针 */

    printf("total = %.2f\n", total);
    printf("mean = %.4f\n", total / (rows * 4));

    return 0;
}
```

| 2 行网格（10 20 30 40 / 50 60 70 80） | 求和 360；均值 360/8 = 45 | `total = 360.00`、`mean = 45.0000` ✓ |

> 地址类说明：`p`、`p + i` 的具体地址随运行环境而定，但 `p + i` 相对 `g` 前进 i 整行这一关系恒定；程序输出的是数值统计量，与具体地址无关。

## 六、常见错误与讲解

**错误 1：形参写成 `double **p` 或 `double *p`**

```c
double grid_total(double **p, int rows)   /* 错：这是"指向指针的指针"，与二维数组内存模型不符 */
double grid_total(double (*p)[4], int rows) /* 对：行指针 */
```
`double **` 表示"一块内存里存着一个地址、那个地址又指向别处"，而二维数组是连续的一整块，两者的寻址方式根本不同，混用会得到乱码或崩溃。

**错误 2：括号写丢，把行指针变成指针数组**

```c
double (*p)[4]   /* 对：p 是指向"含4个double的数组"的指针（行指针） */
double *p[4]     /* 错：这是"含4个double指针的数组"，完全是另一回事 */
```
辨析：`[]` 优先级高于 `*`，`*p[4]` 先算 `p[4]`（数组），故是指针数组；加括号 `(*p)` 才约束成"p 先是指针"。

**错误 3：以为 `p + 1` 只前进一个 `double`**

```c
/* 误以为 (p + 1) 指向 g[0][1]，实际它指向 g[1][0]（下一行行首） */
```
行指针的步长是"一整行"。要在一行内移动，得先解引用到列指针：`*(p + i) + j`。

**错误 4：作参数时省略列数**

```c
double grid_total(double (*p)[], int rows)   /* 错：列数不可省，编译器无法确定行宽 */
double grid_total(double (*p)[4], int rows)  /* 对：显式给出列数 4 */
```
