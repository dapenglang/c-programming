# 第 4 章 练习 12　全局变量与局部变量作用域

**对应章节**：4 模块化程序设计方法（4.1 函数调用与参数传递，4.4 变量的存储属性与作用域——全局变量、局部变量）

**场景来源**：综合实验 D4《燃料棒温度场分析系统》（核学院）——本练习是该实验中"测点温度阈值判定与超限计数"环节的实现。

**建议用时**：25 分钟

## 一、应用场景

燃料棒表面温度是一个关键安全参数：当某个测点的温度超过报警阈值时，系统需要把它标为"超限"，并累计整段数据里超限测点的总数，供后续评估使用。阈值 $T_{\text{lim}}$ 与超限计数 `over` 都是**整个分析过程共用的量**——阈值要能被每个测点的判定函数读到，计数要能被主程序最后打印出来。把它们定义成**全局变量**，所有函数就都能直接访问；而每个测点自己的临时判定结果则只需一个**局部变量**，用完即弃。

## 二、任务要求

编写一个完整程序 `temp_scope.c`：

1. 定义两个全局变量：`double g_limit;`（温度报警阈值，单位：摄氏度）与 `int g_over;`（超限测点数量，初值 0）；
2. 编写函数 `void check(double t)`：用一个**局部变量** `level` 存放本次判定等级，当 $t > g\_limit$ 时令 `level = 1` 并把全局变量 `g_over` 加一，否则令 `level = 0`；然后按格式输出该测点的温度与等级；
3. `main` 中依次读入阈值、测点数 `n`，再循环读入 `n` 个测点温度并调用 `check`；最后输出超限总数 `g_over`；
4. **接口约定**：`check` 只接收一个 `double` 形参、无返回值；阈值与计数必须通过全局变量在两个函数之间共享，不得靠参数传递；`level` 必须是只在 `check` 内部可见的局部变量。

## 三、输入输出格式

**输入**：第一行一个实数（报警阈值）；第二行一个整数 `n`（测点数，$0 < n \le 100$）；接下来 `n` 行，每行一个实数（测点温度，℃）。

**输出**：每调用一次 `check` 输出一行 `T = 温度, level = 等级`（温度保留 1 位小数）；最后一行输出 `over = 超限数`。

## 四、样例

**样例 1**

输入：
```
400
3
380
420
400
```
输出：
```
T = 380.0, level = 0
T = 420.0, level = 1
T = 400.0, level = 0
over = 1
```

**样例 2**

输入：
```
500
4
520
480
500
535
```
输出：
```
T = 520.0, level = 1
T = 480.0, level = 0
T = 500.0, level = 0
T = 535.0, level = 1
over = 2
```

## 五、提示

- 全局变量定义在**所有函数之外**，从它出现的位置起，后面的每个函数都能直接读写，不需要加参数；
- 判定条件是严格大于：$t > T_{\text{lim}}$ 才算超限，$t = T_{\text{lim}}$ 不算；
- `main` 中最后打印 `g_over` 时不需要任何特殊语法——它本来就是全局变量，直接写变量名即可；
- 请体会：如果把 `g_over` 写成 `check` 里的普通局部变量，`main` 就完全看不到它；这正是"作用域"带来的差别。

**完成本练习后你将具备的能力**：分清全局变量与局部变量在**作用域**（谁能看见）上的差异、理解为什么"需要多函数共享的状态"常用全局变量表达、能写出在多个函数间协作完成统计的小程序——这是实验 D4 中"温度监测与报警模块"的地基。
