# 第 7 章 练习 22　任务表结构体数组排序

**所属综合实验**：B9（B9-基于贪心策略的机房任务调度模拟系统）

**对应章节**：7 构造数据类型（7.1 结构体类型定义、7.4 结构体数组、7.3 成员访问、5.1 一维数组、3.3 循环结构）

**场景来源**：综合实验 B9《基于贪心策略的机房任务调度模拟系统》（人工智能学院）——本练习是该实验中"任务排序"环节的最小实现。

**建议用时**：30 分钟

## 一、应用场景

机房任务调度时，**先做哪个任务**直接影响效率。贪心策略常用的一条规则是"截止时间早的先做"（最早截止优先）：把任务按截止时间从早到晚排一遍，再依次安排机器。

每个任务包含好几条信息：任务编号、截止时间、所需机器数。用**结构体数组**存整个任务表，排序时随着任务一起搬动的就是"整条记录"——编号、时间、机器数不会走散。B9 系统的调度入口就是这道排序。

## 二、任务要求

编写一个完整程序 `task_sort.c`：

1. 定义结构体类型
   ```c
   struct Task {
       int id;       /* 任务编号 */
       int deadline; /* 截止时间（相对时刻） */
       int machines; /* 所需机器数 */
   };
   ```
2. 从键盘读入任务个数 `n`（$1 \le n \le 10$）；
3. 读入 $n$ 条任务记录（编号、截止时间、机器数）；
4. 用**冒泡排序**按截止时间 `deadline` **从小到大**排序（若截止时间相同，则按编号从小到大排）；
5. 输出排序后的任务表，每行一条。

## 三、输入输出格式

**输入**：
第一行，一个整数 n；
接下来 n 行，每行三个整数：id、deadline、machines。

**输出**：n 行，每行按格式 `id=编号 deadline=截止时间 machines=机器数` 输出排序后的记录。

## 四、样例

**样例 1**

输入：
```
3
1 5 2
2 3 1
3 4 3
```
输出：
```
id=2 deadline=3 machines=1
id=3 deadline=4 machines=3
id=1 deadline=5 machines=2
```

**样例 2**

输入：
```
3
1 4 2
2 4 1
3 2 5
```
输出：
```
id=3 deadline=2 machines=5
id=1 deadline=4 machines=2
id=2 deadline=4 machines=1
```

## 五、提示

冒泡排序的思想：反复比较相邻两个元素，若顺序不对就交换，一轮下来最大的"沉"到底部。

对结构体数组排序，**交换时要整体交换**——不能只换截止时间，否则编号和机器数就对不上了。结构体变量可以直接整体赋值，比逐个成员搬方便得多：

```c
struct Task tmp = t[j];
t[j] = t[j+1];
t[j+1] = tmp;
```

比较规则（从小到大）：若 $t[j].deadline > t[j+1].deadline$，或截止时间相同但 $t[j].id > t[j+1].id$，则交换。
