# 题目 B8：基于高斯消元的交通流量平衡计算系统

**适用学院**：人工智能学院（4 系）　**组容量**：本题目最多 3 组选择

## 一、系统/算法说明

**系统做什么**：本系统是一套命令行交通流量平衡计算工具：读入一个简化路网（若干路段与节点），依据"每个节点流入流量 = 流出流量 + 净产生量"的守恒关系自动组装线性方程组，用列主元高斯消元解出全部路段的流量，再与路段通行能力对比输出超载预警名单，并支持多套出行需求方案批量重算。

**解决什么重要问题**：城市路网上传感器（地感线圈、卡口）只能观测到部分路段的流量，规划者却需要知道每条路的流量才能判断哪里拥堵、改造哪条路。流量平衡计算用"守恒方程 + 少量实测值"把未观测路段的流量反推出来——这正是交通规划经典"四阶段法"中流量分配的简化版。若不做这项计算，决策就只能凭感觉：修哪条路、限行哪个方向都缺乏数据支撑；而方程组一旦无解或出现负流量，程序若不加检测，输出就是一堆毫无意义的数字，因此解状态检测同样是本系统的关键环节。

**支撑哪些关键应用**：① 交通规划中的出行需求分析与流量分配；② 地感线圈数据补全（用守恒关系估计未观测路段）；③ 道路改造与限行方案的前期评估；④ 供水管网、配电网、物流网络等一切"网络流平衡"问题，数学骨架完全相同。

**与专业培养的关联**：智能交通是人工智能专业"智能控制与机器人"方向的重要应用场景，交通状态估计、信号配时优化都以路网流量数据为输入。本系统让学生用课程内的高斯消元（5.6 节）亲手完成一次真实场景的"由守恒定律列方程—解方程—分析解"完整流程，为后续运筹优化与智能交通课程建立直观基础。

## 二、题目任务与专业关联

本题目要求实现一个含 10 个模块的交通流量平衡计算系统：(1) 从路网文件读入路段表（起讫节点、通行能力、实测流量）与节点净流量表并校验；(2) 按节点流量守恒组装线性方程组 Ax=b，并把实测路段流量作为补充方程并入；(3) 用列主元高斯消元求解并回代；(4) 检测主元过小（无唯一解）、负流量（数据矛盾）等异常状态；(5) 与通行能力对比生成超载预警名单；(6) 从场景文件读入多套净流量方案批量重算；(7) 以结果表、字符条形图与报表文件输出。

专业关联：本题展示"物理守恒定律 → 线性方程组 → 数值求解 → 决策预警"这条工程计算的标准链路，与智能交通、机器人、智能控制等专业课程中"建模—求解—评估"的工作方式完全一致。

## 三、数据来源与格式

### 3.1 数据文件格式

（1）路网数据文件 `network.txt`：分两段，`#` 开头为注释行。

```
# 路段表：编号 起节点 迄节点 通行能力(辆/小时) 实测流量(辆/小时, -1表示未观测)
1 1 2 1500 -1
2 1 3 1200 620
3 2 3 1000 -1
4 2 4 1400 -1
5 3 4 1300 810
6 3 5 900 -1
7 4 5 1600 -1
# 节点净流量表：节点编号 净产生量(辆/小时, 正=出行产生, 负=出行吸引)
1 800
2 -300
3 100
4 -250
5 -350
```

样例路网含义：5 个节点、7 条单向路段；节点 1 是出行产生源（如居住区），节点 4、5 是主要吸引点（如商务区）。5 个节点可列 5 个守恒方程（其中一个与其他线性相关），7 个未知路段流量，再补充 2 条实测流量方程（x2=620、x5=810），恰好构成 7×7 方程组，有唯一解。

（2）多场景方案文件 `scenarios.txt`：每行一个场景，格式为"场景名 + 各节点净产生量"。

```
# 场景名  n1    n2    n3   n4    n5    （单位：辆/小时）
S1  800  -300   100  -250  -350
S2 1200  -500   200  -400  -500
S3  600  -200     0  -150  -250
```

### 3.2 仿真数据生成规则

学生按下述规则构造 2~3 个不同规模的路网（建议 5 节点 7 路段、6 节点 9 路段各一个）：

| 字段 | 说明 | 单位/取值规则 |
|---|---|---|
| 节点净产生量 | 单位：辆/小时 | 取 50 的整数倍，范围 [-1000, 1000]；全部节点之和必须为 0（先随机生成 n-1 个，最后一个取相反数），否则物理上不成立 |
| 通行能力 | 单位：辆/小时 | 每条路段取 [500, 2000] 内的 100 的倍数 |
| 实测流量 | 模拟地感线圈 | 每个路网选 2~3 条"上游路段"注入实测值：先由手算或试算估计该路段真实流量，再加 ±3% 以内的测量噪声后取整；其余路段置 -1 |
| 方案场景 | 单位：辆/小时 | 在基准方案基础上把各节点净产生量放大或缩小 20%~50%，且保持总和为 0，至少 3 个场景 |
| 异常注入·数据矛盾 | 考察检测模块 | 另存一个"坏数据版"network.txt：把某条实测流量故意加大 200 辆/小时，使方程组无相容解，解状态检测模块应报告矛盾 |
| 异常注入·观测不足 | 演示无唯一解 | 另存一个只含 1 条实测流量的版本，M4 应提示"主元过小，无唯一解" |

### 3.3 真实数据集（选做）

Sioux Falls 交通测试路网是交通规划领域最常用的公开测试网络（24 节点、76 路段，含 OD 需求与通行能力），可作为选做扩展的数据来源：https://github.com/bstabler/TransportationNetworks

## 四、数据结构设计

```c
#define MAX_LINK 12         /* 路段上限 */
#define MAX_NODE 10         /* 节点上限 */
#define MAX_DIM  (MAX_LINK + 2)   /* 方程组最大阶数 */
#define MAX_SCN  10         /* 场景上限 */

/* 路段条目 */
struct Link {
    int    id;               /* 路段编号 1 起 */
    int    from;             /* 起节点编号 */
    int    to;               /* 迄节点编号 */
    double cap;              /* 通行能力（辆/小时） */
    double obs;              /* 实测流量（辆/小时），-1 表示未观测 */
};
struct Link g_link[MAX_LINK];  int g_linkCount;
int g_nodeCount;                       /* 节点数 n（编号 1~n） */
double g_net[MAX_NODE];                /* 各节点净产生量（辆/小时） */

double g_A[MAX_DIM][MAX_DIM + 1];      /* 增广矩阵 [A|b]，最后一列为 b */
double g_x[MAX_LINK];                  /* 解向量：各路段流量（辆/小时） */
int    g_status;                       /* 0=正常 1=主元过小无唯一解 2=不相容 */

/* 多场景批量计算用 */
struct Scenario {
    char name[16];                     /* 场景名，如 S1 */
    double net[MAX_NODE];              /* 各节点净产生量 */
};
struct Scenario g_scn[MAX_SCN];  int g_scnCount;
```

## 五、功能模块拆解（共 10 个模块）

### 第一部分：数据读入（2 个模块）

**M1 路网流量数据读入模块**（源文件 `NetIO.c`）

- 功能简介：打开 `network.txt` 分两段读入路段表与节点净流量表；校验路段编号连续、节点编号在 1~n 内、净流量总和为 0（不为零给出警告并允许继续）；屏幕打印路网结构清单。
- 输入：文件路径（默认 `network.txt`）。
- 输出：`g_link`、`g_net`、`g_linkCount`、`g_nodeCount`；屏幕路网清单。

**M7 多场景批量计算模块**（源文件 `Scenario.c`）

- 功能简介：打开 `scenarios.txt` 读入多套净流量方案；对每个场景依次"替换 g_net → 调用 M2 组装 → M3 求解 → M6 预警"，把各场景的解向量与预警条数汇总成横向对比总表。
- 输入：`scenarios.txt`、已读入的路网。
- 输出：屏幕多场景对比表；填充 `g_scn`。

### 第二部分：算法实现（4 个模块）

**M2 平衡方程组装模块**（源文件 `Assemble.c`）

- 功能简介：把守恒关系翻译成方程组：对每个节点 i，"流入该节点的路段流量之和 − 流出该节点的路段流量之和 = −净产生量"，逐行填入增广矩阵；再对每条有实测值的路段追加一行 `x_j = 实测值`；组装完成后屏幕打印增广矩阵供检查。
- 输入：`g_link`、`g_net`、`g_nodeCount`。
- 输出：增广矩阵 `g_A`（n+观测数 行 × 路段数+1 列）。

**M3 高斯消元求解模块**（源文件 `Gauss.c`）

- 功能简介：实现列主元高斯消元：每列选绝对值最大的主元并换行、消元三角化、再从最后一行回代求出 `g_x`；消元过程中把每步主元值记录下来供 M4 判定；解出后屏幕输出解向量。
- 输入：增广矩阵 `g_A` 及方程个数、未知数个数。
- 输出：解向量 `g_x`；主元最小值信息。

**M4 解状态检测模块**（源文件 `Check.c`）

- 功能简介：对求解结果做三重检查并置 `g_status`：① 任一主元绝对值小于 1e-6 → 报告"方程组无唯一解，请增加实测路段"；② 把解代回原方程计算残差，最大残差超过 1e-3 → 报告"数据不相容，可能存在矛盾观测"；③ 某路段流量为负 → 报告"出现负流量，路段方向假设或数据有误"，并给出该路段编号。
- 输入：`g_A`、`g_x`、主元信息。
- 输出：状态码 `g_status`；屏幕诊断报告。

**M6 超载预警模块**（源文件 `Overload.c`）

- 功能简介：对每条路段计算负荷率 `流量/通行能力`，按规则分级：比率 ≥ 1.0 为"严重超载"、0.9~1.0 为"接近饱和"、其余正常；把超载路段按负荷率从大到小排序输出预警名单（含路段号、起讫点、流量、能力、负荷率）。
- 输入：`g_x`、`g_link`。
- 输出：屏幕分级预警名单。

### 第三部分：数据输出（4 个模块）

**M5 路段流量结果表模块**（源文件 `FlowTable.c`）

- 功能简介：以对齐表格输出全部路段的编号、起讫节点、解出流量、实测值（若有）、通行能力、负荷率，实测路段用 `*` 标注；表尾汇总总流量与平均负荷率。
- 输入：`g_x`、`g_link`。
- 输出：屏幕结果表。

**M8 流量分布字符图模块**（源文件 `BarFlow.c`）

- 功能简介：每条路段绘一行水平字符条：`#` 个数按 负荷率 × 30 缩放，负荷率 ≥ 0.9 的行首标 `!`，严重超载标 `!!`；超长截断并在行尾给出数值，一眼看出全网负荷分布。
- 输入：`g_x`、`g_link`。
- 输出：屏幕字符条形图。

**M9 结果报表输出模块**（源文件 `Report.c`）

- 功能简介：把当前场景的完整计算结果写入 `flow_result.csv`：表头（场景名、求解状态）、逐路段行（编号、起、讫、流量、能力、负荷率、预警级别）；多场景模式下把所有场景结果按场景名分节追加写入。
- 输入：各全局结果。
- 输出：`flow_result.csv`；屏幕确认信息。

**M10 主控菜单模块**（源文件 `main.c`）

- 功能简介：文本主菜单（读入路网 / 组装方程 / 求解与检测 / 结果表 / 预警名单 / 字符图 / 多场景批量 / 写报表 / 退出），`do-while + switch` 调度；状态约束"必须先读入路网才能组装，必须先求解才能出表与预警"。
- 输入：用户菜单选项。
- 输出：调度各模块。

## 六、数据流与控制流

**控制流**：`main()` 菜单循环 → switch 分发 M1~M9 → 直至退出。状态约束：M2 依赖 M1，M3 依赖 M2，M4/M5/M6/M8/M9 依赖 M3，M7 会循环触发 M2→M3→M4→M6 链路。

**数据流**：

```
network.txt ──► M1 读入校验 ──► g_link[] / g_net[]（路段与节点数据）
                                        │
                                        ▼
              M2 组装：守恒方程 + 实测补充方程 ──► 增广矩阵 g_A
                                        │
                                        ▼
              M3 列主元高斯消元 ──► 解向量 g_x ──► M4 状态检测 g_status
                                        │
                    ┌───────────────────┼───────────────────┐
                    ▼                   ▼                   ▼
              M5 流量结果表      M6 超载预警名单       M8 字符条形图
                    │                   │
scenarios.txt ─► M7 多场景批量（循环 M2→M3→M4→M6）──► 对比表
                    └───────────────────┴────► M9 flow_result.csv
```

所有模块之间只通过 `g_link`、`g_net`、`g_A`、`g_x`、`g_status` 与参数传递交换数据，接口（函数头部）编码前书面约定。

## 十、选做扩展

1. 观测噪声实验：把 3 条实测流量分别加 ±5% 噪声重算，对比解的变化幅度，体会"观测数据质量决定估计质量"（纯重复计算，无新理论）；
2. 扩容方案贪心：按负荷率从大到小逐条把超载路段的通行能力提升一档重算，输出"最小扩容次数使全网不超载"的简易方案（排序 + 贪心枚举）；
3. 下载 Sioux Falls 路网数据，抽取一个 6~8 节点子网转成本系统格式并求解，检验程序在更大规模下的表现。
