## 二、预备知识：打擂台法求最值

### 1. 问题是怎么来的

n 个数里找最大值，人眼的办法是"扫一眼全表"；程序没有全表可看（数据是一个一个读进来的），只能在读取的过程中**边走边记**：任何时候都记住"到目前为止见过的最大数"。读完后记着的就是全表最大——这就像擂台赛：台上始终站着当前的擂主，挑战者一个个上台，赢了就替换擂主，比赛结束时台上就是最终擂主。

### 2. 方法是怎么想出来的（不变式思想）

这个算法为什么对？因为循环从头到尾保持一条**不变式**：每次挑战之前，`peak` 恰好等于"已读过的那些数中的最大值，`index` 是它首次出现的位置"。第 1 次挑战前"已读过的数"只有第 1 个，不变式成立（初始化保证）；每挑战一次，要么新数不比擂主大（擂主仍是已读部分的最大，不变式保持），要么新数严格更大（换擂主，不变式重新成立）。读完全部 n 个数时，不变式说的"已读过的数"就是全部 n 个数，于是 `peak` 就是全局最大值。这种"循环不变式"是思考所有遍历类算法的通用工具。

### 3. 用本例走一遍（手算）

样例 1 的序列 $2.415,\ 2.508,\ 2.470,\ 2.508,\ 2.332,\ 2.194$：

- 初始化：读入第 1 个数，擂主 $peak = 2.415$，$index = 1$；
- 挑战 2：$2.508 > 2.415$，换擂主 → $peak = 2.508$，$index = 2$；
- 挑战 3：$2.470 < 2.508$，不动；
- 挑战 4：$2.508$ **不严格大于** $2.508$，不换——并列时保留先出现者，正是靠这个"严格大于"实现；
- 挑战 5、6：都不大于，不动。终局：$peak = 2.508$，$index = 2$。

### 4. 编程时怎么用它（循环怎么写、什么时候停）

三处关键：

- **初始化不能省**：第 1 个数必须在循环前单独读入、直接当擂主，否则第一次比较是在和"内存里的随机数"比。另一种常见写法是 `peak` 初始化为一个"比任何可能值都小的数"（如 -1e308），但"用第 1 个数据当擂主"最可靠，不依赖对数据范围的假设；
- **循环从 2 开始**：`for (i = 2; i <= n; i = i + 1)`，第 1 个数已经处理过；
- **命中即同时更新两个量**：`peak` 与 `index` 在同一个 if 内一起换，漏一个就会"数值与位置对不上号"。

## 三、解题思路

1. **确定变量**：`n`、`i`、`index` 为 `int`；`p`（当前读入值）、`peak`（擂主）为 `double`；
2. **读入 n 后先读第 1 个数**，令 `peak = 第 1 个数`、`index = 1`；
3. **for 循环 i 从 2 到 n**：每轮读入一个压力值，若 `p > peak` 则同时更新 `peak` 与 `index`；
4. **输出** `peak = %.3f, index = %d`。

## 四、参考代码

```c
#include <stdio.h>

int main(void)
{
    int n, i;         /* 测点个数、循环变量 */
    int index;        /* 峰值首次出现的测点序号 */
    double p;         /* 当前测点的压力值，MPa */
    double peak;      /* 擂主：到目前为止的最大压力，MPa */

    scanf("%d", &n);
    scanf("%lf", &p);     /* 先读第 1 个数作为比较起点 */
    peak = p;
    index = 1;

    for (i = 2; i <= n; i = i + 1) {   /* 第 1 个已处理，从 2 开始 */
        scanf("%lf", &p);
        if (p > peak) {     /* 严格大于：并列时保留先出现者 */
            peak = p;
            index = i;
        }
    }

    printf("peak = %.3f, index = %d\n", peak, index);

    return 0;
}
```

## 五、运行验证

| 输入 | 手算过程 | 程序输出 |
|---|---|---|
| `6` + `2.415 2.508 2.470 2.508 2.332 2.194` | 擂台过程见"预备知识"第 3 步；并列的 2.508 取先出现的第 2 号 | `peak = 2.508, index = 2` ✓ |
| `4` + `1.1 2.2 3.3 4.4` | 每次挑战都成功，擂主一路换到末尾 | `peak = 4.400, index = 4` ✓ |
| `3` + `5.2 1.8 3.0` | 挑战 2、3 均失败，擂主是第 1 个数 | `peak = 5.200, index = 1` ✓ |
| `1` + `2.777` | 循环体一次都不执行（i=2 > n=1），直接输出初值 | `peak = 2.777, index = 1` ✓ |

第 4 行验证了 n = 1 的边界：初始化已把答案备好，循环体不执行也正确。

## 六、常见错误与讲解

**错误 1：peak 不初始化就开始比较**

```c
for (i = 1; i <= n; i = i + 1) {   /* 错：第一次 p > peak 与随机数比较 */
    scanf("%lf", &p);
    if (p > peak) { ... }
}
```

必须先读第 1 个数作为擂主（且循环从 2 起），或保证第一次比较前 peak 已有确定值。

**错误 2：命中时漏更新 index**

```c
if (p > peak)
    peak = p;        /* 错：位置没换，最终 index 停在旧值 */
```

`peak` 与 `index` 是一对，必须放在同一个 if 块里一起更新。

**错误 3：用 `>=` 导致并列时记到后出现者**

```c
if (p >= peak) { ... }   /* 错：样例 1 会输出 index = 4 */
if (p > peak)  { ... }   /* 对：严格大于保留先出现者 */
```

边界语义（并列取先还是取后）由题面规定，本题要求取先。

**错误 4：循环起点与初始化不配套**

```c
scanf("%lf", &p); peak = p; index = 1;
for (i = 1; i <= n; i = i + 1) { ... }   /* 错：第 1 个数被处理了两遍 */
```

先读第 1 个当擂主后，循环必须从 `i = 2` 开始，否则第 1 个数既当过擂主又当过挑战者——本题碰巧结果不变，但计数类问题（如练习 06 的基础上再统计均值）就会出错。
