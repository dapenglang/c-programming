## 二、预备知识：移动平均与滚动窗口的基本原理（零基础阅读）

### 1. 问题是怎么来的

潮位观测值 = 真实潮汐 + 噪声（浪涌、船扰）。真实潮汐变化缓慢（周期以小时计），噪声变化剧烈（周期以秒计）。**移动平均**正是利用这个差别：取连续 3 个观测值求平均，平均的过程让正负噪声相互抵消，留下缓慢变化的趋势——这是信号处理里最古老的"滤波器"。

### 2. 公式推导

对观测序列 $\{x_i\}$，三点移动平均的输出定义为：

$$y_i = \frac{x_{i-2} + x_{i-1} + x_i}{3}, \qquad i = 3, 4, \ldots, n$$

三个性质值得体会：

- **加权相等**：三点各占 $1/3$ 权重，权重和为 1，均值不会整体抬高或压低序列；
- **对称**：窗口以 $x_{i-1}$ 为中心，输出对齐中间时刻，不引入"时间偏移"（五点、七点窗口同理）；
- **有边界**：$i < 3$ 时窗口凑不齐 3 个值，无输出——共输出 $n-2$ 个平滑值。

噪声方差在三点等权平均后降为原来的 $1/3$（独立噪声假设下 $\sigma^2 \to \sigma^2/3$），毛刺被压平；而缓变的潮位在窗口内近似不变，均值几乎就是它本身。

### 3. 代入本例数值

样例 1 的前三个窗口：

| 输出序号 i | 窗口 $(x_{i-2}, x_{i-1}, x_i)$ | $y_i$ |
|---|---|---|
| 3 | (2.10, 2.30, 2.60) | $(2.10+2.30+2.60)/3 = 7.00/3 = 2.333$ |
| 4 | (2.30, 2.60, 2.45) | $7.35/3 = 2.450$ |
| 5 | (2.60, 2.45, 2.80) | $7.85/3 = 2.617$ |

注意相邻窗口**共享两个值**：窗口每前进一格，只进来一个新值、出去一个旧值——这就是"滑动"的含义。后续三个窗口依次得 2.783、2.950、3.083。原始序列从 2.10 涨到 3.20 且带毛刺（2.45 比邻点低），平滑后曲线明显变缓变匀。

### 4. 通过编程翻译

程序要把"窗口滑动"翻译成循环。关键洞察：**任意时刻只需要记住最近 3 个值**，更早的值永远不会再被用到。于是用三个变量 `x1, x2, x3`（由旧到新）当窗口，每读入一个新值：

1. 新值进 `x3`；
2. 若已读满 3 个（`i >= 3`），调用 `movavg3(x1, x2, x3)` 输出；
3. **接力**：`x1 = x2; x2 = x3;`——全员向后挪一位，为下一圈腾出窗口。

`movavg3` 只负责"三数平均"这一件事，完全不知道数据的来源与顺序——函数与主程序各司其职。

> **这个思想在综合实验中反复出现**：C7 的 M4 移动平均（本题）、M5 中值滤波（同样滑窗口，只是把平均换成取中位数）、C6 的 M5 三点滑动平滑差分，全是"函数算窗口 + 循环滑窗口"的同一副骨架。

## 三、解题思路

1. **写函数**：`double movavg3(double a, double b, double c) { return (a + b + c) / 3.0; }`，原型放 main 前；
2. **主循环**：读 n；三个窗口变量初始化；for 循环每圈读新值进 `x3`；
3. **输出判断**：`if (i >= 3)` 时调用函数并打印；
4. **接力滑动**：`x1 = x2; x2 = x3;` 放在输出之后。

## 四、参考代码

```c
#include <stdio.h>

double movavg3(double a, double b, double c);   /* 原型声明 */

int main(void)
{
    int n, i;
    double x1 = 0.0, x2 = 0.0, x3;      /* 窗口：x1 最旧，x3 最新 */

    scanf("%d", &n);                    /* 读入观测条数 */

    for (i = 1; i <= n; i++) {
        scanf("%lf", &x3);              /* 新值进窗口 */
        if (i >= 3) {                   /* 凑满 3 个值才有输出 */
            printf("第%d个平滑值=%.3f\n", i, movavg3(x1, x2, x3));
        }
        x1 = x2;                        /* 接力滑动：为下一圈腾窗口 */
        x2 = x3;
    }
    return 0;
}

/* 三点窗口的算术平均 */
double movavg3(double a, double b, double c)
{
    return (a + b + c) / 3.0;
}
```

## 五、运行验证

**样例 1 运行结果**：

```
第3个平滑值=2.333
第4个平滑值=2.450
第5个平滑值=2.617
第6个平滑值=2.783
第7个平滑值=2.950
第8个平滑值=3.083
```

**样例 2 运行结果**（常数序列自检）：

```
第3个平滑值=5.000
```

**核对**：样例 1 六个输出已按 IEEE-754 double 与 `%.3f` 舍入规则复算核对（如 7.00/3 = 2.3333… → 2.333）；输出条数恰为 $n-2 = 6$。样例 2 中常数序列的均值应不变，输出 5.000——滤波不改变常数信号，符合理论预期。

**反例验证**：若把接力两句放到打印之前，第 3 圈打印的窗口会变成 (x1_old→x2, x2_old→x3, x3) 的错误组合（实际是 x2 的两个副本与新值），样例 1 第一个输出会变成 2.500 而非 2.333——**接力的次序**立刻被暴露。

## 六、常见错误与讲解

**错误 1：接力次序颠倒**

```c
x2 = x3;          /* 错：先动 x2，x1 = x2 拿到的已是新值 */
x1 = x2;
```

接力必须"从旧到新"：先 `x1 = x2`，再 `x2 = x3`。顺序反了，窗口里会出现重复值。

**错误 2：在函数里除以 3（整数除法）**

```c
return (a + b + c) / 3;      /* a,b,c 是 double，结果仍是 double，这里没错； */
                             /* 但若参数是 int 型就会丢小数 —— 参数类型务必写 double */
```

**错误 3：输出起点判错**

```c
if (i > 3) { ... }           /* 错：第 3 个点被漏掉，只输出 n-3 个 */
```

从第 3 个值开始有输出，条件是 `i >= 3`。

**错误 4：窗口变量没初始化**

前两圈 `i < 3` 时不打印，`x1、x2` 的初值用不到；但保持 `= 0.0` 的习惯能避免将来改代码时踩坑，也是防御未定义行为的好习惯。
