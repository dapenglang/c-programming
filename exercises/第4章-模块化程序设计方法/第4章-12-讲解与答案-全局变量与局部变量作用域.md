## 二、预备知识：变量的作用域与存储属性（零基础阅读）

### 1. 什么叫"作用域"

**作用域**回答的问题是：这个名字（变量）在程序的哪些地方"认得"？C 语言里按定义位置分两类：

- **局部变量**：定义在函数（或复合语句）内部。它只在**那个函数内部**有效，出了函数就成了"陌生人"。例如 `check` 里的 `level`，`main` 完全不知道它的存在。
- **全局变量**：定义在**所有函数之外**。从它定义的那一行起，**后面所有的函数都能直接使用它**——不用加参数，写变量名即可。

### 2. 生命周期（活多久）与作用域（谁能看见）

这两个概念很容易混：

- **作用域**决定"谁能看见"（写在哪儿）；
- **存储属性/生命周期**决定"活多久"。局部自动变量随函数调用而生、随返回而灭；全局变量和 `static` 局部变量则贯穿整个程序。

本题中 `g_limit`、`g_over` 是全局变量：作用域是全程序，生命周期也是全程序——所以 `check` 能改它、`main` 能读它，两处的修改是**同一个变量**。

### 3. 为什么本题要用全局变量

题目要求 `check` 的接口只有"一个温度、无返回值"，却要让 `main` 最后拿到总数。若走参数传递，`check` 就得把累计值返回，`main` 再用 `g_over = check(t);` 接收；而用全局变量，`check` 直接改 `g_over`，`main` 直接读——**共享状态**被自然地放在两个函数都能触达的地方。这也解释了工程直觉：阈值这类"全流程常量"、计数这类"全局统计量"，常常做成全局变量。

### 4. 为什么不滥用全局变量

全局变量方便，但代价是"人人可改"，程序一大就容易互相干扰、难以调试。因此本题的纪律是：**只有确实需要跨函数共享的才设为全局**，像 `level` 这种一次性的中间结果，必须留在函数内部当局部变量。培养"该共享的共享、该私有的私有"的意识，正是模块化设计的核心。

## 三、解题思路

1. **定全局**：在文件开头（`#include` 之后、函数之前）定义 `double g_limit;` 与 `int g_over = 0;`；
2. **写 `check`**：先算局部 `level`；若超限则 `level=1` 且 `g_over++`，否则 `level=0`；最后打印一行；
3. **定 `main`**：先 `scanf` 读阈值存入全局 `g_limit`，再读 `n`，循环读温度并调用 `check`；
4. **收尾**：循环结束后打印 `g_over`，验证全局变量确实把累计结果"传"了出来。

## 四、参考代码

```c
#include <stdio.h>

double g_limit = 0.0;   /* 全局：温度报警阈值，所有函数可见 */
int    g_over  = 0;     /* 全局：超限测点数量 */

/* 判定单个测点：level 是局部变量，出了本函数即失效 */
void check(double t)
{
    int level;                       /* 局部：仅本函数可见 */

    if (t > g_limit) {
        level = 1;
        g_over = g_over + 1;         /* 修改全局变量，main 也能看到 */
    } else {
        level = 0;
    }
    printf("T = %.1f, level = %d\n", t, level);
}

int main(void)
{
    int n, i;
    double t;

    scanf("%lf", &g_limit);          /* 读入阈值，存入全局变量 */
    scanf("%d", &n);
    for (i = 0; i < n; i++) {
        scanf("%lf", &t);
        check(t);
    }
    printf("over = %d\n", g_over);   /* 全局变量在 main 中可直接读 */
    return 0;
}
```

## 五、运行验证

| 阈值 | 本次输入温度 | 与阈值比较 | 程序输出 |
|---|---|---|---|
| 400 | 380 | $380>400$ 假 | `T = 380.0, level = 0` |
| 400 | 420 | $420>400$ 真 | `T = 420.0, level = 1` |
| 400 | 400 | $400>400$ 假 | `T = 400.0, level = 0` |
| 500 | 520 | $520>500$ 真 | `T = 520.0, level = 1` |
| 500 | 500 | $500>500$ 假 | `T = 500.0, level = 0` |
| 500 | 535 | $535>500$ 真 | `T = 535.0, level = 1` |

样例 1 结束后 `over = 1`，样例 2 结束后 `over = 2`，与程序输出一致。注意 `level` 每次调用都是"新的"（局部变量），而 `g_over` 跨调用持续累加——这正是局部与全局最直观的对照。

## 六、常见错误与讲解

**错误 1：把全局变量定义在函数内部**

```c
void check(double t)
{
    double g_limit;      /* 错：这其实是一个局部变量，main 根本看不到 */
}
```

全局变量必须写在**所有函数之外**。写在函数里就变成局部变量，各函数之间无法共享。

**错误 2：忘记初始化全局计数器**

```c
int g_over;              /* 虽默认 0，但显式初始化更清楚 */
int g_over = 0;          /* 推荐 */
```

全局变量若不显式初始化，C 会把它置 0，但显式写出 `= 0` 能让读者一眼明白设计意图。

**错误 3：在 `main` 里重新定义同名变量遮蔽全局**

```c
int main(void)
{
    int g_over = 0;      /* 错：定义了同名局部变量，遮蔽了全局的 g_over */
    ...
}
```

此时 `check` 改的是全局 `g_over`，而 `main` 打印的是自己的局部 `g_over`，输出永远是 0。**局部会遮蔽全局**，务必避免重名。

**错误 4：把无返回值的接口当成有返回值**

```c
g_over = check(t);       /* 错：check 返回 void，不能这么用 */
check(t);                /* 对：直接调用，结果靠全局变量传出 */
```

## 七、与综合实验的衔接

实验 **D4（燃料棒温度场分析）**中，阈值、最高温度、超限计数等都是贯穿全流程的量，天然适合用全局变量在"判定模块—统计模块—报表模块"之间共享。但要记住：全局变量是把"双刃剑"，实验 20（模块化计算报表）会改用**参数传递与返回值**来完成统计，把每个函数的输入输出写清楚，从而降低模块之间的耦合。本题先让你看清"全局"这种共享方式的便利，也为后面理解它可能带来的副作用打好底子。
