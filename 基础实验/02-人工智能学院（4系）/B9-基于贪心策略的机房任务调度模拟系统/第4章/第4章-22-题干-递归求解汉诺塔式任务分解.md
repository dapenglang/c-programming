# 第 4 章 练习 22　递归求解汉诺塔式任务分解

**所属综合实验**：B9（B9-基于贪心策略的机房任务调度模拟系统）

**对应章节**：4 模块化程序设计（4.1 函数的定义、4.2 函数的调用、4.3 返回值）、3.2 选择结构、3.3 循环结构

**场景来源**：综合实验 B9《基于贪心策略的机房任务调度模拟系统》（人工智能学院）——本练习是该实验中"任务分治拆解"环节的最小实现。

**建议用时**：25 分钟

## 一、应用场景

机房任务调度系统有时要把一个"大任务"反复对半拆开：一个任务排 8 台机器，就可以拆成两个子任务各排 4 台，每个子任务再拆成两个各排 2 台……直到每台机器单独处理。这种"自己拆自己"的分解方式，天然适合用**递归**来描述。

递归是"函数自己调用自己"的技巧。它把一个规模为 $n$ 的问题，变成规模更小的同类问题，逐步缩小直到可以直接解决。B9 系统在生成调度方案时，就借助这个思路把大任务拆成一棵"任务树"。

## 二、任务要求

编写一个完整程序 `task_split.c`：

1. 定义递归函数
   ```c
   int split(int n);
   ```
   功能：把规模为 `n` 的任务不断对半拆分，每拆一次就打印一行分解信息，并统计**总共拆出了多少个最小任务单元**（规模为 1 的叶子）并返回：
   - 若 `n == 1`，说明已是最小任务，返回 1；
   - 否则把任务拆成两个规模各为 $\lfloor n/2 \rfloor$ 和 $\lceil n/2 \rceil$ 的子任务，分别递归处理，返回两者结果之和。
2. 在 `main` 中读入任务规模 `n`（$1 \le n \le 16$）；
3. 调用 `split`，输出分解的单元个数。

## 三、输入输出格式

**输入**：一行，一个整数 n，表示任务规模。

**输出**：
先输出若干行分解信息，格式为 `split n -> a + b`（n 被拆成 a、b 两部分，a 取 $\lfloor n/2 \rfloor$、b 取 $\lceil n/2 \rceil$）；
最后输出一行 `units = 结果`，为最小任务单元个数。

## 四、样例

**样例 1**

输入：
```
2
```
输出：
```
split 2 -> 1 + 1
units = 2
```

**样例 2**

输入：
```
4
```
输出：
```
split 4 -> 2 + 2
split 2 -> 1 + 1
split 2 -> 1 + 1
units = 4
```

## 五、提示

递归的两个必备要素：

1. **终止条件**（递归出口）：`n == 1` 时不再拆分，直接返回 1；
2. **递归步骤**：把 $n$ 拆成 $\lfloor n/2 \rfloor$ 和 $\lceil n/2 \rceil$，分别递归，再合并结果。

$$
\text{split}(n) = \begin{cases}
1, & n = 1 \\[4pt]
\text{split}\!\left(\lfloor n/2 \rfloor\right) + \text{split}\!\left(\lceil n/2 \rceil\right), & n > 1
\end{cases}
$$

分解信息要在**拆之前**打印，这样输出的顺序才是"先大后小"，与样例一致。注意 $\lfloor n/2 \rfloor$ 就是整数除法 `n / 2`，$\lceil n/2 \rceil$ 是 `n - n / 2`（例如 $n=5$ 时拆成 2 和 3）。

**完成本练习后你将具备的能力**：理解递归的"自己调用自己"、写出正确的终止条件、用递归分解问题并合并结果——这些是实验 B9 中"任务分治模块"的地基。
