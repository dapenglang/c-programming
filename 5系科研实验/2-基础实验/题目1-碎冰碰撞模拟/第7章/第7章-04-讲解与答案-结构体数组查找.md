## 二、预备知识：结构体数组上查找的基本原理（零基础阅读）

### 1. 查找查的是"成员"，拿到的是"整条记录"

结构体数组的内存布局仍是"大块套小格"，每个元素是一条完整记录：

```
b[0]                b[1]                b[2]                b[3]
+----+------+------+-----+----+------+------+-----+
| id | mass |  x   |  y  | id | mass |  x   |  y  | ...
+----+------+------+-----+----+------+------+-----+
  3   1650.60 12.5  8.4   7   440.16  5.0  3.2
```

查询条件是"编号等于 q"，编号只是记录中的一个成员，所以比较写在成员上：`b[i].id == q`。但一旦匹配成功，我们关心的往往不只是编号本身，而是这块冰的**全部属性**——正因为质量、位置与编号被封装在同一个结构体里，找到 `b[i]` 就等于拿到了整条记录，输出时直接引用 `b[i].mass、b[i].x、b[i].y` 即可。若当初用的是四个平行数组（id[]、mass[]、x[]、y[]），查找逻辑一样能写，但每一步都要警惕"下标对不齐"的隐患；结构体把这种一致性交给了语法。

### 2. 顺序查找：最朴素也最可靠

编号在清单里是无序的（冰块按观测先后登记），二分查找用不上，只能从头到尾逐个比对：

```
found = 0
for i = 0 .. n-1:
    if b[i].id == q: 记下 i，found = 1，退出循环
循环后：found 为 1 输出 b[i] 的记录，否则输出未找到
```

最多比较 $n$ 次，$n \le 10$ 时瞬间完成。第 5 章学过：若数组按编号**有序**，可换用二分查找把比较次数降到 $\log_2 n$；等清单大到上万条且常有序时再升级，思路不变。

### 3. 标志变量为什么必要

查找有两种结局（找到/未找到），而匹配发生在循环体内部。若在循环里"边找边输出"，未找到的情况就没人负责报告，还可能在找到后多跑几圈重复输出。标准做法是：循环只负责"找"，用一个 `int found` 标志把结局带出循环，输出交给循环后的分支统一处理——**查找与输出分离**，两种结局各有着落。

## 三、解题思路

1. **定类型定数组**：`struct IceBlock b[10];`；
2. **读入**：第一个循环读入 $n$ 条记录（编号、质量、x、y）；
3. **读查询值**：`scanf("%d", &q)`；
4. **顺序查找**：第二个循环内比对 `b[i].id == q`，命中则记下下标、置 `found = 1` 并 `break`；
5. **统一输出**：循环后按 `found` 分支，输出完整记录或未找到提示。

## 四、参考代码

```c
#include <stdio.h>

struct IceBlock {              /* 一块冰的登记记录 */
    int    id;                 /* 编号 */
    double mass;               /* 质量 kg */
    double x;                  /* 位置 x m */
    double y;                  /* 位置 y m */
};

int main(void)
{
    struct IceBlock b[10];
    int n, i, q;
    int found = 0;             /* 标志：是否找到 */

    scanf("%d", &n);
    for (i = 0; i < n; i++)
        scanf("%d%lf%lf%lf", &b[i].id, &b[i].mass, &b[i].x, &b[i].y);

    scanf("%d", &q);           /* 待查询的编号 */

    /* 顺序查找：逐个比对编号成员 */
    for (i = 0; i < n; i++) {
        if (b[i].id == q) {
            found = 1;         /* 命中：置标志并提前退出 */
            break;
        }
    }

    /* 查找与输出分离：两种结局统一处理 */
    if (found)
        printf("找到：%d 号冰块，质量 %.2f kg，位置 (%.2f, %.2f) m\n",
               b[i].id, b[i].mass, b[i].x, b[i].y);
    else
        printf("未找到编号为 %d 的冰块\n", q);

    return 0;
}
```

## 五、运行验证

| 输入要点 | 过程分析 | 程序输出 |
|---|---|---|
| 样例 1，q = 5 | 依次比对 3、7、**5**——第 3 次命中，此时 i = 2 | `找到：5 号冰块，质量 1834.00 kg，位置 (20.10, 15.60) m` ✓ |
| 样例 2，q = 6 | 比对 3、7、5、9 共 4 次均不匹配，found 保持 0 | `未找到编号为 6 的冰块` ✓ |
| 边界：q 是第一个 | 输入 4 条记录后查 q = 3，第 1 次即命中 | `找到：3 号冰块，质量 1650.60 kg，位置 (12.50, 8.40) m` ✓ |

三种情况覆盖"中间命中、未找到、首元素命中"，查找逻辑与输出格式均验证无误。

## 六、常见错误与讲解

**错误 1：比较对象写错——比较整条记录而不是成员**

```c
if (b[i] == q)          /* 错：结构体不能与整数比较，编译报错 */
if (b[i].id == q)       /* 对：比较的是编号成员 */
```

顺带记住一条一般规则：**两个结构体变量之间不能用 == 直接比较**（即使所有成员都相等），逐成员比较或逐成员赋值才是合法操作。

**错误 2：命中后忘了 break，或 break 后下标失效**

```c
if (b[i].id == q) {
    found = 1;
    break;              /* 若没有 break，i 会继续加到 n，循环外 b[i] 越界 */
}
```

本代码依赖"命中时 break，循环外的 i 恰好停在命中位置"这一配合，删掉 break 不但多比较，还会让输出读到越界元素。

**错误 3：未找到时输出越界数据**

```c
for (i = 0; i < n; i++)
    if (b[i].id == q)
        printf("找到：%d 号...", b[i].id, ...);
printf("未找到编号为 %d 的冰块\n", q);   /* 错：找到时也会多打这一行 */
```

循环内直接输出、循环后无条件输出"未找到"，会把两种结局同时打印。必须用 `found` 标志 + 循环后 if-else 统一收口。

**错误 4：实数成员比较编号用错了格式符**

输出质量与坐标时要用 `%.2f`（`double` 配 `%f` 系），编号用 `%d`；若把 `b[i].mass` 配了 `%d`，输出的是乱码（第 2 章的老规矩，在结构体成员上同样适用）。

## 七、与综合实验的衔接

实验 C6 的碰撞调度模块每个时间步都要按编号调取冰块记录，本练习就是它的最小实现；当清单扩大到上千条且按编号有序存放时，只需把顺序查找换成第 5 章的二分查找，结构体数组的其余代码不动——数据封装方式与查找算法是两个独立的维度，可以分别升级。练习 05 将把结构体整体**传给函数**，让"对一块冰做计算"成为可复用的模块。
