## 二、预备知识：为什么要拆分模块、内部函数是什么（零基础阅读）

### 1. 一个"大函数"有什么问题

假设把换算、应力、判定全塞进 `main`，代码也能跑，但会带来三个麻烦：一是**难读**——一长串算式看不出哪一步在干什么；二是**难改**——若以后要把力改成输入单位 N，就得在 `main` 里四处找换算；三是**难复用**——别处再要算应力，只能复制粘贴。解决之道就是**模块化**：把每个独立的小计算包装成一个函数，让 `main` 只负责"串流程"。

### 2. 模块化带来什么

拆成 `kn_to_n`、`calc_stress`、`check_safe` 之后：

- 每个函数**职责单一**，名字就说明了它在做什么，读起来像一句话："先把 kN 换成 N，再算应力，最后判定安全"；
- 修改只影响一处。要改换算系数，只动 `kn_to_n` 一个函数；
- 可以**逐层调用**：`main` 调用 `calc_stress`，`calc_stress` 又用到了换算结果——函数的调用关系像一棵树，结构清晰。

### 3. 内部函数：`static` 修饰的函数

C 语言里，函数默认是**外部函数**（`extern`），可以被同一程序的其它源文件调用；若在函数定义（和声明）前加 `static`，它就变成**内部函数**，**只在本源文件内可见**，别的 `.c` 文件即使写了同名的 `static` 函数也不会冲突。

为什么要这样做？因为 `kn_to_n` 这类函数是"本模块的实现细节"，对外没有意义。把它们设为内部函数，等于对外声明："这些是我的私有工具，你只该调用我对外提供的接口。"这样一来，即便以后别的文件里也写了同名的换算函数，也不会发生重名冲突，程序的模块边界更清晰。**注意**：`static` 只改变"谁能看见"，不改变函数的算法；本题里三个函数加不加 `static`，单文件编译运行的结果完全一样，但加上它才是规范的模块化写法。

### 4. 用函数调用把流程串起来

`main` 中的调用顺序，正是题目应用场景里的三步：

$$
F_{\text{N}} = \texttt{kn\_to\_n}(F_{\text{kN}}),\qquad
\sigma = \texttt{calc\_stress}(F_{\text{N}}, A),\qquad
\text{结论} = \texttt{check\_safe}(\sigma, [\sigma]).
$$

每一步都把上一步的返回值作为下一步的输入，函数之间**通过参数与返回值通信**，谁也不需要全局变量——这正是低耦合模块的标志。

## 三、解题思路

1. **先定接口**：三个函数各写一句注释说明"输入什么、输出什么、单位是什么"，接口清晰是模块化的前提；
2. **`kn_to_n`**：一行 `return kn * 1000.0;`；
3. **`calc_stress`**：一行 `return f_n / area;`（N/mm² 即 MPa）；
4. **`check_safe`**：`return (sigma <= allow) ? 1 : 0;`；
5. **`main` 串流程**：读三个数 → 调三个函数 → 按要求格式输出三行。

## 四、参考代码

```c
#include <stdio.h>

/* 内部函数 1：单位换算，kN -> N */
static double kn_to_n(double kn)
{
    return kn * 1000.0;
}

/* 内部函数 2：由力(N)与面积(mm^2)求应力(MPa)，1 N/mm^2 = 1 MPa */
static double calc_stress(double f_n, double area)
{
    return f_n / area;
}

/* 内部函数 3：安全判定，sigma <= allow 返回 1，否则返回 0 */
static int check_safe(double sigma, double allow)
{
    return (sigma <= allow) ? 1 : 0;
}

int main(void)
{
    double f_kn, area, allow;   /* 输入：力、面积、许用应力 */
    double f_n, sigma;          /* 中间结果 */

    scanf("%lf %lf %lf", &f_kn, &area, &allow);

    f_n   = kn_to_n(f_kn);              /* 第一步：换算 */
    sigma = calc_stress(f_n, area);     /* 第二步：算应力 */

    printf("force = %.1f N\n", f_n);
    printf("stress = %.3f MPa\n", sigma);

    if (check_safe(sigma, allow))       /* 第三步：判定 */
        printf("safe\n");
    else
        printf("over\n");

    return 0;
}
```

## 五、运行验证

| 输入 `f_kn area allow` | 换算后力 (N) | 应力 (MPa) | 判定 | 程序输出 |
|---|---|---|---|---|
| 12.5 250 60 | $12.5\times1000 = 12500.0$ | $12500/250 = 50.000$ | $50\le60$ 安全 | `safe` |
| 20 250 60 | $20\times1000 = 20000.0$ | $20000/250 = 80.000$ | $80\le60$ 不安全 | `over` |
| 12.5 500 60 | 12500.0 | $12500/500 = 25.000$ | $25\le60$ 安全 | `safe` |

三组结果的 `force` 与 `stress` 两行同样按格式输出，判定行随应力变化，与表格一致。

## 六、常见错误与讲解

**错误 1：忘了 `return`，或只在某个分支里 `return`**

```c
static double calc_stress(double f_n, double area)
{
    area + f_n;                 /* 错：算了却没返回 */
}
static int check_safe(double s, double a)
{
    if (s <= a) return 1;       /* 错：不安全时没有返回值，结果不确定 */
}
```

有返回值的函数，**每条执行路径**都必须 `return`。判定函数最稳妥的写法是三目表达式一行搞定。

**错误 2：把 `static` 写错位置**

```c
static double kn_to_n(double kn) { ... }   /* 对：static 在返回类型前 */
double static kn_to_n(double kn) { ... }   /* 语法上可接受，但风格不规范 */
```

规范写法是 `static` 放在返回类型之前。当函数在调用处之后定义时，可在文件开头用 `static double kn_to_n(double kn);` 做**原型声明**，供前面调用。

**错误 3：单位混用**

```c
sigma = calc_stress(f_kn, area);   /* 错：把 kN 直接当 N 除以 mm^2，应力小了 1000 倍 */
```

必须先用 `kn_to_n` 换算，再代入应力公式；这正是"拆分模块"后容易出现、也容易被接口名字暴露的问题。

**错误 4：误以为 `static` 会影响运行结果**

```c
/* 删掉三个函数前的 static，功能完全一样 */
```

`static` 只限制可见范围，不改变数值。若本题是**多文件**工程，它的作用是防止与其它文件里的同名函数冲突。

## 七、与综合实验的衔接

实验 **C7（冰载荷辨识）**的代码量远大于单次练习，必须靠"一个函数一个职责"来组织：辨识算法、单位换算、判据、报表各自独立，主流程只负责调度。把只服务于本文件的辅助函数写成 `static` 内部函数，能有效减少不同源文件之间的命名冲突，是团队协作时保护模块边界的重要手段。下一题（14）起，我们将进入 4.6 节，学习用函数来承载**迭代求解**的过程。
