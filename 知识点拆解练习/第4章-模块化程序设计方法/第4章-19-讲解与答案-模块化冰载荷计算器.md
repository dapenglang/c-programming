## 二、预备知识：为什么要拆分模块、函数之间如何协作（零基础阅读）

### 1. 一个大程序为什么必须拆分

交互式程序越长，"把一切都写在 `main` 里"的坏处越明显：`main` 里既有菜单、又有公式、又有判定，读起来像一团乱麻；想改某一个计算，得在几十行里找；想复用它，只能复制。**模块化的做法**是把每个独立的计算搬进一个函数，让 `main` 只做两件事：**显示菜单、根据选项调度函数**。这样每个函数职责单一、名字自解释，`main` 也变得一目了然。

### 2. 函数之间的调用关系

本程序的调用关系像一棵两层的小树：

- 顶层是 `main`——负责读选项、`switch` 分派；
- 底层是三个功能函数——`calc_stress`、`kn_to_n`、`check_safe`，各自完成一个计算。

`main` 通过**实参 → 形参**把数据交给功能函数，功能函数通过 **`return`** 把结果交回 `main`。整个过程没有任何全局变量，模块之间只靠"接口"通信，这正是低耦合的体现。注意 `calc_stress` 内部其实隐含了"先把 kN 换成 N 再除以面积"的两步——也可以进一步调用 `kn_to_n`，形成三层调用；本题为清晰起见把换算式直接写在应力函数里。

### 3. 菜单程序为什么用 `switch` + `do-while`

菜单是典型的"多中选一"，用 `switch` 比一串 `if-else` 更整齐，每个 `case` 处理一个选项、`break` 结束本分支。而"处理完一个选项还要回到菜单"，天然适合作业前判断的写法：用 `do-while`，让"读选项—分派—判断是否退出"至少执行一次，`while (opt != 0)` 决定是否继续。`default` 分支专门接住非法输入，输出 `invalid`，让程序更健壮。

### 4. 为什么功能函数用 `static`

这三个函数是"本计算器的私有工具"，外部源文件没有理由调用它们。加 `static` 把它们设为**内部函数**，等于划定模块边界：即使别的文件也定义了同名函数，也不会冲突。功能上，删掉 `static` 结果完全一样，但保留它才是规范的模块化写法。

## 三、解题思路

1. **先写三个功能函数**：接口清晰、每个只做一件事；
2. **打印固定菜单**：标题与选项行在循环外打印一次；
3. **写菜单循环**：`do { scanf("%d",&opt); switch(opt){...} } while (opt != 0);`
4. **每个 `case` 先读参数、再调用、再输出**，`case 0` 输出 `exit`，`default` 输出 `invalid`。

## 四、参考代码

```c
#include <stdio.h>

/* 内部函数：由力(kN)与面积(mm^2)求应力(MPa) */
static double calc_stress(double f_kn, double area)
{
    return f_kn * 1000.0 / area;        /* kN->N 后除以 mm^2，即 MPa */
}

/* 内部函数：kN -> N */
static double kn_to_n(double kn)
{
    return kn * 1000.0;
}

/* 内部函数：安全判定 */
static int check_safe(double sigma, double allow)
{
    return (sigma <= allow) ? 1 : 0;
}

int main(void)
{
    int opt;
    double f_kn, area, sigma, allow, kn;

    /* 固定菜单，只打印一次 */
    printf("=== Ice Load Calculator ===\n");
    printf("1 stress  2 convert  3 judge  0 exit\n");

    do {
        scanf("%d", &opt);
        switch (opt) {
        case 1:                                     /* 应力 */
            scanf("%lf %lf", &f_kn, &area);
            printf("stress = %.3f MPa\n", calc_stress(f_kn, area));
            break;
        case 2:                                     /* 换算 */
            scanf("%lf", &kn);
            printf("force = %.1f N\n", kn_to_n(kn));
            break;
        case 3:                                     /* 判定 */
            scanf("%lf %lf", &sigma, &allow);
            printf("%s\n", check_safe(sigma, allow) ? "safe" : "over");
            break;
        case 0:                                     /* 退出 */
            printf("exit\n");
            break;
        default:                                    /* 非法输入 */
            printf("invalid\n");
        }
    } while (opt != 0);

    return 0;
}
```

## 五、运行验证

| 选项 | 本选项输入 | 计算过程 | 程序输出 |
|---|---|---|---|
| 1 | 12.5 250 | $12.5\times1000/250 = 50.000$ | `stress = 50.000 MPa` |
| 2 | 30 | $30\times1000 = 30000.0$ | `force = 30000.0 N` |
| 3 | 50 60 | $50\le60$ 真 | `safe` |
| 3 | 80 60 | $80\le60$ 假 | `over` |
| 0 | — | 退出循环 | `exit` |

把样例 1 的选项序列 `1→2→3→0` 依次输入，输出与上表完全一致；样例 2 的 `1→3→0` 亦如此。

## 六、常见错误与讲解

**错误 1：`switch` 分支漏写 `break`**

```c
case 1:
    ...
    /* 少了 break，会继续执行 case 2 的代码 */
```

漏 `break` 会发生"贯穿"，把后面分支的语句也执行一遍，务必每个 `case` 以 `break` 收尾。

**错误 2：把退出条件的判断写反**

```c
} while (opt == 0);      /* 错：输入 0 反而继续 */
} while (opt != 0);      /* 对 */
```

**错误 3：一次性把参数全部读入**

```c
scanf("%d %lf %lf %lf", &opt, &f_kn, &area, &sigma);   /* 错：选项不同，需要的参数个数也不同 */
```

应"选中哪个选项，才读它自己的参数"，否则会打乱后续读入。

**错误 4：忘记在读选项前打印菜单**

菜单只在程序开始时打印一次，放进循环或忘记打印都会让交互体验变差（样例输出也会对不上）。
