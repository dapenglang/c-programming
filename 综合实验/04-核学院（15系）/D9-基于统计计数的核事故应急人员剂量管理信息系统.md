# 题目 D9：基于统计计数的核事故应急人员剂量管理信息系统

**适用学院**：核学院（15 系）　**组容量**：本题目最多 2 组选择

## 一、系统/算法说明

本系统是一套命令行核事故应急人员剂量管理工具，围绕"应急响应期间人员受照剂量的台账记录、汇总统计与分级管理"这一核应急核心业务展开。系统读入应急人员名册与历次受照剂量记录，能够按人员编号汇总累计剂量，按 20 mSv/年与 50 mSv 两个阈值把人员分为"正常 / 关注 / 超限"三档，对超限人员按累计剂量降序排序并生成干预清单，还能按编号查找某人的全部受照记录并打印剂量区间人数直方图。

剂量台账是核事故应急响应的第一份账本。如果不解决它，应急指挥将失去量化依据——无法判断哪些人已接近个人年剂量限值 20 mSv 而必须撤出、哪些人已达到应急受照的较高水平而必须立即干预；无法在多次进入高辐射区之间合理安排轮换，结果是一批骨干在事故前期就被"用尽"，人力与防护双双失控。记录散落在纸片与不同班组手里、重复计算与漏记并存时，指挥部拿不到一张可信的超限名单，超限人员会继续进入控制区。

本系统支撑的关键应用场景包括：① 核电厂应急演练中的现场剂量台账与轮换调度；② 辐射工作人员职业健康管理与个人剂量监测档案的年度汇总；③ 事故后受照人员的医学观察分级与随访名单生成；④ 应急队伍进场前的剂量余量核对。本题目与核工程与核技术专业"辐射防护与核安全"方向直接相关，训练学生把管理规则转化为"数据读入—统计计算—分级输出"完整程序工程的能力。

## 二、题目任务与专业关联

本题目要求学生实现一个完整的应急人员剂量管理系统：从两个文本文件分别读入人员名册（编号、姓名、岗位）与剂量记录（编号、日期、剂量 mSv），实现记录有效性校验函数（剂量非负、编号必须在名册中、单次剂量不超过 500 mSv 的上限），按编号汇总每人累计剂量，按 20 与 50 mSv 两级阈值判定"正常 / 关注 / 超限"三档，对超限人员用冒泡排序按累计剂量降序排列并生成干预清单，支持按编号查找该人的全部记录，最后输出分级名册、剂量区间人数直方图与干预清单文件。

专业关联上，本题目复现了核应急演练剂量台账、职业健康管理年报、事故受照人员分级三类真实业务的核心统计。学生在此过程中将掌握课程中的结构体与结构体数组、计数统计、排序与查找、字符数组、文件读写，并第一次把"限值—分级—名册"的管理规则写成一套程序，理解"一条防护标准如何变成一份可执行的清单"。
## 三、数据来源与格式

- **数据文件格式**：人员名册采用纯文本格式，首行为标题说明，其后每行一条人员记录。字段依次为：人员编号（6 位整数，如 150102）、姓名（无空格字符串）、岗位（无空格字符串）。剂量记录文件同样首行为标题，其后每行一条记录，字段依次为：人员编号、受照日期（`YYYY-MM-DD` 字符串）、单次剂量 D（单位：毫希沃特 mSv，实数）。
```
# staff_id  name      post
150102      ZhangSan  RESCUE
150103      LiSi      DOSE_ASSESS
150104      WangWu    VENTILATION
150105      ZhaoLiu   SAMPLING
150106      SunQi     MAINTENANCE
```

```
# staff_id  date        dose_mSv
150102      2026-03-11  8.5
150103      2026-03-11  25.4
150104      2026-03-12  52.0
```

- **仿真数据生成规则**：
  - 人员编号：单位无，取值范围 150001～150999，递增生成不重复，作为名册与记录两个文件的关联主键。
  - 姓名：取 3～10 个字母的拼音串，长度 ≤ 15，无空格，如 `ZhangSan`、`LiSi`。
  - 岗位：取自固定枚举集合 `{RESCUE, DOSE_ASSESS, VENTILATION, SAMPLING, MAINTENANCE, COMMAND}` 之一，长度 ≤ 15，无空格。
  - 受照日期：格式固定 `YYYY-MM-DD`，年份取 2026，月 1～12，日 1～28，按应急持续周期（3～30 天）连续生成。
  - 单次剂量 D：单位 mSv，取值范围 0.1～120.0。按分段分布生成——多数人次服从 [0.1, 15.0] 的均匀分布（常规作业），少量人次服从 [15.0, 120.0] 的均匀分布（高辐射区抢修），使累计剂量呈现"多数正常、少数超限"的真实形态；单次剂量绝对上限 500.0 mSv。
  - 记录条数：每人 1～8 条；人员总数 20～40 人，总记录数 80～300 条。
  - **异常值注入方式**：由教师提供的生成程序人为注入四类错误。其一，剂量字段填入负数（如 `-3.5`）或零，需识别并剔除；其二，记录中的编号在名册中不存在（如 `999999`），需判为"无名册记录"并单独统计；其三，单次剂量填入超过 500 mSv 的物理不合理值（如 `1200.0`），需判为超上限并剔除；其四，日期字段写成 `2026-13-45` 之类非法月日，需判为格式错误。校验模块需输出"行号—异常类型—处理动作"清单。
- **真实数据集（如有）**：剂量限值依据可参考 ICRP 第 103 号出版物给出的职业照射年有效剂量限值 20 mSv（连续 5 年平均），以及 GB 18871-2002《电离辐射防护与辐射源安全基本标准》中职业照射与应急照射的剂量管理要求。学生**无需下载**真实数据文件，课程提供与上述字段含义对应的简化仿真数据表；表中"单次剂量"对应个人剂量计（TLD/OSL）读数，"累计剂量"对应个人剂量监测档案的年度累计值。

## 四、数据结构设计

```c
/* ===== 常量定义 ===== */
#define MAX_STAFF    40      /* 最多人员数量 */
#define MAX_RECORD  400      /* 最多剂量记录条数 */
#define MAX_NAME_LEN  16     /* 姓名最大长度（含结束符） */
#define MAX_POST_LEN  16     /* 岗位名最大长度（含结束符） */
#define MAX_DATE_LEN  12     /* 日期字符串最大长度 "YYYY-MM-DD" */
#define LIMIT_WATCH  20.0    /* 关注阈值，单位 mSv */ 
#define LIMIT_OVER   50.0    /* 超限阈值，单位 mSv */
#define SINGLE_MAX  500.0    /* 单次剂量物理上限，单位 mSv */

/* ===== 人员名册结构体 ===== */
struct Staff {
    int    id;                    /* 人员编号，150001~150999 */
    char   name[MAX_NAME_LEN];    /* 姓名，如 "ZhangSan" */
    char   post[MAX_POST_LEN];    /* 岗位，如 "RESCUE" */
    double cumDose;               /* 累计剂量，单位 mSv，由记录汇总得到，初值 0 */
    int    recCount;              /* 该人有效记录条数 */
    int    level;                 /* 分级：0 正常(<20)，1 关注(20~50)，2 超限(>=50) */
};

/* ===== 剂量记录结构体 ===== */
struct DoseRec {
    int    id;                    /* 所属人员编号 */
    char   date[MAX_DATE_LEN];    /* 受照日期，格式 "YYYY-MM-DD" */
    double dose;                  /* 单次剂量，单位 mSv，0 < dose <= 500 */
    int    valid;                 /* 有效标志：1 有效，0 已判为异常剔除 */
};

/* ===== 剂量区间直方图 ===== */
struct HistBin {
    double lo;                    /* 区间下界，单位 mSv（含） */
    double hi;                    /* 区间上界，单位 mSv（不含） */
    int    count;                 /* 落在此区间的人数 */
};

/* ===== 全局数据区 ===== */
struct Staff   g_staff[MAX_STAFF];      /* 人员名册表 */
int            g_staffCount;            /* 名册人数 */
struct DoseRec g_rec[MAX_RECORD];       /* 剂量记录表 */
int            g_recCount;              /* 读入记录条数 */
int            g_validRecCount;         /* 有效记录条数 */
struct HistBin g_bin[6];                /* 剂量区间直方图（6 档） */
int            g_levelCount[3];         /* 三档人数统计 */
int            g_loaded, g_checked, g_summed;   /* 流程状态标记 */

/* ===== 处理日志（供报表模块使用） ===== */
struct LogItem {
    char op[24];                /* 操作名，如 "SUM_DOSE" */
    char detail[64];            /* 参数与关键结果摘要 */
};
struct LogItem g_log[MAX_RECORD / 4];
int            g_logCount;     /* 已记录日志条数 */
```

辅助说明：人员名册与剂量记录分别用结构体数组组织（课程 7.1/7.2），两个数组通过人员编号建立关联；累计剂量在名册结构体内就地累加，避免二次遍历（课程 3.3 循环累加）。分级结果 `level` 以整数编码存储，便于排序与统计；直方图 `g_bin[]` 用 6 个固定区间覆盖 0～500 mSv 全量程。

## 五、功能模块拆解（共 11 个模块）

### 第一部分：数据读入（3 个模块）

**M1 人员名单读入模块**（源文件 `StaffIO.c`）
- 功能简介：打开人员名册文本文件，跳过首行标题，用循环 + `fscanf` 逐行读入人员编号、姓名与岗位，填充全局名册表，记录读入条数；名册为空或文件不存在时给出明确提示并返回失败。
- 输入：文件路径（菜单输入，默认 `staff.txt`）。
- 输出：填充后的 `g_staff[]` 与 `g_staffCount`；返回成功/失败标志。
**M2 剂量记录读入模块**（源文件 `DoseIO.c`）
- 功能简介：打开剂量记录文本文件，跳过首行标题，用循环 + `fscanf` 逐行读入人员编号、受照日期与单次剂量，填充全局记录表；读入过程中不判对错，只做字段计数，为 M3 校验提供原始数据。
- 输入：文件路径（菜单输入，默认 `dose_rec.txt`）。
- 输出：填充后的 `g_rec[]` 与 `g_recCount`；返回成功/失败标志。
**M3 记录有效性校验模块**（源文件 `DoseCheck.c`）
- 功能简介：逐条检查单次剂量是否为正且不超过 500 mSv、记录编号是否能在名册中查找到、日期字符串月日是否在合法范围；对异常记录置 `valid=0` 并生成"行号—异常类型—处理动作"清单，同时统计"无名册记录"条数。
- 输入：`g_rec[]`、`g_recCount`、`g_staff[]`、`g_staffCount`。
- 输出：屏幕校验报告；修正后的 `g_rec[]`、`g_validRecCount`。

### 第二部分：算法实现（5 个模块）

**M4 累计剂量统计模块**（源文件 `DoseStat.c`）
- 功能简介：遍历全部有效记录，用顺序查找定位记录所属人员在名册中的下标，把该条剂量累加到该人的 `cumDose`，同时 `recCount` 自增；遍历前先把名册中所有人的 `cumDose` 与 `recCount` 清零，保证重复统计结果一致。
- 输入：`g_rec[]`（仅 `valid=1`）、`g_staff[]`、`g_staffCount`。
- 输出：更新后的 `g_staff[].cumDose` 与 `recCount`；屏幕统计摘要。
**M5 剂量分级判定模块**（源文件 `DoseStat.c`）
- 功能简介：对每名人员按累计剂量套用两级阈值规则——`cumDose < 20.0` 判为 0（正常），`20.0 ≤ cumDose < 50.0` 判为 1（关注），`cumDose ≥ 50.0` 判为 2（超限）；边界用"左闭右开"约定，并同步累计三档人数到 `g_levelCount[]`。
- 输入：`g_staff[]`、`g_staffCount`。
- 输出：每人的 `level` 字段、`g_levelCount[3]`；屏幕分级统计。
**M6 超限人员排序模块**（源文件 `DoseSort.c`）
- 功能简介：先把名册中所有 `level==2` 的人员下标抽到临时下标数组，再对该数组按累计剂量用冒泡排序降序排列，得到"谁最严重"的干预优先顺序；排序只交换下标，不改动名册原始次序。
- 输入：`g_staff[]`、`g_staffCount`。
- 输出：降序排列的超限人员下标数组与超限人数；屏幕打印排序过程摘要。
**M7 人员记录查找模块**（源文件 `DoseFind.c`）
- 功能简介：先对名册按编号做一次冒泡升序排序，再用二分查找定位用户输入编号的名册下标，然后遍历全部有效记录把属于该编号的记录逐条打印；若编号不在名册中则提示"查无此人"并返回 -1。
- 输入：用户输入的待查编号（菜单输入）。
- 输出：该人员的名册信息、全部记录与累计剂量；返回名册下标或 -1。
**M8 剂量分布直方图模块**（源文件 `DoseHist.c`）
- 功能简介：按固定 6 个区间（0～5、5～20、20～50、50～100、100～200、200～500 mSv，单位均为 mSv）统计各区间人数，用 `#` 字符按人数比例打印横向柱状图，柱长按最大区间人数归一化到 40 个字符。
- 输入：`g_staff[]`、`g_staffCount`。
- 输出：`g_bin[]`；屏幕字符直方图。
### 第三部分：数据输出（3 个模块）

**M9 分级名册输出模块**（源文件 `DoseReport.c`）
- 功能简介：按"正常 / 关注 / 超限"三档分组打印人员名册，列出编号、姓名、岗位、记录条数与累计剂量，每组末尾给出该组人数小计与占全员比例，便于指挥人员一眼掌握队伍剂量态势。
- 输入：`g_staff[]`、`g_staffCount`、`g_levelCount[]`。
- 输出：屏幕分级名册与比例统计。
**M10 干预清单文件输出模块**（源文件 `DoseReport.c`）
- 功能简介：按 M6 排好的降序顺序，把全部超限人员的编号、姓名、岗位、累计剂量与处置建议（撤出控制区 / 限制再进入 / 医学观察）写入 `intervene_list.txt`，首行写列名与生成时间；同时把分级名册与直方图数据写出到 `dose_report.csv`。
- 输入：`g_staff[]`、超限人员下标数组、`g_bin[]`。
- 输出：`intervene_list.txt`、`dose_report.csv`；屏幕确认信息。
**M11 主控菜单模块**（源文件 `Stu_main.c`）
- 功能简介：用 `do-while + switch` 调度 M1～M10，用状态标记 `g_loaded`、`g_checked`、`g_summed` 约束"必须先读入名册与记录、再校验、才能统计与分级"；菜单含读入、校验、统计分级、排序、查找、直方图、名册、输出、退出共 9 项。
- 输入：用户菜单选项。
- 输出：调度各模块；屏幕菜单与状态提示。
## 六、数据流与控制流

**控制流**：`main()` 进入菜单循环，先用状态标记约束流程——`g_loaded==0` 时只允许执行 M1/M2；读入完成后必须执行 M3 校验（`g_checked=1`）才能进行 M4/M5 统计与分级；`g_summed==1` 后开放 M6～M10。任何计算模块要求 `g_validRecCount > 0`，否则提示先执行 M2/M3 并重新读入。

**数据流**：

```
staff.txt ─► M1 名册读入 ─► g_staff[]
                                 │
dose_rec.txt ─► M2 记录读入 ─► g_rec[] ─► M3 校验 ─► 有效记录集
                                                          │
                                        ┌─────────────────┼─────────────────┐
                                        ▼                 ▼                 ▼
                              M4 累计剂量统计    M7 按编号查找记录   M8 剂量直方图
                                        │                 │                 │
                                        ▼                 ▼                 ▼
                              M5 分级判定 ─► level/统计  M9 分级名册输出
                                        │
                                        ▼
                              M6 超限排序 ─► 干预优先序
                                        │
                                        ▼
                              M10 干预清单/报告文件
                                        │
                                        ▼
                              M11 主控菜单（调度全部模块）
```

所有模块之间只通过全局名册表、全局记录表与函数参数交换数据，函数头部（接口）在编码前由全组书面约定。

## 十、选做扩展

1. **应急预案阈值敏感性分析**：把两级阈值改为可配置参数（如 20/50、15/40、25/60 三套方案），重跑 M5～M10，输出"阈值方案—三档人数—干预人数"对照表，观察阈值收紧对干预清单长度的影响。
2. **岗位维度统计**：按岗位（RESCUE、VENTILATION、SAMPLING 等）分别汇总该岗位的人均累计剂量与超限人数占比，用冒泡排序按人均剂量排列岗位，输出"岗位—人均剂量—超限率"报表，体会不同任务岗位的受照风险差异。
3. **多批次台账合并**：从文件再读入第二个批次的剂量记录，与第一批次合并后重新统计累计剂量，输出"首批—第二批—合计"三列对照名册，观察后续批次进入对人员分级结果的影响。
