## 二、预备知识：一维数组的基本原理（零基础阅读）

### 1. 为什么需要数组

第 3 章的"多测点阻力求和"题里，我们读一个数就算进和里，读下一个时上一个数就"丢了"。这样做求和勉强够用，但若要求"先输出全部原始数据，再求均值、再找峰值"，就必须**让所有数据同时待在内存里**。

数组就是解决这个问题的工具：它把若干个**同类型**的变量按顺序排成一排，共用一个名字，靠**下标**区分彼此。声明

```c
double r[100];
```

的含义是：向内存申请 100 个连续的 `double` 单元，名字叫 `r`，每个单元都可以通过 `r[0]`、`r[1]`、……、`r[99]` 单独访问，用法与普通变量完全一样（可以读、可以赋值、可以放进表达式）。

### 2. 下标从 0 开始——最容易栽的跟头

C 语言规定下标从 **0** 开始：长度为 100 的数组，合法下标是 $0 \sim 99$，**没有 `r[100]` 这个元素**。于是有一个换算关系必须刻进脑子里：

$$
\text{第 } i \text{ 个数据（自然序号 } i = 1, 2, \ldots, n\text{）存放在 } r[i-1] \text{ 中}
$$

题目的输出要求序号从 1 开始（工程报表习惯），所以输出时要写 `printf("r[%d] = %.2f\n", i + 1, r[i])`——存储和显示相差的这 1，全靠程序员自己记，编译器不会提醒。

### 3. 越界问题

`r[100]`、`r[-1]`，甚至 `r[105]` 这样的写法**编译都能通过**，但运行时读写的已不是你的数据，而是内存中别的位置，轻则数据错乱，重则程序崩溃。这叫**下标越界**。防越界只有两条纪律：

- 声明时容量取题目上限（本题 $n \le 100$，容量取 100）；
- 一切循环都写成 `for (i = 0; i < n; i++)`，让下标严格落在 $0 \sim n-1$。

### 4. "容量"与"实际个数"是两回事

`double r[100]` 的 100 是**容量**（最多能放多少），实际读入了 $n$ 个，就只使用 `r[0]` 至 `r[n-1]`，后面 $100-n$ 个单元闲置不用。所以后续一切遍历的循环上界都是 `n`，而不是 100——这是初学者第二个高发错误：把循环写成 `i < 100`，于是输出了 95 行无意义的 `0.00`。

### 5. 读入与输出为什么分两遍

本题直接"边读边输出"也能得到相同结果，但请坚持**先读入存储、再遍历处理**的两遍式写法：实验 C7 的真实流程是"读入一批 → 统计 → 排序 → 报表"，每一步都依赖"数据已在数组里"。现在养成习惯，后面 9 道题全部受益。

## 三、解题思路

1. **定容量**：`n ≤ 100`，声明 `double r[100];`；
2. **读个数**：`scanf("%d", &n)`；
3. **第一遍循环读入**：`for (i = 0; i < n; i++) scanf("%lf", &r[i]);`；
4. **第二遍循环输出**：显示序号用 `i + 1`，数值用 `%.2f`；
5. **输出个数统计**：直接打印 `n` 的值。

## 四、参考代码

```c
#include <stdio.h>

int main(void)
{
    double r[100];            /* 阻力数组，容量 100，够放题目上限的数据 */
    int n, i;                 /* n 为实际数据个数 */

    scanf("%d", &n);          /* 读入数据个数 */

    /* 第一遍：逐个读入，第 i 个数据存入 r[i]（下标 0 ~ n-1） */
    for (i = 0; i < n; i++)
        scanf("%lf", &r[i]);

    /* 第二遍：按下标遍历输出，显示序号 = 下标 + 1 */
    for (i = 0; i < n; i++)
        printf("r[%d] = %.2f\n", i + 1, r[i]);

    printf("共 %d 个数据\n", n);

    return 0;
}
```

## 五、运行验证

以样例 1 的输入 `5` 与 `12.5 13.2 11.8 14.6 13.9` 为例：

| 步骤 | 循环变量 i | 发生的事情 | 数组状态 |
|---|---|---|---|
| 读入循环 | 0 | 读 12.5 存入 r[0] | r = {12.5, ?, ?, ?, ?} |
| | 1 | 读 13.2 存入 r[1] | r = {12.5, 13.2, ?, ?, ?} |
| | 2 | 读 11.8 存入 r[2] | r = {12.5, 13.2, 11.8, ?, ?} |
| | 3 | 读 14.6 存入 r[3] | r = {12.5, 13.2, 11.8, 14.6, ?} |
| | 4 | 读 13.9 存入 r[4] | r = {12.5, 13.2, 11.8, 14.6, 13.9} |
| 输出循环 | 0～4 | 依次打印 r[i]，序号显示为 i+1 | 五行 `r[1] = 12.50` … `r[5] = 13.90` |

最终输出与题干样例 1 完全一致；样例 2 中 `16.733` 按 `%.2f` 四舍五入输出 `16.73`，`9.8` 输出 `9.80`，同样吻合。

## 六、常见错误与讲解

**错误 1：循环边界差一（最高发）**

```c
for (i = 0; i <= n; i++) scanf("%lf", &r[i]);   /* 错：i = n 时多读一个，且 r[n] 越界占用闲置单元 */
for (i = 0; i < n; i++)  scanf("%lf", &r[i]);   /* 对：下标严格 0 ~ n-1 */
```

`i <= n` 会执行 $n+1$ 次，不仅多读一个数，当 $n = 100$ 时 `r[100]` 直接越界。

**错误 2：输出序号与下标混淆**

```c
printf("r[%d] = %.2f\n", i, r[i]);     /* 错：第一个显示 r[0]，与样例的 r[1] 不符 */
printf("r[%d] = %.2f\n", i + 1, r[i]); /* 对：显示序号 = 下标 + 1 */
```

**错误 3：scanf 漏写取地址符**

```c
scanf("%lf", r[i]);    /* 错：给了元素的值，编译能过但运行出错 */
scanf("%lf", &r[i]);   /* 对：数组元素也是变量，一样要取地址 */
```

注意区别：`scanf("%s", name)` 读字符数组时**不加** `&`（数组名本身就代表地址），这是第 5.3 节的内容，现在只需记住"数值型数组元素要加 `&`"。

**错误 4：容量开小或循环用到容量而不是 n**

```c
double r[10];                    /* 错：n 最大 100，容量 10 会被大数据越界 */
for (i = 0; i < 100; i++) ...    /* 错：把容量当个数，多处理了 100-n 个垃圾单元 */
```
