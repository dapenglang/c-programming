# 题目 B6：基于词频统计的文本热度分析系统

**适用学院**：人工智能学院（4 系）　**组容量**：本题目最多 3 组选择

## 一、系统/算法说明

**系统做什么**：本系统是一套命令行文本热度分析工具：读入一篇或多篇英文文本文档，自动完成"读入—清洗—切词—统计—排序—报告"全流程，回答一个朴素却重要的问题——这篇文档里人们最关心什么。系统最终输出每篇文档的 Top-N 高频词表、词频柱状字符图，以及两篇文档的热词对照与重合率。

**解决什么重要问题**：互联网每天产生海量新闻、评论、弹幕、搜索日志，它们都是非结构化文本，计算机无法直接"读懂"。词频统计是把文本变成可计算数字的第一步：不统计词频，运营方不知道舆情热点在哪，编辑不知道读者关心什么，搜索引擎也无法建立索引。同时，"哪些词不算有效词"同样关键——不过滤 the、of 这类停用词，Top-N 会被毫无信息量的虚词霸占，热度分析就完全失真。本系统专门设置停用词过滤环节，让学生体会"统计之前先想清楚统计什么"。

**支撑哪些关键应用**：① 搜索引擎倒排索引构建（词频是相关性打分的第一项）；② 舆情监控与热搜榜（热搜榜的内核就是分词加词频统计）；③ 推荐系统的用户兴趣标签；④ 垃圾邮件过滤（垃圾邮件的词频分布显著异常）；⑤ 论文关键词自动抽取。这些系统无一例外从"清洗与词频统计"起步。

**与专业培养的关联**：人工智能专业后续的"数据挖掘""自然语言处理"课程都以词频统计作为第一个实验。本系统让学生用纯 C 语言（二维字符数组、字符串函数、计数统计、排序）亲手搭起这条流水线，建立"文本 = 可统计数据"的核心直觉，全程不涉及任何机器学习理论。

## 二、题目任务与专业关联

本题目要求实现一个含 10 个模块的文本热度分析系统：(1) 从文本文件按行读入英文文档；(2) 清洗文本，剔除标点并把大写统一为小写；(3) 用二维字符数组维护"词表 + 频次"，逐词查表累加完成词频统计；(4) 从停用词文件读入停用词表，统计时跳过；(5) 按频次排序取 Top-N；(6) 对两篇文档做热词对照，计算 Top-N 重合率；(7) 绘制词频柱状字符图并生成热度报告文件。

专业关联体现在：词频表就是数据挖掘中最基础的"特征向量"，Top-N 排序就是热搜榜的内核，两篇文档热词的重合率则是文本相似度的雏形。完成本题后，学生对"清洗—特征提取—统计—排序—报告"这一数据挖掘通用流程将形成第一手体感。

## 三、数据来源与格式

### 3.1 数据文件格式

（1）待分析文本文件 `news1.txt`：首行为 `#` 开头的说明行，其后每行一条"新闻标题式短句"，纯英文，单词间以空格分隔。

```
# 文档说明行：news1 城市交通主题 新闻标题合集 共 60 行
City traffic congestion worsens as urban population grows rapidly
New metro line opens to ease downtown traffic pressure
Experts suggest smart traffic lights to reduce congestion delay
Traffic accident rate drops after speed limit policy takes effect
Ride sharing services change the way citizens commute daily
```

（2）停用词文件 `stopwords.txt`：每行一个停用词，`#` 开头为注释行。

```
# 英文停用词表（节选，正式版约 150 词）
the
of
and
to
a
in
```

### 3.2 仿真数据生成规则

学生按下述规则生成 4～6 篇仿真文档（每篇 40～80 行）作为测试数据：

| 字段 | 说明 | 单位/取值规则 |
|---|---|---|
| 主题词池 | 每篇围绕 1 个主题 | 从 traffic / campus / weather / sports 四个主题中选 1，主题词及其同义词应占全文单词量的 15%～25%，保证 Top-N 中出现主题热词 |
| 常用词填充 | 模拟自然语言 | 从约 200 词的常用词表中抽取，第 k 常用词出现概率正比于 1/k，重现"少数词高频、大量词低频"的真实分布 |
| 句长 | 每行单词数 | 6～15 个，均匀随机 |
| 异常注入·标点与大小写 | 制造脏数据 | 约 20% 的词后随机跟 `. , ! ? ;` 之一；约 15% 的单词首字母大写；清洗模块必须全部处理掉 |
| 异常注入·噪声 token | 考察健壮性 | 每篇注入 3～5 个含数字的串（如 `abc123`）和 1～2 个长度超过 31 字符的超长串；统计模块须丢弃含数字 token、把超长串截断到 31 字符 |

### 3.3 真实数据集（选做）

古腾堡计划（Project Gutenberg）提供数万本英文原著全文，可直接下载 .txt 文件作为大规模测试文本：https://www.gutenberg.org

## 四、数据结构设计

```c
#define MAX_WORDS 1000       /* 词表容量：单篇文档不重复单词上限 */
#define WORD_LEN  32         /* 单个单词最大长度 */
#define MAX_LINES 600        /* 单篇文档最大行数 */
#define MAX_LINE  200        /* 单行最大字符数 */
#define MAX_STOP  200        /* 停用词上限 */
#define N_TOP     20         /* Top-N 的 N */

/* 词表条目：单词 + 频次，全系统的核心数据单元 */
struct WordItem {
    char word[WORD_LEN];     /* 单词本体，统一为小写 */
    int  freq;               /* 出现次数 */
};

/* ---------- 关键全局数组 ---------- */
char g_text[MAX_LINES][MAX_LINE];     /* 原始文本，按行存储 */
int  g_lineCount;                     /* 实际读入行数 */

struct WordItem g_words[MAX_WORDS];   /* 当前文档词频表 */
int  g_wordCount;                     /* 不重复单词个数 */

struct WordItem g_words2[MAX_WORDS];  /* 第二篇文档词频表（多文档对比用） */
int  g_wordCount2;

char g_stop[MAX_STOP][WORD_LEN];      /* 停用词表 */
int  g_stopCount;

struct WordItem g_top[N_TOP];         /* Top-N 结果副本，供图表与报告模块使用 */
```

## 五、功能模块拆解（共 10 个模块）

### 第一部分：数据读入（2 个模块）

**M1 文本文件读入模块**（源文件 `TextIO.c`）

- 功能简介：打开指定路径的文本文件，用 fgets 按行读入 `g_text`；跳过 `#` 说明行；处理文件不存在、空文件、超长行截断三种异常，读入后报告行数与总字符数。
- 输入：文件路径（菜单输入，默认 `news1.txt`）。
- 输出：填充 `g_text` 与 `g_lineCount`；返回成功/失败标志。

**M2 文本清洗模块**（源文件 `Clean.c`）

- 功能简介：逐行逐字符扫描 `g_text`，把大写字母转小写、把标点替换为空格、压缩连续空格，得到干净的"纯单词行"；统计被清洗的标点个数供日志使用。
- 输入：`g_text`。
- 输出：就地清洗后的 `g_text`；屏幕清洗摘要（标点数、大写转换数）。

### 第二部分：算法实现（5 个模块）

**M3 词表管理模块**（源文件 `WordTable.c`）

- 功能简介：实现词表的三个基本操作：`查找单词`（顺序查找返回下标或 -1）、`插入单词`（频次置 1）、`词表满/词过长` 的保护处理；提供 `打印词表前 K 条` 的调试函数。
- 输入：一个单词字符串。
- 输出：维护 `g_words` 与 `g_wordCount`；调试时屏幕输出。

**M4 词频统计主循环模块**（源文件 `Count.c`）

- 功能简介：遍历清洗后的每一行，按空格切出单词，依次调用 M3 查表累加频次；同时统计总词数、最长词、平均词长三个整体指标。
- 输入：清洗后的 `g_text`。
- 输出：填充 `g_words` 词频表；屏幕整体统计信息。

**M5 Top-N 排序模块**（源文件 `TopN.c`）

- 功能简介：用选择排序把词频表按频次从大到小排序（频次相同按字典序），取前 N 条复制到 `g_top`；屏幕输出 Top-N 名次、单词、频次、占比（频次/总词数，百分数保留 1 位）。
- 输入：`g_words`、用户输入的 N（不超过 N_TOP）。
- 输出：`g_top`；屏幕 Top-N 表。

**M6 多文档对比模块**（源文件 `Compare.c`）

- 功能简介：对第二篇文档重复"读入—清洗—统计"得到 `g_words2`，然后对两篇文档的 Top-N 词表做双向对照：找出仅在文档 1 热榜中的词、仅在文档 2 热榜中的词、两边都有的词，并计算 Top-N 重合率（共同词数 / N）。
- 输入：第二篇文档路径、N。
- 输出：`g_words2`；屏幕对照表与重合率。

**M9 停用词过滤模块**（源文件 `Stopword.c`）

- 功能简介：从 `stopwords.txt` 读入停用词表到 `g_stop`；提供 `是否停用词` 判断函数（strcmp 匹配）；在 M4 统计流程中调用本模块，命中停用词的 token 直接跳过并单独计数。
- 输入：停用词文件路径。
- 输出：`g_stop` 与 `g_stopCount`；屏幕报告"已跳过停用词 xx 次"。

### 第三部分：数据输出（3 个模块）

**M7 词频柱状字符图模块**（源文件 `BarChart.c`）

- 功能简介：把 Top-N 词频绘制成水平柱状字符图：每词一行，`*` 个数按 频次/最大频次 × 40 缩放，行尾标注频次与占比；支持设定柱宽上限。
- 输入：`g_top`。
- 输出：屏幕字符柱状图。

**M8 热度报告生成模块**（源文件 `Report.c`）

- 功能简介：把本次分析的完整结果写入 `heat_report.txt`：文档名、总词数、不重复词数、停用词命中数、Top-N 词表（名次/单词/频次/占比）、两文档对照结论；每次生成不覆盖旧报告（文件名带序号）。
- 输入：各全局统计结果。
- 输出：`heat_report.txt`；屏幕确认信息。

**M10 主控菜单模块**（源文件 `main.c`）

- 功能简介：文本主菜单（读入文本 / 清洗 / 停用词加载 / 词频统计 / Top-N / 多文档对比 / 柱状图 / 生成报告 / 退出），`do-while + switch` 调度；用状态标记约束"必须先读入文本才能清洗，必须先统计才能排序与出图"。
- 输入：用户菜单选项。
- 输出：调度各模块。

## 六、数据流与控制流

**控制流**：`main()` 菜单循环 → switch 分发 M1～M9 → 直至退出。状态约束：M2 依赖 M1，M4 依赖 M2 与 M9，M5/M6/M7/M8 均要求词频统计已完成。

**数据流**：

```
news1.txt ──► M1 按行读入 ──► g_text (600×200 二维字符数组)
                                   │
                                   ▼
 stopwords.txt ──► M9 读入 g_stop ─┴─► M2 清洗（去标点/转小写）
                                        │
                                        ▼
                                 M4 词频统计（切词→M3 查表累加）
                                        │
                        g_words 词频表 ─┴─► 总词数/最长词/平均词长
                                        │
                 ┌──────────────────────┼──────────────────────┐
                 ▼                      ▼                      ▼
         M5 排序取 g_top        M6 读入第二篇→g_words2   （g_top 供图与报告）
                 │                      │                      │
                 ▼                      ▼                      ▼
           M7 词频柱状图          对照表+重合率            M8 热度报告文件
```

所有模块之间只通过全局数组与参数传递交换数据，接口（函数头部）编码前书面约定。

## 十、选做扩展

1. 词长分布统计：统计长度为 1～10 及 10 以上字符的单词各出现多少次，绘制第二张柱状图（纯计数统计，无新理论）；
2. 中文支持：对中文文本按"字"切分（限定每汉字 2 字节的编码文件）做单字频次统计，与英文流程共用词表结构；
3. 大规模测试与查找提速：下载古腾堡整本小说（数万词），对比顺序查表与"先排序后二分查找"两种方式的运行时间感受（用循环次数计数即可，不必精确计时）。
