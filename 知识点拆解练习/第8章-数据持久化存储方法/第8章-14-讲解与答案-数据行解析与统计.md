## 二、预备知识：手工拆分数据行的基本原理（零基础阅读）

### 1. 一行数据在内存里是什么样子

`fgets` 把 `A01,23.5,0.82\n` 读进字符数组 `line` 后，内存里实际存放的是：

```
'A'  '0'  '1'  ','  '2'  '3'  '.'  '5'  ','  '0'  '.'  '8'  '2'  '\n'  '\0'
```

C 语言没有"字段"概念，所谓解析，就是**我们自己划定边界**：第 1 个字段是下标 0～2 的三个字符，第 2 个字段从下标 4 到下一个逗号前，依此类推。

### 2. 截断的技巧：把逗号改成 '\0'

C 的字符串以 `'\0'` 结尾。如果我们把 `line[3]` 的逗号改成 `'\0'`，那么从 `line` 开始看，它就变成了字符串 `"A01"`——后面的内容还在数组里，但"字符串到此为止"。这就是手工截断的全部秘密：**找到分隔符，把它改成 `'\0'`，字段就切下来了**。

```
'A'  '0'  '1'  '\0'  '2'  '3'  '.'  '5'  ',' ...
      ↑ 原来的逗号位置改成 '\0'，"A01" 成为独立字符串
```

### 3. 数值字段可以"偷懒"：atof 从指定位置开始读

数值字段不必截断。`atof(p)` 会从指针 `p` 指向的位置开始读数字，遇到第一个"读不动"的字符（逗号、换行、`'\0'` 都算）就停。所以第二、三字段只需把各自起始位置的地址交给 `atof` 即可：

- 第 2 字段起点：第一个逗号之后一格；
- 第 3 字段起点：第二个逗号之后一格。

### 4. 数据流与文件指针生命周期

本题的数据流是"读一行 → 拆字段 → 统计累加"，统计结果只放在变量里，最后一次性输出，**不写任何文件**。因此只有一条文件指针生命周期：`fin` 从 fopen 到 fgets 返回 NULL、循环结束，立即 fclose。生命周期虽短，检查 fopen 返回值和 fclose 两条纪律一条不能少。

### 5. 为什么要会手写解析

`sscanf("%[^,],%lf,%lf", ...)` 之类的格式串也能拆逗号行，但它对格式变化敏感：多一个空格、字段宽度变了，解析就失败。手写扫描想怎么容错就怎么容错——先扫掉行首空格再找逗号、逗号后自动跳过空格等，都只是几行代码的事。工程上，"先手写理解原理，再按需选用库函数"是正确顺序。

## 三、解题思路

1. **打开文件**并检查；定义 `line[100]`、编号数组 `id[8]`、统计变量；
2. **循环读行**：fgets 返回非 NULL 就处理，空行跳过；
3. **手工拆分**：指针 p 从行首出发——第一段把字符逐个拷进 `id` 直到逗号，把逗号改成 `'\0'`；p 前进一格后 `f = atof(p)`；再扫到下一个逗号，p 前进一格后 `v = atof(p)`；
4. **统计**：计数、累加、更新最大值与对应编号；
5. **收尾输出**：fclose 后输出条数、总和、平均、最大。

## 四、参考代码

```c
#include <stdio.h>
#include <stdlib.h>     /* atof */
#include <string.h>     /* strcpy */

int main(void)
{
    FILE *fin;
    char line[100];          /* 读入的一行 */
    char id[8];              /* 样本编号字段 */
    char maxid[8];           /* 最大阻力样本的编号 */
    char *p;                 /* 扫描指针 */
    double f, v;             /* 阻力 kN、航速 m/s（航速读入但本题不统计） */
    double sum = 0.0, fmax = -1.0;
    int n = 0;

    fin = fopen("samples.txt", "r");
    if (fin == NULL) {
        printf("错误：无法打开 samples.txt\n");
        return 1;
    }

    while (fgets(line, sizeof(line), fin) != NULL) {
        if (line[0] == '\n')
            continue;
        /* -- 第一段：编号，拷到逗号为止并把逗号改成 '\0' -- */
        p = line;
        while (*p != ',') {
            id[p - line] = *p;
            p++;
        }
        id[p - line] = '\0';
        /* -- 第二段：阻力，atof 从逗号后一格开始读 -- */
        f = atof(p + 1);
        p++;                         /* 越过第一个逗号 */
        while (*p != ',')            /* 找第二个逗号 */
            p++;
        /* -- 第三段：航速，atof 自动在换行符处停止 -- */
        v = atof(p + 1);
        /* -- 统计 -- */
        n++;
        sum += f;
        if (f > fmax) {
            fmax = f;
            strcpy(maxid, id);
        }
    }

    fclose(fin);
    printf("共 %d 条记录\n", n);
    printf("阻力总和 = %.2f kN\n", sum);
    printf("平均阻力 = %.2f kN\n", sum / n);
    printf("最大阻力 = %.2f kN（编号 %s）\n", fmax, maxid);

    return 0;
}
```

## 五、运行验证

**手工核对**（数据 4 行）：

- 条数：4；
- 阻力总和：$23.5 + 25.1 + 19.8 + 27.6 = 96.0$；
- 平均阻力：$96.0 / 4 = 24.0$；
- 最大阻力：27.6，逐条比较 23.5 → 25.1 → 19.8 → 27.6，最大值编号依次更新为 A01 → A02 → A04，最终 A04。

**屏幕输出**：

```
共 4 条记录
阻力总和 = 96.00 kN
平均阻力 = 24.00 kN
最大阻力 = 27.60 kN（编号 A04）
```

**文件内容变化**：本题只读不写，`samples.txt` 前后不变——验证"只读型统计程序"对源数据零污染。

## 六、常见错误与讲解

**错误 1：编号字段忘记补 '\0'**

```c
while (*p != ',') { id[p - line] = *p; p++; }
/* 少了 id[p - line] = '\0'; —— id 不是合法字符串，printf("%s", id) 会一直输出到内存垃圾 */
```

截断的本质就是补 `'\0'`，这一行绝不能省。

**错误 2：找到逗号后忘了跳过逗号本身**

```c
f = atof(p);        /* 错：p 还指着逗号，atof 读不到数字，返回 0.0 */
f = atof(p + 1);    /* 对：跳过逗号，从数字开始 */
```

**错误 3：找第二个逗号时忘了越过第一个**

```c
while (*p != ',') p++;   /* 错：p 还停在第一个逗号上，循环一步都不走，
                            v = atof(p+1) 读到的仍是阻力字段 */
p++;                     /* 对：先越过当前逗号，再继续向前找第二个 */
while (*p != ',') p++;
```

指针停在哪里要时刻清楚：第一段结束时 p 停在第一个逗号上，必须先 `p++` 跳过它，才能开始搜索第二个逗号。

**错误 4：最大值初值设为 0**

阻力可能全部为负吗？本实验不会，但初值习惯要养好：把 `fmax` 初始化为"不可能的小值"（如 -1.0 或首条记录的值），并让编号跟随更新。若只更新数值忘了 `strcpy(maxid, id)`，输出的编号就会与最大值对不上。

## 七、与综合实验的衔接

- 实验 **C7（冰区载荷辨识与统计）**中，事件记录文件往往是仪器直接吐出的逗号分隔文本，字段里混着编号、时间戳、数值，格式并不总能让 sscanf 一次吃下。本题的手工扫描三步法——"定位分隔符、截断字符串字段、atof 读数值字段"——是应对任意分隔格式的通用技术，稍加扩展（先跳空格、支持多分隔符、处理引号字段）就是一个麻雀虽小的 CSV 解析器；
