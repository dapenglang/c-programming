## 二、预备知识：文件读写的基本原理（零基础阅读）

### 1. 为什么需要文件

内存里的数据"程序一停就没了"，要长期保存必须写文件。日志文件还有个特殊要求：**历史记录只增不改**。仿真跑一百次，就有一百次碰撞记录，每次运行时都只往末尾添新的，绝不能把老的冲掉。普通写模式做不到这一点，于是 C 语言专门提供了**追加模式 `"a"`**。

### 2. 文件操作的标准四步曲

1. **声明文件指针**：`FILE *fp;`；
2. **打开文件**：`fp = fopen("文件名", "模式");`；
3. **读或写**：本题用 `fprintf` 追加写；
4. **关闭文件**：`fclose(fp);`。

**`fopen` 返回的 `FILE *` 是什么？** 它是这次文件访问的"编号牌"，指向系统为该文件建立的记录（文件在哪、当前进行到哪、是读还是写）；记录里的**文件位置指针**标明"现在写到第几个字节"。特别地，以 `"a"` 打开时，位置指针**一开始就被放在文件末尾**，所以每次写入都自动接在老内容后面。

**打开失败会怎样？** 目标是只读文件、目录不可写时 `fopen` 返回 `NULL`，不判空就用会崩溃，因此打开后**必须**判空：

```c
if (fp == NULL) { printf("无法打开日志文件\n"); return 1; }
```

### 3. 常用读写函数怎么选

| 函数 | 读/写单位 | 典型写法 | 适合场景 |
|---|---|---|---|
| `fprintf` | 按格式写 | `fprintf(fp, "t=%.2f A=%d\n", t, a);` | 把一行文本按格式写入 |
| `fscanf` | 按格式读 | `fscanf(fp, "%d%lf", &id, &v);` | 从文本里按格式读 |
| `fgets` | 读一整行 | `fgets(buf, sizeof(buf), fp);` | 整行处理 |
| `fgetc`/`fputc` | 读/写单个字符 | `c = fgetc(fp);` | 逐字符处理 |
| `fread`/`fwrite` | 按字节块读写 | `fwrite(a, sizeof(double), n, fp);` | 二进制批量数据 |

日志是"每行一条事件"的文本，用 `fprintf` 按固定格式写最合适——它和 `printf` 用法相同，只是第一个参数是文件指针。

### 4. 打开模式的区别（本题重点）

| 模式 | 含义 | 文件已存在时 | 位置指针初始位置 |
|---|---|---|---|
| `"r"` | 只读文本 | 从文件头开始读 | 开头 |
| `"w"` | 只写文本 | **清空原有内容** | 开头 |
| `"a"` | **追加文本** | **保留原有内容** | 文件末尾 |
| `"rb"`/`"wb"` | 二进制只读/只写 | 清空（`wb`） | 开头 |

口诀：**`"w"` 清空重写、`"a"` 末尾追加**。日志必须用 `"a"`；一旦误用 `"w"`，运行一次就把历史记录全部清空，这是本练习最容易犯也最致命的错误。

### 5. 用本题的数据走一遍文件指针

运行前文件已有两行（含末尾换行）：

```
t=0.50 A=3 B=7 F=1250.0\n
t=1.25 A=1 B=4 F=980.5\n
```

以 `"a"` 打开后，位置指针**直接停在文件末尾**（两行共 47 字节，指针在第 47 字节处）。第一次循环读入 `2.00 2 5 560.0`，`fprintf` 在末尾写下 `t=2.00 A=2 B=5 F=560.0` 加换行，指针后移；第二次写下 `t=3.10 A=6 B=8 F=1420.0` 加换行。`fclose` 后，文件就是老两行加新两行共四行。

要点：**用 `"a"` 时不需要任何 `fseek`，系统已经把指针放在末尾**；这也解释了为什么追加模式特别适合"持续写日志"。

## 三、解题思路

1. **读入条数**：`scanf("%d", &n)`；
2. **打开文件**：`fp = fopen("collision_log.txt", "a")`，判空；
3. **循环追加**：每次读 `t、A、B、F`，用 `fprintf` 写一行，重复 $n$ 次；
4. **关闭**：`fclose(fp)`；
5. **屏幕提示**：输出追加条数。

## 四、参考代码

```c
#include <stdio.h>

int main(void)
{
    FILE *fp;                 /* 日志文件指针 */
    int n, i, a, b;           /* n 为追加条数；a、b 为冰块编号 */
    double t, f;              /* t 为碰撞时刻(s)，f 为碰撞力(N) */

    scanf("%d", &n);          /* 本次要追加的事件条数 */

    /* 以"追加"模式打开：不会清空已有日志 */
    fp = fopen("collision_log.txt", "a");
    if (fp == NULL) {
        printf("无法打开文件 collision_log.txt\n");
        return 1;
    }

    /* 逐条读入并追加到文件末尾 */
    for (i = 0; i < n; i++) {
        scanf("%lf%d%d%lf", &t, &a, &b, &f);
        fprintf(fp, "t=%.2f A=%d B=%d F=%.1f\n", t, a, b, f);
    }

    fclose(fp);               /* 关闭文件，数据落盘 */

    printf("已追加 %d 条碰撞记录\n", n);

    return 0;
}
```

## 五、运行验证

**样例 1：运行前** `collision_log.txt` 内容：
```
t=0.50 A=3 B=7 F=1250.0
t=1.25 A=1 B=4 F=980.5
```
屏幕输入：
```
2
2.00 2 5 560.0
3.10 6 8 1420.0
```
屏幕输出：
```
已追加 2 条碰撞记录
```
**运行后** 文件内容（老两行保留，新两行追加在后面）：
```
t=0.50 A=3 B=7 F=1250.0
t=1.25 A=1 B=4 F=980.5
t=2.00 A=2 B=5 F=560.0
t=3.10 A=6 B=8 F=1420.0
```
逐行核对：`t=%.2f` 把 2.00、3.10 原样输出；`F=%.1f` 把 560.0、1420.0 输出为 `560.0`、`1420.0`；老记录 `F=1250.0`、`980.5` 一行未动，证明 `"a"` 保留了历史。

**样例 2：运行前** 文件仍是原始两行。屏幕输入：
```
1
4.75 3 9 870.0
```
屏幕输出：
```
已追加 1 条碰撞记录
```
**运行后** 文件内容：
```
t=0.50 A=3 B=7 F=1250.0
t=1.25 A=1 B=4 F=980.5
t=4.75 A=3 B=9 F=870.0
```
只多一行，历史记录依旧完整。

## 六、常见错误与讲解

**错误 1：用 `"w"` 代替 `"a"`，把日志清空**

```c
fp = fopen("collision_log.txt", "w");   /* 致命错误：历史记录全部丢失 */
fp = fopen("collision_log.txt", "a");   /* 对：追加保存 */
```
这是日志类程序头号事故。建议写完先检查"运行前有几行、运行后是不是在末尾多了几行"，来确认模式用对了。

**错误 2：追加模式下还去 `fseek` 到开头**

```c
fseek(fp, 0, SEEK_END);   /* 多余：以 "a" 打开时指针本来就在末尾 */
fprintf(fp, ...);         /* 另外，某些实现对追加模式的写位置有强制约束 */
```
追加模式下不必手动定位，直接 `fprintf` 即可；多此一举反而可能引发非预期行为。

**错误 3：`fopen` 不判空、忘记 `fclose`**

```c
fp = fopen("collision_log.txt", "a");
fprintf(fp, "t=%.2f ...\n", t);   /* 错：fp 可能为 NULL */
```
以及写完后不 `fclose`，缓冲区里的记录可能没有真正落盘。此外，格式串与数据个数要匹配：若漏写某个字段（如碰撞力 `F`），日志就会残缺或错位，写完应对照题干样例行逐字段检查一次。

## 七、与综合实验的衔接

实验 C6 的碰撞仿真在每一个时间步检测到碰撞后，都用本练习的方式往日志文件追加一行事件，便于事后回溯"哪两块冰、何时、以多大力相撞"；程序崩溃或中断也不会丢掉之前已经写下的记录，这正是追加模式的工程价值。C9 的运行日志、A1 的工况记录同样适用。若日志量大到需要按时间、按对象快速检索与统计，第 8 章 8.7 节介绍的数据库技术会比纯文本日志更胜任这类管理任务。
